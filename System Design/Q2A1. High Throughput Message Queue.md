## 1. Understanding the Requirements

Before diving into the design, we need to clarify what "high-throughput message queue" means and what constraints we're working under. In a real interview, you would ask these clarifying questions.

### What type of message queue?

- **In-process queue**: Communication between threads in the same process
- **Inter-process queue**: Communication between processes on the same machine
- **Distributed queue**: Communication across machines (like Kafka, RabbitMQ)
- For this design, we'll focus on an **in-process, inter-thread message queue**

### What are the message characteristics?

- **Fixed size or variable size?** Variable-size messages are more flexible but harder to optimize
- **Average message size?** Let's assume 64-256 bytes typical, up to 4KB max
- **Message ordering requirements?** FIFO per producer, or global ordering?
- For this design: **Variable size, FIFO per producer, eventual consistency across producers**

### Producer-Consumer model?

- **Single-Producer Single-Consumer (SPSC)**: Simplest, fastest
- **Single-Producer Multi-Consumer (SPMC)**: One writer, multiple readers
- **Multi-Producer Single-Consumer (MPSC)**: Multiple writers, one reader
- **Multi-Producer Multi-Consumer (MPMC)**: Most complex, most flexible
- We'll design for **MPMC** as the most general case, with optimizations for simpler cases

### What are the performance requirements?

- **Throughput**: Millions of messages per second
- **Latency**: Sub-microsecond for enqueue/dequeue operations
- **Scalability**: Linear scaling with number of cores
- **Memory efficiency**: Bounded memory usage, no memory leaks

### What about durability and persistence?

- **Volatile (memory only)**: Fastest, messages lost on crash
- **Persistent**: Messages survive restarts, much slower
- For high-throughput: **Volatile with optional async persistence**

## 2. Back-of-the-Envelope Calculations

Let's do the math to understand what "millions of messages per second" actually requires.

### Time budget per operation

```
Target: 10,000,000 messages/second
= 10 messages per microsecond
= 1 message per 100 nanoseconds
```

100 nanoseconds is roughly **200-400 CPU cycles** on a 2-4 GHz processor. This is extremely tight!

### What fits in 100ns?

| Operation | Approximate Time |
|-----------|-----------------|
| L1 cache hit | 1-2 ns |
| L2 cache hit | 3-10 ns |
| L3 cache hit | 10-40 ns |
| Main memory access | 60-100 ns |
| Mutex lock/unlock (uncontended) | 20-50 ns |
| Mutex lock (contended) | 1,000+ ns |
| System call | 100-1,000 ns |
| malloc/new (typical) | 50-500 ns |
| Atomic CAS (uncontended) | 10-20 ns |
| Atomic CAS (contended) | 50-200 ns |

**Key Insights:**
1. We cannot afford mutexes under contention
2. We cannot afford memory allocation per message
3. We must stay in L1/L2 cache as much as possible
4. Lock-free algorithms with atomics are feasible

### Memory bandwidth check

```
10M messages/sec × 256 bytes average = 2.56 GB/sec
```

Modern DDR4 provides 25-50 GB/sec per channel. Memory bandwidth is not the bottleneck.

### Cache considerations

```
L1 cache: 32-64 KB per core (access in ~1ns)
L2 cache: 256-512 KB per core (access in ~5ns)
L3 cache: 8-32 MB shared (access in ~20ns)
```

For maximum throughput, our hot path data structures should fit in L1/L2 cache.

## 3. High-Level Architecture

Based on our analysis, here's the high-level architecture:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                         HIGH-THROUGHPUT MESSAGE QUEUE                        │
└─────────────────────────────────────────────────────────────────────────────┘

    ┌──────────────┐                                      ┌──────────────┐
    │  Producer 1  │──┐                               ┌──►│  Consumer 1  │
    └──────────────┘  │                               │   └──────────────┘
                      │                               │
    ┌──────────────┐  │   ┌─────────────────────┐    │   ┌──────────────┐
    │  Producer 2  │──┼──►│   Lock-Free Ring    │────┼──►│  Consumer 2  │
    └──────────────┘  │   │       Buffer        │    │   └──────────────┘
                      │   │                     │    │
    ┌──────────────┐  │   │  ┌───┬───┬───┬───┐  │    │   ┌──────────────┐
    │  Producer 3  │──┘   │  │ M │ M │ M │ M │  │    └──►│  Consumer 3  │
    └──────────────┘      │  └───┴───┴───┴───┘  │        └──────────────┘
                          │    ▲           │    │
                          │  write       read   │
                          │  head        tail   │
                          └─────────────────────┘

    ┌─────────────────────────────────────────────────────────────────────┐
    │                         MEMORY POOL                                  │
    │  ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐   │
    │  │Slot │ │Slot │ │Slot │ │Slot │ │Slot │ │Slot │ │Slot │ │Slot │   │
    │  └─────┘ └─────┘ └─────┘ └─────┘ └─────┘ └─────┘ └─────┘ └─────┘   │
    └─────────────────────────────────────────────────────────────────────┘
```

### Key Architectural Decisions

1. **Lock-Free Ring Buffer**: Core data structure for the queue
2. **Pre-allocated Memory Pool**: Avoid malloc/free in hot path
3. **Cache-Line Padding**: Prevent false sharing between producers/consumers
4. **Batching**: Amortize atomic operation costs across multiple messages
5. **NUMA-Aware Allocation**: Keep memory close to the accessing core

## 4. Queue Design Patterns

### 4.1 Single-Producer Single-Consumer (SPSC)

The simplest and fastest design. Only one thread writes, only one thread reads.

**Why it's fast:**
- No contention on head or tail pointers
- Simple load/store operations instead of CAS
- Compiler can optimize more aggressively

```
Producer                          Consumer
    │                                 │
    ▼                                 ▼
┌───────┐                         ┌───────┐
│ write │                         │ read  │
│ head  │                         │ tail  │
└───┬───┘                         └───┬───┘
    │     ┌───┬───┬───┬───┬───┐      │
    └────►│ 0 │ 1 │ 2 │ 3 │ 4 │◄─────┘
          └───┴───┴───┴───┴───┘
          Ring Buffer (power of 2 size)
```

**Memory ordering:**
- Producer: `store(data)` then `store-release(head)`
- Consumer: `load-acquire(head)` then `load(data)`

This ensures the consumer sees the data before the head advances.

### 4.2 Multi-Producer Single-Consumer (MPSC)

Multiple producers compete to enqueue. Single consumer reads sequentially.

**Challenge:** Multiple producers must coordinate to claim slots atomically.

**Solution:** Use fetch_add to atomically claim the next slot:

```
Producer 1: fetch_add(head, 1) → gets slot 5
Producer 2: fetch_add(head, 1) → gets slot 6
Producer 3: fetch_add(head, 1) → gets slot 7
```

**Problem:** What if Producer 1 (slot 5) is slow and Producer 2 (slot 6) finishes first?
The consumer might see slot 6 before slot 5 is ready!

**Solution:** Add a "ready" flag per slot:

```cpp
struct Slot {
    std::atomic<bool> ready;
    Message message;
};
```

### 4.3 Single-Producer Multi-Consumer (SPMC)

One producer, multiple consumers compete to dequeue.

**Challenge:** Multiple consumers must coordinate to claim messages atomically.

**Solution:** Similar to MPSC, use fetch_add on the tail pointer.

### 4.4 Multi-Producer Multi-Consumer (MPMC)

The most general and complex case. Both enqueue and dequeue require coordination.

**Approaches:**
1. **Sequence-based**: Each slot has a sequence number indicating its state
2. **State-based**: Each slot has an explicit state (EMPTY, WRITING, READY, READING)
3. **Ticket-based**: Separate head/tail "tickets" for reservation vs. completion

We'll implement the **sequence-based approach** as it has the best performance characteristics.

## 5. Lock-Free Queue Implementation

### 5.1 The Sequence-Based MPMC Queue

This is the gold standard for lock-free MPMC queues, based on Dmitry Vyukov's design.

**Core Idea:**
- Each slot has a sequence number
- Producers and consumers use the sequence to coordinate
- The sequence indicates the slot's state without explicit state flags

```cpp
#include <atomic>
#include <memory>
#include <cstddef>
#include <new>

template<typename T>
class MPMCQueue {
private:
    // Slot structure - each slot holds one message and its sequence number
    struct Slot {
        std::atomic<size_t> sequence;
        T data;
    };

    // Cache line size for padding (typically 64 bytes on x86)
    static constexpr size_t CACHE_LINE_SIZE = 64;

    // The ring buffer of slots
    Slot* slots_;
    
    // Capacity must be power of 2 for efficient modulo
    size_t capacity_;
    size_t mask_;  // capacity - 1, for bitwise AND instead of modulo

    // Head and tail pointers, each on its own cache line to prevent false sharing
    alignas(CACHE_LINE_SIZE) std::atomic<size_t> head_;
    alignas(CACHE_LINE_SIZE) std::atomic<size_t> tail_;

public:
    explicit MPMCQueue(size_t capacity) 
        : capacity_(roundUpToPowerOf2(capacity))
        , mask_(capacity_ - 1)
        , head_(0)
        , tail_(0) 
    {
        // Allocate slots with proper alignment
        slots_ = new Slot[capacity_];
        
        // Initialize sequence numbers
        // Slot i starts with sequence = i, meaning "ready for producer at position i"
        for (size_t i = 0; i < capacity_; ++i) {
            slots_[i].sequence.store(i, std::memory_order_relaxed);
        }
    }

    ~MPMCQueue() {
        delete[] slots_;
    }

    // Non-copyable, non-movable
    MPMCQueue(const MPMCQueue&) = delete;
    MPMCQueue& operator=(const MPMCQueue&) = delete;

    bool try_enqueue(const T& item) {
        size_t head = head_.load(std::memory_order_relaxed);
        
        while (true) {
            Slot& slot = slots_[head & mask_];
            size_t seq = slot.sequence.load(std::memory_order_acquire);
            intptr_t diff = static_cast<intptr_t>(seq) - static_cast<intptr_t>(head);
            
            if (diff == 0) {
                // Slot is ready for this producer
                if (head_.compare_exchange_weak(head, head + 1, 
                                                std::memory_order_relaxed)) {
                    // Successfully claimed the slot
                    slot.data = item;
                    // Mark slot as ready for consumer
                    slot.sequence.store(head + 1, std::memory_order_release);
                    return true;
                }
                // CAS failed, another producer claimed it, retry with updated head
            } else if (diff < 0) {
                // Queue is full
                return false;
            } else {
                // Slot was claimed by another producer, reload head and retry
                head = head_.load(std::memory_order_relaxed);
            }
        }
    }

    bool try_dequeue(T& item) {
        size_t tail = tail_.load(std::memory_order_relaxed);
        
        while (true) {
            Slot& slot = slots_[tail & mask_];
            size_t seq = slot.sequence.load(std::memory_order_acquire);
            intptr_t diff = static_cast<intptr_t>(seq) - static_cast<intptr_t>(tail + 1);
            
            if (diff == 0) {
                // Slot is ready for this consumer
                if (tail_.compare_exchange_weak(tail, tail + 1,
                                                std::memory_order_relaxed)) {
                    // Successfully claimed the slot
                    item = std::move(slot.data);
                    // Mark slot as ready for producer at position (tail + capacity)
                    slot.sequence.store(tail + mask_ + 1, std::memory_order_release);
                    return true;
                }
                // CAS failed, another consumer claimed it, retry with updated tail
            } else if (diff < 0) {
                // Queue is empty
                return false;
            } else {
                // Slot was claimed by another consumer, reload tail and retry
                tail = tail_.load(std::memory_order_relaxed);
            }
        }
    }

    bool is_empty() const {
        return head_.load(std::memory_order_relaxed) == 
               tail_.load(std::memory_order_relaxed);
    }

    size_t size_approx() const {
        size_t head = head_.load(std::memory_order_relaxed);
        size_t tail = tail_.load(std::memory_order_relaxed);
        return head >= tail ? head - tail : 0;
    }

private:
    static size_t roundUpToPowerOf2(size_t n) {
        --n;
        n |= n >> 1;
        n |= n >> 2;
        n |= n >> 4;
        n |= n >> 8;
        n |= n >> 16;
        n |= n >> 32;
        return n + 1;
    }
};
```

### 5.2 Understanding the Sequence Number Magic

The sequence number elegantly encodes the slot state:

| Sequence Value | Meaning |
|----------------|---------|
| `seq == pos` | Slot at position `pos` is ready for producer |
| `seq == pos + 1` | Slot at position `pos` contains data, ready for consumer |
| `seq == pos + capacity` | Slot has been consumed, ready for next producer cycle |

**Visual Timeline:**

```
Initial State (capacity = 4):
Slot:     [0]  [1]  [2]  [3]
Sequence:  0    1    2    3
Head = 0, Tail = 0

After enqueue at position 0:
Slot:     [0]  [1]  [2]  [3]
Sequence:  1    1    2    3   ← slot[0].seq changed from 0 to 1
Head = 1, Tail = 0

After dequeue from position 0:
Slot:     [0]  [1]  [2]  [3]
Sequence:  4    1    2    3   ← slot[0].seq changed from 1 to 4 (0 + 4)
Head = 1, Tail = 1

Now slot[0] is ready for producer at head = 4 (next cycle)
```

### 5.3 Why Power of 2 Capacity?

Using power-of-2 capacity allows us to replace expensive modulo operations with fast bitwise AND:

```cpp
// Slow: uses division
size_t index = position % capacity;

// Fast: uses bitwise AND (capacity must be power of 2)
size_t index = position & (capacity - 1);
```

Division takes ~20-80 CPU cycles; bitwise AND takes 1 cycle.

### 5.4 SPSC Queue (Optimized for Single Producer/Consumer)

When you know there's only one producer and one consumer, you can avoid CAS entirely:

```cpp
template<typename T>
class SPSCQueue {
private:
    struct Slot {
        T data;
    };

    static constexpr size_t CACHE_LINE_SIZE = 64;

    Slot* slots_;
    size_t capacity_;
    size_t mask_;

    // Separate cache lines for head and tail
    alignas(CACHE_LINE_SIZE) std::atomic<size_t> head_{0};
    alignas(CACHE_LINE_SIZE) size_t cached_tail_{0};  // Producer's cached view of tail
    
    alignas(CACHE_LINE_SIZE) std::atomic<size_t> tail_{0};
    alignas(CACHE_LINE_SIZE) size_t cached_head_{0};  // Consumer's cached view of head

public:
    explicit SPSCQueue(size_t capacity)
        : capacity_(roundUpToPowerOf2(capacity))
        , mask_(capacity_ - 1) 
    {
        slots_ = new Slot[capacity_];
    }

    ~SPSCQueue() {
        delete[] slots_;
    }

    bool try_enqueue(const T& item) {
        size_t head = head_.load(std::memory_order_relaxed);
        size_t next_head = head + 1;
        
        // Check if queue is full
        if (next_head - cached_tail_ > mask_) {
            // Update cached tail
            cached_tail_ = tail_.load(std::memory_order_acquire);
            if (next_head - cached_tail_ > mask_) {
                return false;  // Still full
            }
        }
        
        slots_[head & mask_].data = item;
        head_.store(next_head, std::memory_order_release);
        return true;
    }

    bool try_dequeue(T& item) {
        size_t tail = tail_.load(std::memory_order_relaxed);
        
        // Check if queue is empty
        if (cached_head_ == tail) {
            cached_head_ = head_.load(std::memory_order_acquire);
            if (cached_head_ == tail) {
                return false;  // Still empty
            }
        }
        
        item = std::move(slots_[tail & mask_].data);
        tail_.store(tail + 1, std::memory_order_release);
        return true;
    }

private:
    static size_t roundUpToPowerOf2(size_t n) {
        --n;
        n |= n >> 1;
        n |= n >> 2;
        n |= n >> 4;
        n |= n >> 8;
        n |= n >> 16;
        n |= n >> 32;
        return n + 1;
    }
};
```

**Why SPSC is faster:**
1. No CAS operations—just loads and stores
2. Cached head/tail reduces atomic reads
3. The compiler can optimize more aggressively

## 6. Memory Management Strategy

### 6.1 The Problem with malloc/new

At 10M messages/second, calling `new` for each message would be disastrous:
- Each allocation takes 50-500ns
- Memory fragmentation over time
- Cache pollution from allocator metadata

### 6.2 Memory Pool (Object Pool Pattern)

Pre-allocate a pool of message buffers:

```cpp
template<typename T>
class ObjectPool {
private:
    struct Node {
        T object;
        std::atomic<Node*> next;
    };

    std::atomic<Node*> free_list_;
    Node* pool_;
    size_t pool_size_;

public:
    explicit ObjectPool(size_t size) : pool_size_(size) {
        pool_ = new Node[size];
        
        // Build the free list
        for (size_t i = 0; i < size - 1; ++i) {
            pool_[i].next.store(&pool_[i + 1], std::memory_order_relaxed);
        }
        pool_[size - 1].next.store(nullptr, std::memory_order_relaxed);
        free_list_.store(&pool_[0], std::memory_order_relaxed);
    }

    ~ObjectPool() {
        delete[] pool_;
    }

    T* acquire() {
        Node* node = free_list_.load(std::memory_order_acquire);
        while (node) {
            Node* next = node->next.load(std::memory_order_relaxed);
            if (free_list_.compare_exchange_weak(node, next,
                                                  std::memory_order_release,
                                                  std::memory_order_relaxed)) {
                return &node->object;
            }
            // CAS failed, node was updated, retry
        }
        return nullptr;  // Pool exhausted
    }

    void release(T* obj) {
        Node* node = reinterpret_cast<Node*>(
            reinterpret_cast<char*>(obj) - offsetof(Node, object));
        
        Node* old_head = free_list_.load(std::memory_order_relaxed);
        do {
            node->next.store(old_head, std::memory_order_relaxed);
        } while (!free_list_.compare_exchange_weak(old_head, node,
                                                    std::memory_order_release,
                                                    std::memory_order_relaxed));
    }
};
```

### 6.3 Thread-Local Caching

To reduce contention on the global pool, each thread can maintain a local cache:

```cpp
template<typename T>
class ThreadLocalPool {
private:
    ObjectPool<T>& global_pool_;
    
    static constexpr size_t LOCAL_CACHE_SIZE = 64;
    
    // Thread-local storage
    struct LocalCache {
        T* items[LOCAL_CACHE_SIZE];
        size_t count = 0;
    };
    
    static thread_local LocalCache local_cache_;

public:
    explicit ThreadLocalPool(ObjectPool<T>& global) : global_pool_(global) {}

    T* acquire() {
        LocalCache& cache = local_cache_;
        
        if (cache.count > 0) {
            return cache.items[--cache.count];
        }
        
        // Refill from global pool
        size_t to_fetch = LOCAL_CACHE_SIZE / 2;
        for (size_t i = 0; i < to_fetch; ++i) {
            T* obj = global_pool_.acquire();
            if (!obj) break;
            cache.items[cache.count++] = obj;
        }
        
        return cache.count > 0 ? cache.items[--cache.count] : nullptr;
    }

    void release(T* obj) {
        LocalCache& cache = local_cache_;
        
        if (cache.count < LOCAL_CACHE_SIZE) {
            cache.items[cache.count++] = obj;
            return;
        }
        
        // Return half to global pool
        size_t to_return = LOCAL_CACHE_SIZE / 2;
        for (size_t i = 0; i < to_return; ++i) {
            global_pool_.release(cache.items[--cache.count]);
        }
        
        cache.items[cache.count++] = obj;
    }
};
```

### 6.4 Huge Pages

For very large queues, use huge pages to reduce TLB misses:

```cpp
#include <sys/mman.h>

void* allocate_huge_pages(size_t size) {
    void* ptr = mmap(nullptr, size,
                     PROT_READ | PROT_WRITE,
                     MAP_PRIVATE | MAP_ANONYMOUS | MAP_HUGETLB,
                     -1, 0);
    
    if (ptr == MAP_FAILED) {
        // Fallback to regular pages
        ptr = mmap(nullptr, size,
                   PROT_READ | PROT_WRITE,
                   MAP_PRIVATE | MAP_ANONYMOUS,
                   -1, 0);
    }
    
    return ptr;
}
```

## 7. Producer-Consumer Patterns

### 7.1 Busy-Wait (Spin) Pattern

Best for lowest latency when you can dedicate CPU cores:

```cpp
// Producer
void producer_spin(MPMCQueue<Message>& queue, const Message& msg) {
    while (!queue.try_enqueue(msg)) {
        // Spin - optionally add pause instruction
        _mm_pause();  // Intel intrinsic for spin-wait
    }
}

// Consumer
void consumer_spin(MPMCQueue<Message>& queue, Message& msg) {
    while (!queue.try_dequeue(msg)) {
        _mm_pause();
    }
}
```

**Pros:**
- Lowest possible latency
- No context switch overhead

**Cons:**
- Burns 100% CPU
- Wastes power
- Can cause thermal throttling

### 7.2 Hybrid Spin-Then-Block Pattern

Spin for a while, then block if no progress:

```cpp
#include <thread>
#include <condition_variable>

template<typename T>
class BlockingQueue {
private:
    MPMCQueue<T> queue_;
    std::mutex mutex_;
    std::condition_variable not_empty_;
    std::condition_variable not_full_;
    
    static constexpr int SPIN_COUNT = 1000;

public:
    void enqueue(const T& item) {
        // Try spinning first
        for (int i = 0; i < SPIN_COUNT; ++i) {
            if (queue_.try_enqueue(item)) return;
            _mm_pause();
        }
        
        // Fall back to blocking
        std::unique_lock<std::mutex> lock(mutex_);
        while (!queue_.try_enqueue(item)) {
            not_full_.wait(lock);
        }
        not_empty_.notify_one();
    }

    T dequeue() {
        T item;
        
        // Try spinning first
        for (int i = 0; i < SPIN_COUNT; ++i) {
            if (queue_.try_dequeue(item)) return item;
            _mm_pause();
        }
        
        // Fall back to blocking
        std::unique_lock<std::mutex> lock(mutex_);
        while (!queue_.try_dequeue(item)) {
            not_empty_.wait(lock);
        }
        not_full_.notify_one();
        return item;
    }
};
```

### 7.3 Batching Pattern

Process multiple messages at once to amortize overhead:

```cpp
template<typename T>
class BatchingQueue {
private:
    MPMCQueue<T> queue_;

public:
    // Enqueue a batch of items
    size_t enqueue_batch(const T* items, size_t count) {
        size_t enqueued = 0;
        for (size_t i = 0; i < count; ++i) {
            if (!queue_.try_enqueue(items[i])) break;
            ++enqueued;
        }
        return enqueued;
    }

    // Dequeue a batch of items
    size_t dequeue_batch(T* items, size_t max_count) {
        size_t dequeued = 0;
        while (dequeued < max_count) {
            if (!queue_.try_dequeue(items[dequeued])) break;
            ++dequeued;
        }
        return dequeued;
    }
};

// Usage
void consumer_batched(BatchingQueue<Message>& queue) {
    constexpr size_t BATCH_SIZE = 64;
    Message batch[BATCH_SIZE];
    
    while (running) {
        size_t count = queue.dequeue_batch(batch, BATCH_SIZE);
        for (size_t i = 0; i < count; ++i) {
            process(batch[i]);
        }
        
        if (count == 0) {
            std::this_thread::yield();
        }
    }
}
```

**Benefits of batching:**
- Amortizes atomic operation costs
- Better cache utilization
- Reduces context switches

## 8. Bounded vs Unbounded Queues

### 8.1 Bounded Queue

Fixed maximum capacity. Enqueue fails when full.

**Pros:**
- Predictable memory usage
- Natural backpressure
- Better cache behavior

**Cons:**
- Can lose messages under load
- Must choose capacity carefully

### 8.2 Unbounded Queue

Grows dynamically as needed.

**Pros:**
- Never drops messages due to capacity
- Adapts to traffic spikes

**Cons:**
- Can exhaust memory
- No natural backpressure
- Memory fragmentation
- Harder to implement lock-free

### 8.3 Linked-List Based Unbounded Queue

```cpp
template<typename T>
class UnboundedMPMCQueue {
private:
    struct Node {
        std::atomic<Node*> next{nullptr};
        T data;
        
        Node() = default;
        explicit Node(const T& d) : data(d) {}
    };

    alignas(64) std::atomic<Node*> head_;
    alignas(64) std::atomic<Node*> tail_;
    
    ObjectPool<Node>& pool_;  // Use pool to avoid malloc overhead

public:
    explicit UnboundedMPMCQueue(ObjectPool<Node>& pool) : pool_(pool) {
        // Start with a dummy node
        Node* dummy = new Node();
        head_.store(dummy, std::memory_order_relaxed);
        tail_.store(dummy, std::memory_order_relaxed);
    }

    void enqueue(const T& item) {
        Node* node = pool_.acquire();
        node->data = item;
        node->next.store(nullptr, std::memory_order_relaxed);
        
        Node* prev_tail = tail_.exchange(node, std::memory_order_acq_rel);
        prev_tail->next.store(node, std::memory_order_release);
    }

    bool try_dequeue(T& item) {
        Node* head = head_.load(std::memory_order_acquire);
        Node* next = head->next.load(std::memory_order_acquire);
        
        if (!next) {
            return false;  // Queue is empty
        }
        
        if (head_.compare_exchange_strong(head, next,
                                          std::memory_order_release,
                                          std::memory_order_relaxed)) {
            item = std::move(next->data);
            pool_.release(head);  // Return dummy node to pool
            return true;
        }
        
        return false;  // Another consumer won
    }
};
```

## 9. Backpressure Handling

When producers are faster than consumers, the queue fills up. We need strategies to handle this.

### 9.1 Drop Oldest (Overwrite)

Replace oldest messages when full. Good for real-time data where old data is less valuable.

```cpp
template<typename T>
class OverwriteQueue {
private:
    T* buffer_;
    size_t capacity_;
    size_t mask_;
    
    alignas(64) std::atomic<size_t> write_pos_{0};
    alignas(64) std::atomic<size_t> read_pos_{0};

public:
    void enqueue(const T& item) {
        size_t pos = write_pos_.fetch_add(1, std::memory_order_relaxed);
        buffer_[pos & mask_] = item;
        
        // If we've lapped the reader, advance read_pos
        size_t read = read_pos_.load(std::memory_order_relaxed);
        while (pos - read >= capacity_) {
            read_pos_.compare_exchange_weak(read, read + 1,
                                            std::memory_order_relaxed);
        }
    }
};
```

### 9.2 Drop Newest

Reject new messages when full. Simple and fair.

```cpp
bool try_enqueue(const T& item) {
    if (is_full()) {
        ++dropped_count_;
        return false;
    }
    return queue_.try_enqueue(item);
}
```

### 9.3 Block Producer

Make producers wait when queue is full. Provides natural flow control.

```cpp
void enqueue_blocking(const T& item) {
    while (!queue_.try_enqueue(item)) {
        std::this_thread::yield();
        // Or use condition variable
    }
}
```

### 9.4 Dynamic Rate Limiting

Slow down producers based on queue depth:

```cpp
class AdaptiveProducer {
private:
    MPMCQueue<Message>& queue_;
    size_t queue_capacity_;
    
public:
    void send(const Message& msg) {
        size_t queue_size = queue_.size_approx();
        float utilization = static_cast<float>(queue_size) / queue_capacity_;
        
        if (utilization > 0.9) {
            // Queue nearly full, add significant delay
            std::this_thread::sleep_for(std::chrono::microseconds(100));
        } else if (utilization > 0.7) {
            // Queue getting full, add small delay
            std::this_thread::sleep_for(std::chrono::microseconds(10));
        }
        
        while (!queue_.try_enqueue(msg)) {
            std::this_thread::yield();
        }
    }
};
```

## 10. Performance Optimizations

### 10.1 Cache Line Padding (Preventing False Sharing)

When two atomic variables are on the same cache line, updates to one invalidate the other:

```cpp
// BAD: head_ and tail_ on same cache line
struct {
    std::atomic<size_t> head_;
    std::atomic<size_t> tail_;
};

// GOOD: Each on its own cache line
alignas(64) std::atomic<size_t> head_;
alignas(64) std::atomic<size_t> tail_;
```

### 10.2 Memory Ordering

Use the weakest memory ordering that's correct:

```cpp
// Expensive: full barrier
head_.store(value, std::memory_order_seq_cst);

// Cheaper: release barrier (sufficient for publishing)
head_.store(value, std::memory_order_release);

// Cheapest: no barrier (only for thread-local or already synchronized)
head_.store(value, std::memory_order_relaxed);
```

### 10.3 Prefetching

Tell the CPU to load data before you need it:

```cpp
void consumer_prefetch(Queue<Message>& queue) {
    Message current, next;
    
    while (queue.try_dequeue(current)) {
        // Prefetch the next message while processing current
        if (queue.peek(next)) {
            __builtin_prefetch(&next, 0, 3);  // Read, high locality
        }
        
        process(current);
    }
}
```

### 10.4 NUMA-Aware Design

On multi-socket systems, memory access time depends on which socket owns the memory:

```cpp
#include <numa.h>

void* allocate_on_node(size_t size, int node) {
    return numa_alloc_onnode(size, node);
}

// Pin thread to specific CPU/node
void pin_to_node(int node) {
    cpu_set_t cpuset;
    CPU_ZERO(&cpuset);
    
    // Add all CPUs on this node
    struct bitmask* cpus = numa_allocate_cpumask();
    numa_node_to_cpus(node, cpus);
    
    for (int i = 0; i < numa_num_configured_cpus(); ++i) {
        if (numa_bitmask_isbitset(cpus, i)) {
            CPU_SET(i, &cpuset);
        }
    }
    
    pthread_setaffinity_np(pthread_self(), sizeof(cpuset), &cpuset);
    numa_free_cpumask(cpus);
}
```

### 10.5 Avoiding Contention with Multiple Queues

Instead of one heavily-contended MPMC queue, use multiple SPSC queues:

```cpp
template<typename T>
class StripedQueue {
private:
    static constexpr size_t NUM_STRIPES = 16;
    SPSCQueue<T> queues_[NUM_STRIPES];
    
    std::atomic<size_t> next_producer_{0};
    std::atomic<size_t> next_consumer_{0};

public:
    // Each producer gets its own queue (round-robin assignment)
    SPSCQueue<T>& get_producer_queue() {
        size_t id = next_producer_.fetch_add(1, std::memory_order_relaxed);
        return queues_[id % NUM_STRIPES];
    }
    
    // Consumers round-robin across queues
    bool try_dequeue(T& item) {
        for (size_t i = 0; i < NUM_STRIPES; ++i) {
            size_t idx = (next_consumer_.load() + i) % NUM_STRIPES;
            if (queues_[idx].try_dequeue(item)) {
                next_consumer_.fetch_add(1, std::memory_order_relaxed);
                return true;
            }
        }
        return false;
    }
};
```

Here's a production-ready implementation combining all the concepts:

```cpp
#ifndef HIGH_THROUGHPUT_QUEUE_HPP
#define HIGH_THROUGHPUT_QUEUE_HPP

#include <atomic>
#include <cstddef>
#include <cstdint>
#include <new>
#include <type_traits>
#include <utility>
#include <stdexcept>

#ifdef __x86_64__
#include <emmintrin.h>
#define PAUSE() _mm_pause()
#else
#define PAUSE() ((void)0)
#endif

namespace htq {

// ============================================================================
// Compile-time configuration
// ============================================================================

constexpr size_t CACHE_LINE_SIZE = 64;
constexpr size_t DEFAULT_CAPACITY = 65536;  // 64K slots

// ============================================================================
// Utility functions
// ============================================================================

constexpr size_t round_up_to_power_of_2(size_t n) {
    --n;
    n |= n >> 1;
    n |= n >> 2;
    n |= n >> 4;
    n |= n >> 8;
    n |= n >> 16;
    n |= n >> 32;
    return n + 1;
}

constexpr bool is_power_of_2(size_t n) {
    return n && !(n & (n - 1));
}

// ============================================================================
// SPSC Queue - Single Producer, Single Consumer
// ============================================================================

template<typename T, size_t Capacity = DEFAULT_CAPACITY>
class SPSCQueue {
    static_assert(is_power_of_2(Capacity), "Capacity must be a power of 2");
    
private:
    struct alignas(CACHE_LINE_SIZE) Slot {
        T data;
    };
    
    static constexpr size_t MASK = Capacity - 1;
    
    Slot slots_[Capacity];
    
    // Producer state
    alignas(CACHE_LINE_SIZE) std::atomic<size_t> head_{0};
    size_t cached_tail_{0};
    
    // Consumer state  
    alignas(CACHE_LINE_SIZE) std::atomic<size_t> tail_{0};
    size_t cached_head_{0};

public:
    SPSCQueue() = default;
    
    // Non-copyable, non-movable
    SPSCQueue(const SPSCQueue&) = delete;
    SPSCQueue& operator=(const SPSCQueue&) = delete;
    
    // Producer interface
    template<typename U>
    bool try_push(U&& item) {
        const size_t head = head_.load(std::memory_order_relaxed);
        const size_t next = head + 1;
        
        if (next - cached_tail_ > MASK) {
            cached_tail_ = tail_.load(std::memory_order_acquire);
            if (next - cached_tail_ > MASK) {
                return false;
            }
        }
        
        slots_[head & MASK].data = std::forward<U>(item);
        head_.store(next, std::memory_order_release);
        return true;
    }
    
    template<typename U>
    void push(U&& item) {
        while (!try_push(std::forward<U>(item))) {
            PAUSE();
        }
    }
    
    // Consumer interface
    bool try_pop(T& item) {
        const size_t tail = tail_.load(std::memory_order_relaxed);
        
        if (tail == cached_head_) {
            cached_head_ = head_.load(std::memory_order_acquire);
            if (tail == cached_head_) {
                return false;
            }
        }
        
        item = std::move(slots_[tail & MASK].data);
        tail_.store(tail + 1, std::memory_order_release);
        return true;
    }
    
    T pop() {
        T item;
        while (!try_pop(item)) {
            PAUSE();
        }
        return item;
    }
    
    bool empty() const {
        return head_.load(std::memory_order_acquire) == 
               tail_.load(std::memory_order_acquire);
    }
    
    size_t size() const {
        const size_t head = head_.load(std::memory_order_acquire);
        const size_t tail = tail_.load(std::memory_order_acquire);
        return head - tail;
    }
    
    static constexpr size_t capacity() { return Capacity; }
};

// ============================================================================
// MPMC Queue - Multi Producer, Multi Consumer
// ============================================================================

template<typename T, size_t Capacity = DEFAULT_CAPACITY>
class MPMCQueue {
    static_assert(is_power_of_2(Capacity), "Capacity must be a power of 2");
    
private:
    struct Slot {
        std::atomic<size_t> sequence;
        T data;
        
        Slot() : sequence(0) {}
    };
    
    static constexpr size_t MASK = Capacity - 1;
    
    alignas(CACHE_LINE_SIZE) Slot slots_[Capacity];
    alignas(CACHE_LINE_SIZE) std::atomic<size_t> head_{0};
    alignas(CACHE_LINE_SIZE) std::atomic<size_t> tail_{0};

public:
    MPMCQueue() {
        for (size_t i = 0; i < Capacity; ++i) {
            slots_[i].sequence.store(i, std::memory_order_relaxed);
        }
    }
    
    // Non-copyable, non-movable
    MPMCQueue(const MPMCQueue&) = delete;
    MPMCQueue& operator=(const MPMCQueue&) = delete;
    
    template<typename U>
    bool try_push(U&& item) {
        size_t head = head_.load(std::memory_order_relaxed);
        
        for (;;) {
            Slot& slot = slots_[head & MASK];
            const size_t seq = slot.sequence.load(std::memory_order_acquire);
            const intptr_t diff = static_cast<intptr_t>(seq) - 
                                  static_cast<intptr_t>(head);
            
            if (diff == 0) {
                if (head_.compare_exchange_weak(head, head + 1,
                                                std::memory_order_relaxed)) {
                    slot.data = std::forward<U>(item);
                    slot.sequence.store(head + 1, std::memory_order_release);
                    return true;
                }
            } else if (diff < 0) {
                return false;  // Queue full
            } else {
                head = head_.load(std::memory_order_relaxed);
            }
        }
    }
    
    template<typename U>
    void push(U&& item) {
        while (!try_push(std::forward<U>(item))) {
            PAUSE();
        }
    }
    
    bool try_pop(T& item) {
        size_t tail = tail_.load(std::memory_order_relaxed);
        
        for (;;) {
            Slot& slot = slots_[tail & MASK];
            const size_t seq = slot.sequence.load(std::memory_order_acquire);
            const intptr_t diff = static_cast<intptr_t>(seq) - 
                                  static_cast<intptr_t>(tail + 1);
            
            if (diff == 0) {
                if (tail_.compare_exchange_weak(tail, tail + 1,
                                                std::memory_order_relaxed)) {
                    item = std::move(slot.data);
                    slot.sequence.store(tail + MASK + 1, std::memory_order_release);
                    return true;
                }
            } else if (diff < 0) {
                return false;  // Queue empty
            } else {
                tail = tail_.load(std::memory_order_relaxed);
            }
        }
    }
    
    T pop() {
        T item;
        while (!try_pop(item)) {
            PAUSE();
        }
        return item;
    }
    
    bool empty() const {
        const size_t head = head_.load(std::memory_order_acquire);
        const size_t tail = tail_.load(std::memory_order_acquire);
        return head == tail;
    }
    
    size_t size_approx() const {
        const size_t head = head_.load(std::memory_order_relaxed);
        const size_t tail = tail_.load(std::memory_order_relaxed);
        return head >= tail ? head - tail : 0;
    }
    
    static constexpr size_t capacity() { return Capacity; }
};

// ============================================================================
// Blocking MPMC Queue with condition variables
// ============================================================================

#include <mutex>
#include <condition_variable>

template<typename T, size_t Capacity = DEFAULT_CAPACITY>
class BlockingMPMCQueue {
private:
    MPMCQueue<T, Capacity> queue_;
    std::mutex mutex_;
    std::condition_variable not_empty_;
    std::condition_variable not_full_;
    
    static constexpr int SPIN_TRIES = 100;

public:
    BlockingMPMCQueue() = default;
    
    template<typename U>
    bool try_push(U&& item) {
        return queue_.try_push(std::forward<U>(item));
    }
    
    template<typename U>
    void push(U&& item) {
        // Try non-blocking first
        for (int i = 0; i < SPIN_TRIES; ++i) {
            if (queue_.try_push(std::forward<U>(item))) {
                not_empty_.notify_one();
                return;
            }
            PAUSE();
        }
        
        // Fall back to blocking
        std::unique_lock<std::mutex> lock(mutex_);
        while (!queue_.try_push(std::forward<U>(item))) {
            not_full_.wait(lock);
        }
        lock.unlock();
        not_empty_.notify_one();
    }
    
    bool try_pop(T& item) {
        return queue_.try_pop(item);
    }
    
    T pop() {
        T item;
        
        // Try non-blocking first
        for (int i = 0; i < SPIN_TRIES; ++i) {
            if (queue_.try_pop(item)) {
                not_full_.notify_one();
                return item;
            }
            PAUSE();
        }
        
        // Fall back to blocking
        std::unique_lock<std::mutex> lock(mutex_);
        while (!queue_.try_pop(item)) {
            not_empty_.wait(lock);
        }
        lock.unlock();
        not_full_.notify_one();
        return item;
    }
    
    bool empty() const { return queue_.empty(); }
    size_t size_approx() const { return queue_.size_approx(); }
    static constexpr size_t capacity() { return Capacity; }
};

// ============================================================================
// Memory Pool for zero-allocation message passing
// ============================================================================

template<typename T, size_t PoolSize = 65536>
class MemoryPool {
private:
    union Slot {
        T object;
        Slot* next;
        
        Slot() : next(nullptr) {}
        ~Slot() {}
    };
    
    alignas(CACHE_LINE_SIZE) std::atomic<Slot*> free_list_;
    alignas(CACHE_LINE_SIZE) Slot pool_[PoolSize];

public:
    MemoryPool() : free_list_(&pool_[0]) {
        for (size_t i = 0; i < PoolSize - 1; ++i) {
            pool_[i].next = &pool_[i + 1];
        }
        pool_[PoolSize - 1].next = nullptr;
    }
    
    ~MemoryPool() {
        // Objects should be explicitly destroyed before pool destruction
    }
    
    template<typename... Args>
    T* allocate(Args&&... args) {
        Slot* slot = pop_free_list();
        if (!slot) return nullptr;
        
        return new (&slot->object) T(std::forward<Args>(args)...);
    }
    
    void deallocate(T* obj) {
        if (!obj) return;
        
        obj->~T();
        Slot* slot = reinterpret_cast<Slot*>(obj);
        push_free_list(slot);
    }

private:
    Slot* pop_free_list() {
        Slot* head = free_list_.load(std::memory_order_acquire);
        while (head) {
            Slot* next = head->next;
            if (free_list_.compare_exchange_weak(head, next,
                                                  std::memory_order_release,
                                                  std::memory_order_relaxed)) {
                return head;
            }
        }
        return nullptr;
    }
    
    void push_free_list(Slot* slot) {
        Slot* head = free_list_.load(std::memory_order_relaxed);
        do {
            slot->next = head;
        } while (!free_list_.compare_exchange_weak(head, slot,
                                                    std::memory_order_release,
                                                    std::memory_order_relaxed));
    }
};
```

```cpp
#include <vector>

template<typename Queue>
void benchmark_throughput(const char* name, int num_producers, int num_consumers) {
    constexpr size_t MESSAGES_PER_PRODUCER = 10'000'000;
    
    Queue queue;
    std::atomic<bool> start{false};
    std::atomic<size_t> total_produced{0};
    std::atomic<size_t> total_consumed{0};
    
    // Create producers
    std::vector<std::thread> producers;
    for (int i = 0; i < num_producers; ++i) {
        producers.emplace_back([&, i]() {
            while (!start.load(std::memory_order_acquire)) {
                std::this_thread::yield();
            }
            
            for (size_t j = 0; j < MESSAGES_PER_PRODUCER; ++j) {
                int64_t msg = i * MESSAGES_PER_PRODUCER + j;
                queue.push(msg);
                total_produced.fetch_add(1, std::memory_order_relaxed);
            }
        });
    }
    
    // Create consumers
    std::vector<std::thread> consumers;
    const size_t total_messages = num_producers * MESSAGES_PER_PRODUCER;
    
    for (int i = 0; i < num_consumers; ++i) {
        consumers.emplace_back([&]() {
            while (!start.load(std::memory_order_acquire)) {
                std::this_thread::yield();
            }
            
            while (total_consumed.load(std::memory_order_relaxed) < total_messages) {
                int64_t msg;
                if (queue.try_pop(msg)) {
                    total_consumed.fetch_add(1, std::memory_order_relaxed);
                }
            }
        });

    // Start timing
    auto begin = std::chrono::high_resolution_clock::now();
    start.store(true, std::memory_order_release);
    
    // Wait for completion
    for (auto& t : producers) t.join();
    for (auto& t : consumers) t.join();
    
    auto end = std::chrono::high_resolution_clock::now();
    auto duration = std::chrono::duration_cast<std::chrono::milliseconds>(end - begin);
    
    double messages_per_sec = total_messages * 1000.0 / duration.count();
    
    std::cout << name << " (" << num_producers << "P/" << num_consumers << "C): "

}
```

| MPMC | 8P/8C | 40-80 M msg/s | 150-300 ns | 1-2 µs |

## 13. Trade-offs and Alternatives

### 13.1 Trade-off Summary

| Aspect | SPSC | MPMC | Blocking MPMC |
|--------|------|------|---------------|
| Throughput | Highest | Medium | Lower |
| Latency | Lowest | Low | Higher |
| CPU Usage | Can spin | Can spin | Efficient |
| Complexity | Simple | Complex | Medium |
| Flexibility | Limited | High | High |

### 13.2 When to Use Each Pattern

**Use SPSC when:**
- You have exactly one producer and one consumer
- Maximum throughput is critical
- You can afford dedicated CPU cores

**Use MPMC when:**
- You need multiple producers or consumers
- Low latency is important
- You can afford some spin-waiting

**Use Blocking MPMC when:**
- You have variable workloads
- You need to share CPU with other work
- Latency requirements are moderate

### 13.3 Alternative Approaches

**1. Disruptor Pattern (LMAX)**
- Single-producer, broadcast to multiple consumers
- Eliminates queue contention entirely
- Best for event streaming

**2. Work-Stealing Queues**
- Each consumer has its own queue
- Consumers "steal" from others when idle
- Great for load balancing

**3. Staged Event-Driven Architecture (SEDA)**
- Multiple queues in a pipeline
- Each stage processes and forwards
- Good for complex workflows

## Summary

Designing a high-throughput message queue requires deep understanding of:

1. **Lock-free programming**: Using atomics instead of mutexes
2. **Memory management**: Pre-allocation and object pools
3. **Cache optimization**: Padding, alignment, and locality
4. **Producer-consumer patterns**: SPSC vs MPMC trade-offs
5. **Backpressure**: Handling fast producers, slow consumers

**Key Takeaways:**

1. **Start with requirements**: Clarify SPSC vs MPMC, throughput vs latency
2. **Do the math**: Calculate time budgets and feasibility
3. **Choose the right algorithm**: Sequence-based MPMC is the gold standard
4. **Optimize memory access**: Cache lines, padding, NUMA awareness
5. **Benchmark realistically**: Test with your actual workload patterns

The implementation shown here can achieve **millions of messages per second** with **sub-microsecond latency**, suitable for high-frequency trading, real-time streaming, and high-performance computing applications.
