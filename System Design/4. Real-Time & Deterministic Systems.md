# Real-Time & Deterministic Systems in C++

## Introduction

Real-time systems are not about being "fast"—they're about being **predictable**. A real-time system that always responds in 10ms is better than one that usually responds in 1ms but occasionally takes 100ms.

This document covers the fundamental concepts for designing systems where timing guarantees matter: trading systems, industrial control, robotics, audio processing, and high-frequency networking.

## 1. Deterministic Latency

### What is Deterministic Latency?

**Deterministic latency** means that the time between an input event and the corresponding output is bounded and predictable—not just on average, but in the **worst case**.

```
Non-Deterministic System:
  Latency: 1ms, 1ms, 2ms, 1ms, 150ms(!), 1ms, 1ms, 3ms, 200ms(!)
  Average: ~40ms, but spikes to 200ms
  
Deterministic System:
  Latency: 8ms, 9ms, 7ms, 10ms, 9ms, 8ms, 10ms, 9ms, 8ms
  Worst case: 10ms (guaranteed)
```

### Hard Real-Time vs Soft Real-Time

| Type | Definition | Example | Consequence of Miss |
|------|------------|---------|---------------------|
| **Hard Real-Time** | Missing a deadline is a system failure | Airbag deployment, pacemaker | Catastrophic (death, injury) |
| **Soft Real-Time** | Missing a deadline degrades quality | Video streaming, audio | Quality degradation |
| **Firm Real-Time** | Late results are worthless but not catastrophic | Financial trading | Missed opportunity, loss |

### Sources of Non-Determinism

Understanding what causes latency spikes is the first step to eliminating them:


### Latency Breakdown Example

Typical latency contributors in a network processing system:

| Source | Typical | Worst Case | Notes |
|--------|---------|------------|-------|
| NIC interrupt | 1 µs | 100 µs | Interrupt coalescing |
| Context switch | 1-5 µs | 50 µs | If preempted |
| Cache miss (L3→RAM) | 60 ns | 200 ns | NUMA remote access |
| Page fault | - | 10 ms+ | Catastrophic! |
| malloc | 50 ns | 1 ms | Depends on fragmentation |
| Mutex (contended) | 1 µs | unbounded | Priority inversion |
| System call | 100 ns | 10 µs | Varies by call |

### Achieving Deterministic Latency

#### Technique 1: Pre-allocate Everything

Avoid all dynamic memory allocation in the hot path:

```cpp
class DeterministicProcessor {
    // Pre-allocate all memory at startup
    std::array<Message, 10000> message_pool_;
    std::array<Result, 10000> result_pool_;
    size_t message_pool_index_ = 0;
    size_t result_pool_index_ = 0;
    
public:
    void init() {
        // Touch all memory to ensure pages are mapped
        for (auto& m : message_pool_) {
            volatile char c = reinterpret_cast<char*>(&m)[0];
            (void)c;
        }
        for (auto& r : result_pool_) {
            volatile char c = reinterpret_cast<char*>(&r)[0];
            (void)c;
        }
    }
    
    Message* allocate_message() {
        // O(1), no syscall, no fragmentation
        return &message_pool_[message_pool_index_++ % message_pool_.size()];
    }
    
    // Never call new/malloc in hot path!
};
```

#### Technique 2: Lock Memory in RAM

Prevent the OS from swapping your pages to disk:

```cpp
#include <sys/mman.h>

void lock_memory() {
    // Lock all current and future memory
    if (mlockall(MCL_CURRENT | MCL_FUTURE) != 0) {
        throw std::runtime_error("Failed to lock memory");
    }
}

// For specific allocations
void* allocate_locked(size_t size) {
    void* ptr = aligned_alloc(64, size);  // Cache-line aligned
    if (mlock(ptr, size) != 0) {
        free(ptr);
        throw std::runtime_error("Failed to lock memory");
    }
    return ptr;
}
```

#### Technique 3: Disable Interrupts/Preemption (Kernel or RT Linux)

On real-time Linux with `PREEMPT_RT` patch:

```cpp
#include <pthread.h>
#include <sched.h>

void setup_realtime_thread() {
    // Set real-time scheduling policy
    struct sched_param param;
    param.sched_priority = 99;  // Highest priority
    
    if (pthread_setschedparam(pthread_self(), SCHED_FIFO, &param) != 0) {
        throw std::runtime_error("Failed to set RT priority");
    }
    
    // Pin to specific CPU to avoid migration
    cpu_set_t cpuset;
    CPU_ZERO(&cpuset);
    CPU_SET(2, &cpuset);  // Pin to CPU 2
    
    if (pthread_setaffinity_np(pthread_self(), sizeof(cpuset), &cpuset) != 0) {
        throw std::runtime_error("Failed to set CPU affinity");
    }
}
```

#### Technique 4: Busy-Wait Instead of Blocking

Blocking calls can have unbounded latency:

```cpp
// BAD: Blocking wait - latency depends on scheduler
void wait_for_event_blocking(std::condition_variable& cv, std::mutex& m) {
    std::unique_lock<std::mutex> lock(m);
    cv.wait(lock);  // Could take microseconds to milliseconds!
}

// GOOD: Busy-wait - deterministic (but burns CPU)
void wait_for_event_spinning(std::atomic<bool>& flag) {
    while (!flag.load(std::memory_order_acquire)) {
        _mm_pause();  // CPU hint for spin-wait
    }
}

// BETTER: Hybrid approach
void wait_for_event_hybrid(std::atomic<bool>& flag, int spin_count = 1000) {
    // Spin first for low-latency response
    for (int i = 0; i < spin_count; ++i) {
        if (flag.load(std::memory_order_acquire)) return;
        _mm_pause();
    }
    
    // Fall back to blocking only if spinning didn't work
    // (acceptable if this is the rare case)
    while (!flag.load(std::memory_order_acquire)) {
        std::this_thread::sleep_for(std::chrono::microseconds(1));
    }
}
```

#### Technique 5: Avoid System Calls in Hot Path

```cpp
// BAD: System calls in hot path
void process_with_syscalls(const Data& d) {
    auto now = std::chrono::system_clock::now();  // syscall: clock_gettime
    log_to_file(d);  // syscall: write
    send_to_network(d);  // syscall: sendto
}

// GOOD: Batch/defer system calls
class DeferredLogger {
    std::array<LogEntry, 1000> buffer_;
    std::atomic<size_t> write_pos_{0};
    
public:
    void log(const LogEntry& entry) {
        // Lock-free, no syscall
        size_t pos = write_pos_.fetch_add(1, std::memory_order_relaxed);
        buffer_[pos % buffer_.size()] = entry;
    }
    
    // Flush from low-priority background thread
    void flush_background() {
        // This thread can block, take its time
        write_to_disk(buffer_);
    }
};
```

### Measuring Latency Correctly

Don't measure averages—measure **percentiles**:

```cpp
#include <algorithm>
#include <vector>
#include <chrono>

class LatencyHistogram {
    std::vector<int64_t> samples_;
    size_t index_ = 0;
    
public:
    explicit LatencyHistogram(size_t capacity) : samples_(capacity) {}
    
    void record(std::chrono::nanoseconds latency) {
        samples_[index_++ % samples_.size()] = latency.count();
    }
    
    void print_statistics() const {
        std::vector<int64_t> sorted = samples_;
        std::sort(sorted.begin(), sorted.end());
        
        size_t n = sorted.size();
        
        std::cout << "Latency Statistics (nanoseconds):\n"
                  << "  Min:     " << sorted[0] << "\n"
                  << "  P50:     " << sorted[n * 50 / 100] << "\n"
                  << "  P90:     " << sorted[n * 90 / 100] << "\n"
                  << "  P99:     " << sorted[n * 99 / 100] << "\n"
                  << "  P99.9:   " << sorted[n * 999 / 1000] << "\n"
                  << "  P99.99:  " << sorted[n * 9999 / 10000] << "\n"
                  << "  Max:     " << sorted[n - 1] << "\n";
    }
};
```

**Key Insight**: For real-time systems, the **P99.9** or **max** latency matters more than the average!

### Jitter vs Latency

**Latency**: Time from input to output  
**Jitter**: Variation in latency

```
Low latency, high jitter:    [1ms, 5ms, 2ms, 8ms, 1ms]  - Unpredictable!
High latency, low jitter:    [9ms, 10ms, 9ms, 10ms, 9ms] - Predictable!
```

For real-time systems, **low jitter is often more important than low average latency**.

## 2. Priority Scheduling

### Why Priority Scheduling?

Not all tasks are equally important. A trading system might need to:
- Process market data updates: **Critical** (microseconds matter)
- Send heartbeats: **Important** (seconds OK)
- Generate reports: **Background** (minutes OK)

Priority scheduling ensures critical tasks get resources first.

### Priority Levels

```
┌─────────────────────────────────────────────────────────────────┐
│                    PRIORITY HIERARCHY                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  Priority 0 (Highest) ─────► Interrupt handlers, critical I/O  │
│       │                                                          │
│       ▼                                                          │
│  Priority 1 ───────────────► Real-time processing               │
│       │                                                          │
│       ▼                                                          │
│  Priority 2 ───────────────► Normal processing                  │
│       │                                                          │
│       ▼                                                          │
│  Priority 3 ───────────────► Background tasks                   │
│       │                                                          │
│       ▼                                                          │
│  Priority 4 (Lowest) ──────► Housekeeping, logging              │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### OS-Level Priority Scheduling

Linux provides several scheduling policies:

| Policy | Type | Description | Use Case |
|--------|------|-------------|----------|
| `SCHED_FIFO` | Real-time | First-in, first-out, no time slicing | Hard RT |
| `SCHED_RR` | Real-time | Round-robin with time quantum | Soft RT |
| `SCHED_OTHER` | Normal | Standard time-sharing | General |
| `SCHED_BATCH` | Normal | Optimized for batch jobs | Background |
| `SCHED_IDLE` | Normal | Very low priority | Housekeeping |

```cpp
#include <pthread.h>
#include <sched.h>

enum class TaskPriority {
    CRITICAL = 99,    // Highest RT priority
    HIGH = 80,
    NORMAL = 50,
    LOW = 20,
    BACKGROUND = 1    // Lowest RT priority
};

void set_thread_priority(pthread_t thread, TaskPriority priority) {
    struct sched_param param;
    param.sched_priority = static_cast<int>(priority);
    
    int policy = (priority >= TaskPriority::LOW) ? SCHED_FIFO : SCHED_OTHER;
    
    int result = pthread_setschedparam(thread, policy, &param);
    if (result != 0) {
        throw std::runtime_error("Failed to set thread priority");
    }
}

// Usage
void create_realtime_thread(void* (*func)(void*), TaskPriority priority) {
    pthread_t thread;
    pthread_attr_t attr;
    
    pthread_attr_init(&attr);
    pthread_attr_setschedpolicy(&attr, SCHED_FIFO);
    
    struct sched_param param;
    param.sched_priority = static_cast<int>(priority);
    pthread_attr_setschedparam(&attr, &param);
    pthread_attr_setinheritsched(&attr, PTHREAD_EXPLICIT_SCHED);
    
    pthread_create(&thread, &attr, func, nullptr);
    pthread_attr_destroy(&attr);
}
```

### Application-Level Priority Scheduling

Implement your own priority scheduler for finer control:

```cpp
#include <queue>
#include <functional>
#include <mutex>
#include <condition_variable>

struct Task {
    int priority;  // Higher = more important
    std::function<void()> work;
    
    bool operator<(const Task& other) const {
        return priority < other.priority;  // Max-heap
    }
};

class PriorityTaskScheduler {
    std::priority_queue<Task> queue_;
    std::mutex mutex_;
    std::condition_variable cv_;
    std::atomic<bool> running_{true};
    std::vector<std::thread> workers_;
    
public:
    explicit PriorityTaskScheduler(size_t num_workers) {
        for (size_t i = 0; i < num_workers; ++i) {
            workers_.emplace_back([this] { worker_loop(); });
        }
    }
    
    ~PriorityTaskScheduler() {
        running_ = false;
        cv_.notify_all();
        for (auto& w : workers_) {
            w.join();
        }
    }
    
    void submit(int priority, std::function<void()> work) {
        {
            std::lock_guard<std::mutex> lock(mutex_);
            queue_.push({priority, std::move(work)});
        }
        cv_.notify_one();
    }
    
private:
    void worker_loop() {
        while (running_) {
            Task task;
            {
                std::unique_lock<std::mutex> lock(mutex_);
                cv_.wait(lock, [this] { 
                    return !running_ || !queue_.empty(); 
                });
                
                if (!running_ && queue_.empty()) return;
                
                task = std::move(const_cast<Task&>(queue_.top()));
                queue_.pop();
            }
            task.work();
        }
    }
};

// Usage
PriorityTaskScheduler scheduler(4);

scheduler.submit(100, [] { /* Critical: process market data */ });
scheduler.submit(50, [] { /* Normal: update display */ });
scheduler.submit(10, [] { /* Low: write logs */ });
```

### Priority Inversion Problem

**Priority inversion** occurs when a high-priority task is blocked waiting for a resource held by a low-priority task:

```
Time ─────────────────────────────────────────────────────────────►

High Priority:    [blocked waiting for lock.....................][runs]
Medium Priority:  .............[runs][runs][runs][runs]...........
Low Priority:     [holds lock]..............................[releases]

The high-priority task is blocked while medium-priority tasks run!
This is unbounded priority inversion - the high-priority task could wait forever.
```

**Famous Example**: Mars Pathfinder suffered from priority inversion in 1997, causing system resets.

### Solutions to Priority Inversion

#### Solution 1: Priority Inheritance

When a low-priority thread holds a lock needed by a high-priority thread, temporarily boost the low-priority thread:

```cpp
#include <pthread.h>

class PriorityInheritanceMutex {
    pthread_mutex_t mutex_;
    
public:
    PriorityInheritanceMutex() {
        pthread_mutexattr_t attr;
        pthread_mutexattr_init(&attr);
        pthread_mutexattr_setprotocol(&attr, PTHREAD_PRIO_INHERIT);
        pthread_mutex_init(&mutex_, &attr);
        pthread_mutexattr_destroy(&attr);
    }
    
    ~PriorityInheritanceMutex() {
        pthread_mutex_destroy(&mutex_);
    }
    
    void lock() { pthread_mutex_lock(&mutex_); }
    void unlock() { pthread_mutex_unlock(&mutex_); }
};
```

#### Solution 2: Priority Ceiling

Set a ceiling priority on the mutex. Any thread holding it runs at that priority:

```cpp
class PriorityCeilingMutex {
    pthread_mutex_t mutex_;
    
public:
    PriorityCeilingMutex(int ceiling_priority) {
        pthread_mutexattr_t attr;
        pthread_mutexattr_init(&attr);
        pthread_mutexattr_setprotocol(&attr, PTHREAD_PRIO_PROTECT);
        pthread_mutexattr_setprioceiling(&attr, ceiling_priority);
        pthread_mutex_init(&mutex_, &attr);
        pthread_mutexattr_destroy(&attr);
    }
    
    ~PriorityCeilingMutex() {
        pthread_mutex_destroy(&mutex_);
    }
    
    void lock() { pthread_mutex_lock(&mutex_); }
    void unlock() { pthread_mutex_unlock(&mutex_); }
};
```

#### Solution 3: Lock-Free Data Structures

Avoid locks entirely in critical paths:

```cpp
// Instead of a locked queue
class LockedQueue {
    std::queue<Message> queue_;
    std::mutex mutex_;
    
public:
    void push(Message m) {
        std::lock_guard<std::mutex> lock(mutex_);  // Can cause priority inversion!
        queue_.push(m);
    }
};

// Use lock-free queue
template<typename T, size_t Capacity>
class LockFreeQueue {
    std::array<std::atomic<T*>, Capacity> buffer_;
    std::atomic<size_t> head_{0};
    std::atomic<size_t> tail_{0};
    
public:
    bool try_push(T* item) {
        size_t head = head_.load(std::memory_order_relaxed);
        size_t next = (head + 1) % Capacity;
        
        if (next == tail_.load(std::memory_order_acquire)) {
            return false;  // Full
        }
        
        buffer_[head].store(item, std::memory_order_relaxed);
        head_.store(next, std::memory_order_release);
        return true;
    }
    
    T* try_pop() {
        size_t tail = tail_.load(std::memory_order_relaxed);
        
        if (tail == head_.load(std::memory_order_acquire)) {
            return nullptr;  // Empty
        }
        
        T* item = buffer_[tail].load(std::memory_order_relaxed);
        tail_.store((tail + 1) % Capacity, std::memory_order_release);
        return item;
    }
};
```

### Multi-Level Feedback Queue

A sophisticated scheduler that adjusts priorities dynamically:

```cpp
class MultiLevelFeedbackQueue {
    static constexpr int NUM_LEVELS = 4;
    static constexpr int TIME_QUANTUM_MS[] = {10, 20, 40, 80};  // Increasing
    
    std::array<std::queue<Task>, NUM_LEVELS> queues_;
    std::mutex mutex_;
    
public:
    void submit(Task task, int initial_level = 0) {
        std::lock_guard<std::mutex> lock(mutex_);
        queues_[initial_level].push(task);
    }
    
    std::optional<Task> get_next_task() {
        std::lock_guard<std::mutex> lock(mutex_);
        
        // Always check highest priority first
        for (int level = 0; level < NUM_LEVELS; ++level) {
            if (!queues_[level].empty()) {
                Task task = queues_[level].front();
                queues_[level].pop();
                return task;
            }
        }
        return std::nullopt;
    }
    
    // If task doesn't complete in time quantum, demote it
    void demote_task(Task task, int current_level) {
        int new_level = std::min(current_level + 1, NUM_LEVELS - 1);
        submit(task, new_level);
    }
    
    // Periodically boost all tasks to prevent starvation
    void boost_all() {
        std::lock_guard<std::mutex> lock(mutex_);
        for (int level = 1; level < NUM_LEVELS; ++level) {
            while (!queues_[level].empty()) {
                queues_[0].push(queues_[level].front());
                queues_[level].pop();
            }
        }
    }
};
```

## 3. Backpressure Handling

### What is Backpressure?

**Backpressure** is a mechanism to handle the situation when a system receives data faster than it can process it.

```
Without Backpressure:
  Producer (1000/sec) ────► [Queue grows forever] ────► Consumer (500/sec)
                                    │
                                    ▼
                            MEMORY EXHAUSTION! 💥

With Backpressure:
  Producer (1000/sec) ◄── "Slow down!" ── [Bounded Queue] ────► Consumer (500/sec)
                                    │
                                    ▼
                            System stays stable ✓
```

### Backpressure Strategies

#### Strategy 1: Blocking (Synchronous Backpressure)

The producer blocks until the consumer catches up:

```cpp
template<typename T, size_t Capacity>
class BlockingBoundedQueue {
    std::array<T, Capacity> buffer_;
    size_t head_ = 0;
    size_t tail_ = 0;
    size_t count_ = 0;
    
    std::mutex mutex_;
    std::condition_variable not_full_;
    std::condition_variable not_empty_;
    
public:
    void push(const T& item) {
        std::unique_lock<std::mutex> lock(mutex_);
        
        // Block until there's space
        not_full_.wait(lock, [this] { return count_ < Capacity; });
        
        buffer_[head_] = item;
        head_ = (head_ + 1) % Capacity;
        ++count_;
        
        lock.unlock();
        not_empty_.notify_one();
    }
    
    T pop() {
        std::unique_lock<std::mutex> lock(mutex_);
        
        // Block until there's data
        not_empty_.wait(lock, [this] { return count_ > 0; });
        
        T item = std::move(buffer_[tail_]);
        tail_ = (tail_ + 1) % Capacity;
        --count_;
        
        lock.unlock();
        not_full_.notify_one();
        
        return item;
    }
};
```

**Pros**: Simple, no data loss  
**Cons**: Can cause cascading slowdowns, potential deadlock in complex systems

#### Strategy 2: Dropping (Load Shedding)

When overwhelmed, strategically drop data:

```cpp
enum class DropPolicy {
    DROP_NEWEST,   // Reject new items when full
    DROP_OLDEST,   // Overwrite oldest items
    DROP_RANDOM,   // Randomly drop to maintain representative sample
    DROP_LOW_PRIORITY  // Drop based on priority
};

template<typename T, size_t Capacity>
class DroppingQueue {
    std::array<T, Capacity> buffer_;
    std::atomic<size_t> head_{0};
    std::atomic<size_t> tail_{0};
    
    std::atomic<uint64_t> dropped_count_{0};
    
public:
    // DROP_NEWEST policy
    bool try_push(const T& item) {
        size_t head = head_.load(std::memory_order_relaxed);
        size_t next = (head + 1) % Capacity;
        
        if (next == tail_.load(std::memory_order_acquire)) {
            // Full - drop this item
            dropped_count_.fetch_add(1, std::memory_order_relaxed);
            return false;
        }
        
        buffer_[head] = item;
        head_.store(next, std::memory_order_release);
        return true;
    }
    
    uint64_t get_dropped_count() const {
        return dropped_count_.load(std::memory_order_relaxed);
    }
};

// DROP_OLDEST policy (ring buffer overwrite)
template<typename T, size_t Capacity>
class OverwritingQueue {
    std::array<T, Capacity> buffer_;
    std::atomic<size_t> write_pos_{0};
    std::atomic<size_t> read_pos_{0};
    
public:
    void push(const T& item) {
        size_t pos = write_pos_.fetch_add(1, std::memory_order_relaxed);
        buffer_[pos % Capacity] = item;
        
        // Advance read position if we've lapped it
        size_t read = read_pos_.load(std::memory_order_relaxed);
        while (pos - read >= Capacity) {
            read_pos_.compare_exchange_weak(read, read + 1,
                                            std::memory_order_relaxed);
        }
    }
    
    bool try_pop(T& item) {
        size_t read = read_pos_.load(std::memory_order_relaxed);
        size_t write = write_pos_.load(std::memory_order_acquire);
        
        if (read >= write) return false;  // Empty
        
        if (read_pos_.compare_exchange_strong(read, read + 1,
                                               std::memory_order_relaxed)) {
            item = buffer_[read % Capacity];
            return true;
        }
        return false;  // Another consumer got it
    }
};
```

#### Strategy 3: Signaling (Reactive Backpressure)

Signal the producer to slow down:

```cpp
class ReactiveProducer {
    std::atomic<bool> should_slow_down_{false};
    std::atomic<int> throttle_percent_{0};  // 0-100
    
public:
    void on_backpressure_signal(int throttle_percent) {
        throttle_percent_.store(throttle_percent, std::memory_order_relaxed);
        should_slow_down_.store(throttle_percent > 0, std::memory_order_release);
    }
    
    void produce() {
        while (running_) {
            generate_data();
            
            if (should_slow_down_.load(std::memory_order_acquire)) {
                // Probabilistic throttling
                int throttle = throttle_percent_.load(std::memory_order_relaxed);
                if (rand() % 100 < throttle) {
                    std::this_thread::sleep_for(std::chrono::milliseconds(1));
                }
            }
        }
    }
};

class BackpressureMonitor {
    BoundedQueue& queue_;
    ReactiveProducer& producer_;
    
public:
    void monitor_loop() {
        while (running_) {
            float utilization = static_cast<float>(queue_.size()) / queue_.capacity();
            
            if (utilization > 0.9) {
                producer_.on_backpressure_signal(80);  // Heavy throttle
            } else if (utilization > 0.7) {
                producer_.on_backpressure_signal(30);  // Light throttle
            } else {
                producer_.on_backpressure_signal(0);   // No throttle
            }
            
            std::this_thread::sleep_for(std::chrono::milliseconds(10));
        }
    }
};
```

#### Strategy 4: Credit-Based Flow Control

Producer can only send when it has "credits" from the consumer:

```cpp
class CreditBasedProducer {
    std::atomic<int64_t> credits_{0};
    
public:
    void receive_credits(int64_t amount) {
        credits_.fetch_add(amount, std::memory_order_release);
    }
    
    bool try_send(const Message& msg, Consumer& consumer) {
        // Try to acquire a credit
        int64_t current = credits_.load(std::memory_order_relaxed);
        while (current > 0) {
            if (credits_.compare_exchange_weak(current, current - 1,
                                                std::memory_order_acquire)) {
                consumer.receive(msg);
                return true;
            }
        }
        return false;  // No credits available
    }
};

class CreditBasedConsumer {
    CreditBasedProducer& producer_;
    static constexpr int64_t CREDIT_BATCH = 100;
    int64_t processed_since_credit_ = 0;
    
public:
    void process(const Message& msg) {
        do_work(msg);
        
        ++processed_since_credit_;
        if (processed_since_credit_ >= CREDIT_BATCH) {
            // Grant more credits to producer
            producer_.receive_credits(CREDIT_BATCH);
            processed_since_credit_ = 0;
        }
    }
};
```

### Choosing a Backpressure Strategy

| Strategy | Data Loss | Latency | Complexity | Use Case |
|----------|-----------|---------|------------|----------|
| Blocking | None | Increases | Low | Reliable processing |
| Drop Newest | Yes (new) | Constant | Low | Real-time data |
| Drop Oldest | Yes (old) | Constant | Low | Latest data matters |
| Signaling | Possible | Variable | Medium | Adaptive systems |
| Credit-based | None | Variable | High | Network protocols |

## 4. Bounded Queues

### Why Bounded Queues?

Unbounded queues are dangerous in production systems:

1. **Memory exhaustion**: Queue grows until OOM
2. **Latency explosion**: Old items wait forever
3. **No backpressure signal**: Producers don't know to slow down
4. **Debugging difficulty**: Problems manifest far from cause

```
Unbounded Queue Failure Mode:
  
  Time: 0s    [__|__|__|__|__]            Queue size: 5
  Time: 10s   [__|__|__|__|__|__|__|__|__] Queue size: 9
  Time: 60s   [... 10,000 items ...]      Queue size: 10,000
  Time: 120s  [... 100,000 items ...]     Queue size: 100,000
  Time: 180s  💥 OUT OF MEMORY            System crashes
  
  The oldest item has been waiting 3 minutes!
```

### Bounded Queue Implementations

#### Fixed-Size Ring Buffer

The most common bounded queue:

```cpp
template<typename T, size_t Capacity>
class RingBuffer {
    static_assert((Capacity & (Capacity - 1)) == 0, 
                  "Capacity must be power of 2 for efficient modulo");
    
    std::array<T, Capacity> buffer_;
    alignas(64) std::atomic<size_t> head_{0};  // Write position
    alignas(64) std::atomic<size_t> tail_{0};  // Read position
    
    static constexpr size_t MASK = Capacity - 1;
    
public:
    bool try_push(const T& item) {
        size_t head = head_.load(std::memory_order_relaxed);
        size_t next = (head + 1) & MASK;
        
        if (next == tail_.load(std::memory_order_acquire)) {
            return false;  // Full
        }
        
        buffer_[head] = item;
        head_.store(next, std::memory_order_release);
        return true;
    }
    
    bool try_pop(T& item) {
        size_t tail = tail_.load(std::memory_order_relaxed);
        
        if (tail == head_.load(std::memory_order_acquire)) {
            return false;  // Empty
        }
        
        item = std::move(buffer_[tail]);
        tail_.store((tail + 1) & MASK, std::memory_order_release);
        return true;
    }
    
    size_t size() const {
        size_t head = head_.load(std::memory_order_relaxed);
        size_t tail = tail_.load(std::memory_order_relaxed);
        return (head - tail) & MASK;
    }
    
    bool empty() const { return size() == 0; }
    bool full() const { return size() == Capacity - 1; }
    static constexpr size_t capacity() { return Capacity - 1; }  // One slot reserved
};
```

#### Time-Bounded Queue

Items expire after a deadline:

```cpp
template<typename T>
class TimeBoundedQueue {
    struct TimedItem {
        T data;
        std::chrono::steady_clock::time_point deadline;
    };
    
    std::deque<TimedItem> queue_;
    std::mutex mutex_;
    std::chrono::milliseconds max_age_;
    
public:
    explicit TimeBoundedQueue(std::chrono::milliseconds max_age) 
        : max_age_(max_age) {}
    
    void push(T item) {
        std::lock_guard<std::mutex> lock(mutex_);
        
        auto now = std::chrono::steady_clock::now();
        
        // Remove expired items from front
        while (!queue_.empty() && queue_.front().deadline < now) {
            queue_.pop_front();
            // Could log/count expired items here
        }
        
        queue_.push_back({std::move(item), now + max_age_});
    }
    
    std::optional<T> try_pop() {
        std::lock_guard<std::mutex> lock(mutex_);
        
        auto now = std::chrono::steady_clock::now();
        
        // Skip expired items
        while (!queue_.empty() && queue_.front().deadline < now) {
            queue_.pop_front();
        }
        
        if (queue_.empty()) return std::nullopt;
        
        T item = std::move(queue_.front().data);
        queue_.pop_front();
        return item;
    }
};
```

#### Size + Time Bounded Queue

Combines both constraints:

```cpp
template<typename T, size_t MaxSize>
class BoundedQueue {
    struct TimedItem {
        T data;
        std::chrono::steady_clock::time_point timestamp;
    };
    
    std::array<TimedItem, MaxSize> buffer_;
    size_t head_ = 0;
    size_t tail_ = 0;
    size_t count_ = 0;
    
    std::mutex mutex_;
    std::chrono::milliseconds max_age_;
    
    std::atomic<uint64_t> size_drops_{0};
    std::atomic<uint64_t> time_drops_{0};
    
public:
    explicit BoundedQueue(std::chrono::milliseconds max_age)
        : max_age_(max_age) {}
    
    bool push(T item) {
        std::lock_guard<std::mutex> lock(mutex_);
        
        auto now = std::chrono::steady_clock::now();
        
        // Evict expired items first
        while (count_ > 0 && 
               now - buffer_[tail_].timestamp > max_age_) {
            tail_ = (tail_ + 1) % MaxSize;
            --count_;
            time_drops_.fetch_add(1, std::memory_order_relaxed);
        }
        
        // If still full, drop oldest
        if (count_ >= MaxSize) {
            tail_ = (tail_ + 1) % MaxSize;
            --count_;
            size_drops_.fetch_add(1, std::memory_order_relaxed);
        }
        
        buffer_[head_] = {std::move(item), now};
        head_ = (head_ + 1) % MaxSize;
        ++count_;
        return true;
    }
    
    struct Stats {
        uint64_t size_drops;
        uint64_t time_drops;
    };
    
    Stats get_stats() const {
        return {
            size_drops_.load(std::memory_order_relaxed),
            time_drops_.load(std::memory_order_relaxed)
        };
    }
};
```

### Choosing Queue Capacity

**Too small:**
- Frequent drops/blocking
- Lost throughput under burst
- Producer starving

**Too large:**
- High memory usage
- High latency under load
- Delayed backpressure signals

**Rule of Thumb:**

```
Capacity = (Max Burst Duration) × (Burst Rate - Drain Rate)

Example:
  - Burst can last: 100ms
  - Burst rate: 10,000 msg/sec
  - Drain rate: 8,000 msg/sec
  - Capacity = 0.1 × (10,000 - 8,000) = 200 messages
  - Add safety margin: 200 × 2 = 400 messages
```

**Dynamic Sizing:**

```cpp
class AdaptiveQueue {
    std::vector<Message> buffer_;
    size_t min_capacity_;
    size_t max_capacity_;
    
    // Metrics for adaptation
    std::atomic<uint64_t> push_attempts_{0};
    std::atomic<uint64_t> push_failures_{0};
    
public:
    void adapt() {
        uint64_t attempts = push_attempts_.exchange(0);
        uint64_t failures = push_failures_.exchange(0);
        
        if (attempts == 0) return;
        
        double failure_rate = static_cast<double>(failures) / attempts;
        
        if (failure_rate > 0.1 && buffer_.capacity() < max_capacity_) {
            // Too many failures - grow
            buffer_.reserve(std::min(buffer_.capacity() * 2, max_capacity_));
        } else if (failure_rate < 0.01 && buffer_.capacity() > min_capacity_) {
            // Barely using capacity - could shrink
            // (shrinking is tricky, usually just leave it)
        }
    }
};
```

## 5. Graceful Overload Behavior

### What is Graceful Degradation?

When a system is overloaded, it should:
1. **Continue operating** (not crash)
2. **Maintain partial service** (serve some requests)
3. **Prioritize important work** (shed low-priority load)
4. **Recover automatically** (when load decreases)

```
Brittle System Under Overload:
  Load:     [normal][normal][OVERLOAD] → 💥 CRASH 💥
  Response:   100%    100%     0%          0%

Graceful System Under Overload:
  Load:     [normal][normal][OVERLOAD][OVERLOAD][normal]
  Response:   100%    100%     60%       50%      100%
                               ↑         ↑
                         Degraded but functional
```

### Overload Detection

Detect overload before it becomes critical:

```cpp
class OverloadDetector {
    // Queue-based metrics
    std::atomic<size_t>& queue_size_;
    size_t queue_capacity_;
    
    // Latency-based metrics
    std::atomic<int64_t> recent_latency_sum_{0};
    std::atomic<int64_t> recent_latency_count_{0};
    int64_t latency_threshold_ns_;
    
    // CPU-based metrics
    std::atomic<double> cpu_utilization_{0.0};
    
public:
    enum class LoadLevel {
        NORMAL,
        ELEVATED,
        HIGH,
        CRITICAL
    };
    
    LoadLevel assess_load() const {
        // Check queue utilization
        float queue_util = static_cast<float>(queue_size_.load()) / queue_capacity_;
        
        // Check latency
        int64_t count = recent_latency_count_.load();
        int64_t avg_latency = count > 0 ? recent_latency_sum_.load() / count : 0;
        float latency_ratio = static_cast<float>(avg_latency) / latency_threshold_ns_;
        
        // Check CPU
        double cpu = cpu_utilization_.load();
        
        // Combine signals
        float load_score = std::max({queue_util, latency_ratio, static_cast<float>(cpu)});
        
        if (load_score > 0.95) return LoadLevel::CRITICAL;
        if (load_score > 0.80) return LoadLevel::HIGH;
        if (load_score > 0.60) return LoadLevel::ELEVATED;
        return LoadLevel::NORMAL;
    }
    
    void record_latency(std::chrono::nanoseconds latency) {
        // Exponential moving average would be better in practice
        recent_latency_sum_.fetch_add(latency.count(), std::memory_order_relaxed);
        recent_latency_count_.fetch_add(1, std::memory_order_relaxed);
    }
};
```

### Load Shedding Strategies

#### Strategy 1: Random Dropping

Simple and fair:

```cpp
class RandomLoadShedder {
    std::atomic<int> drop_percentage_{0};
    std::mt19937 rng_{std::random_device{}()};
    
public:
    void set_drop_rate(int percentage) {
        drop_percentage_.store(std::clamp(percentage, 0, 100));
    }
    
    bool should_process(const Request& req) {
        int threshold = drop_percentage_.load(std::memory_order_relaxed);
        if (threshold == 0) return true;
        if (threshold >= 100) return false;
        
        return (rng_() % 100) >= threshold;
    }
};
```

#### Strategy 2: Priority-Based Shedding

Drop low-priority requests first:

```cpp
class PriorityLoadShedder {

                return req.priority >= Priority::MEDIUM;
                
            case LoadLevel::HIGH:

                return req.priority >= Priority::HIGH;
```

#### Strategy 3: Admission Control

Limit concurrent requests:

```cpp
class AdmissionController {
    std::atomic<int> current_requests_{0};
    std::atomic<int> max_requests_{100};
    
    std::atomic<uint64_t> admitted_{0};
    std::atomic<uint64_t> rejected_{0};
    
public:
    class Ticket {
        AdmissionController* controller_;
        bool valid_;
        
    public:
        Ticket(AdmissionController* c, bool v) : controller_(c), valid_(v) {}
        ~Ticket() { if (valid_) controller_->release(); }
        
        Ticket(Ticket&& other) noexcept 
            : controller_(other.controller_), valid_(other.valid_) {
            other.valid_ = false;
        }
        
        operator bool() const { return valid_; }
    };
    
    Ticket try_admit() {
        int current = current_requests_.load(std::memory_order_relaxed);
        int max = max_requests_.load(std::memory_order_relaxed);
        
        while (current < max) {
            if (current_requests_.compare_exchange_weak(
                    current, current + 1, std::memory_order_acquire)) {
                admitted_.fetch_add(1, std::memory_order_relaxed);
                return Ticket(this, true);
            }
        }
        
        rejected_.fetch_add(1, std::memory_order_relaxed);
        return Ticket(this, false);
    }
    
    void release() {
        current_requests_.fetch_sub(1, std::memory_order_release);
    }
    
    // Adaptive limit adjustment
    void adjust_limit(double latency_ratio) {
        int current_max = max_requests_.load();
        
        if (latency_ratio > 1.5) {
            // Latency too high, reduce concurrency
            max_requests_.store(std::max(10, current_max - 10));
        } else if (latency_ratio < 0.5) {
            // Latency headroom, increase concurrency
            max_requests_.store(std::min(1000, current_max + 10));
        }
    }
};

// Usage
void handle_request(const Request& req) {
    auto ticket = admission_controller.try_admit();
    if (!ticket) {
        send_overload_response(req);
        return;
    }
    
    // Process request - ticket automatically released on scope exit
    process(req);
}
```

### Circuit Breaker Pattern

Prevent cascading failures by failing fast when a dependency is unhealthy:

```cpp
class CircuitBreaker {
public:
    enum class State {
        CLOSED,      // Normal operation
        OPEN,        // Failing fast
        HALF_OPEN    // Testing if recovered
    };
    
private:
    std::atomic<State> state_{State::CLOSED};
    std::atomic<int> failure_count_{0};
    std::atomic<int> success_count_{0};
    
    int failure_threshold_ = 5;
    int success_threshold_ = 3;
    std::chrono::milliseconds timeout_{5000};
    
    std::chrono::steady_clock::time_point last_failure_time_;
    std::mutex mutex_;
    
public:
    template<typename Func>
    auto execute(Func&& operation) -> decltype(operation()) {
        if (!allow_request()) {
            throw std::runtime_error("Circuit breaker is OPEN");
        }
        
        try {
            auto result = operation();
            record_success();
            return result;
        } catch (...) {
            record_failure();
            throw;
        }
    }
    
    bool allow_request() {
        State state = state_.load(std::memory_order_acquire);
        
        switch (state) {
            case State::CLOSED:
                return true;
                
            case State::OPEN: {
                std::lock_guard<std::mutex> lock(mutex_);
                auto now = std::chrono::steady_clock::now();
                if (now - last_failure_time_ > timeout_) {
                    // Try half-open
                    state_.store(State::HALF_OPEN, std::memory_order_release);
                    return true;
                }
                return false;
            }
            
            case State::HALF_OPEN:
                return true;  // Let test request through
        }
        return false;
    }
    
    void record_success() {
        State state = state_.load(std::memory_order_relaxed);
        
        if (state == State::HALF_OPEN) {
            int count = success_count_.fetch_add(1) + 1;
            if (count >= success_threshold_) {
                // Recovered - close the circuit
                state_.store(State::CLOSED, std::memory_order_release);
                failure_count_.store(0, std::memory_order_relaxed);
                success_count_.store(0, std::memory_order_relaxed);
            }
        } else {
            failure_count_.store(0, std::memory_order_relaxed);
        }
    }
    
    void record_failure() {
        std::lock_guard<std::mutex> lock(mutex_);
        
        last_failure_time_ = std::chrono::steady_clock::now();
        int count = failure_count_.fetch_add(1) + 1;
        
        State state = state_.load(std::memory_order_relaxed);
        
        if (state == State::HALF_OPEN) {
            // Test failed - back to open
            state_.store(State::OPEN, std::memory_order_release);
            success_count_.store(0, std::memory_order_relaxed);
        } else if (state == State::CLOSED && count >= failure_threshold_) {
            // Too many failures - open the circuit
            state_.store(State::OPEN, std::memory_order_release);
        }
    }
};
```

### Graceful Degradation Modes

Define explicit degradation modes:

```cpp
class ServiceWithDegradation {
public:
    enum class Mode {
        FULL,           // All features enabled
        REDUCED,        // Non-essential features disabled
        MINIMAL,        // Only core functionality
        MAINTENANCE     // Read-only, no writes
    };
    
private:
    std::atomic<Mode> current_mode_{Mode::FULL};
    OverloadDetector detector_;
    
public:
    void update_mode() {
        auto load = detector_.assess_load();
        
        Mode new_mode;
        switch (load) {
            case LoadLevel::NORMAL:   new_mode = Mode::FULL; break;
            case LoadLevel::ELEVATED: new_mode = Mode::REDUCED; break;
            case LoadLevel::HIGH:     new_mode = Mode::MINIMAL; break;
            case LoadLevel::CRITICAL: new_mode = Mode::MAINTENANCE; break;
        }
        
        Mode old_mode = current_mode_.exchange(new_mode);
        if (old_mode != new_mode) {
            log_mode_change(old_mode, new_mode);
        }
    }
    
    Response handle_request(const Request& req) {
        Mode mode = current_mode_.load(std::memory_order_acquire);
        
        switch (mode) {
            case Mode::FULL:
                return full_processing(req);
                
            case Mode::REDUCED:
                // Skip analytics, recommendations, etc.
                return core_processing(req);
                
            case Mode::MINIMAL:
                // Skip validation, use cached data
                return minimal_processing(req);
                
            case Mode::MAINTENANCE:
                if (req.is_write()) {
                    return Response::service_unavailable();
                }
                return read_only_processing(req);
        }
    }
    
private:
    Response full_processing(const Request& req) {
        validate(req);
        auto data = fetch_fresh_data(req);
        auto recommendations = compute_recommendations(data);
        record_analytics(req, data);
        return Response::ok(data, recommendations);
    }
    
    Response core_processing(const Request& req) {
        validate(req);
        auto data = fetch_fresh_data(req);
        // Skip recommendations and analytics
        return Response::ok(data);
    }
    
    Response minimal_processing(const Request& req) {
        // Skip validation, use cache
        auto data = fetch_cached_data(req);
        return Response::ok(data);
    }
    
    Response read_only_processing(const Request& req) {
        return Response::ok(fetch_cached_data(req));
    }
};
```

### Rate Limiting

Control incoming request rate:

```cpp
class TokenBucketRateLimiter {
    std::atomic<double> tokens_;
    double max_tokens_;
    double refill_rate_;  // tokens per second
    
    std::chrono::steady_clock::time_point last_refill_;
    std::mutex refill_mutex_;
    
public:
    TokenBucketRateLimiter(double max_tokens, double rate)
        : tokens_(max_tokens)
        , max_tokens_(max_tokens)
        , refill_rate_(rate)
        , last_refill_(std::chrono::steady_clock::now())
    {}
    
    bool try_acquire(double tokens_needed = 1.0) {
        refill();
        
        double current = tokens_.load(std::memory_order_relaxed);
        while (current >= tokens_needed) {
            if (tokens_.compare_exchange_weak(current, current - tokens_needed,
                                               std::memory_order_acquire)) {
                return true;
            }
        }
        return false;
    }
    
private:
    void refill() {
        auto now = std::chrono::steady_clock::now();
        
        std::lock_guard<std::mutex> lock(refill_mutex_);
        
        auto elapsed = std::chrono::duration<double>(now - last_refill_).count();
        double new_tokens = tokens_.load() + elapsed * refill_rate_;
        tokens_.store(std::min(new_tokens, max_tokens_), std::memory_order_release);
        last_refill_ = now;
    }
};

class SlidingWindowRateLimiter {
    struct RequestTimestamp {
        std::chrono::steady_clock::time_point time;
    };
    
    std::deque<RequestTimestamp> window_;
    std::mutex mutex_;
    
    size_t max_requests_;
    std::chrono::milliseconds window_size_;
    
public:
    SlidingWindowRateLimiter(size_t max_requests, std::chrono::milliseconds window)
        : max_requests_(max_requests), window_size_(window) {}
    
    bool try_acquire() {
        std::lock_guard<std::mutex> lock(mutex_);
        
        auto now = std::chrono::steady_clock::now();
        auto cutoff = now - window_size_;
        
        // Remove old entries
        while (!window_.empty() && window_.front().time < cutoff) {
            window_.pop_front();
        }
        
        if (window_.size() >= max_requests_) {
            return false;
        }
        
        window_.push_back({now});
        return true;
    }
};
```

### Automatic Recovery

Systems should recover automatically when load decreases:

```cpp
class AutoRecoveringService {
    std::atomic<Mode> mode_{Mode::FULL};
    OverloadDetector detector_;
    
    // Hysteresis to prevent oscillation
    std::chrono::steady_clock::time_point last_mode_change_;
    static constexpr auto MODE_CHANGE_COOLDOWN = std::chrono::seconds(5);
    
public:
    void periodic_check() {
        auto now = std::chrono::steady_clock::now();
        
        // Don't change mode too frequently
        if (now - last_mode_change_ < MODE_CHANGE_COOLDOWN) {
            return;
        }
        
        auto load = detector_.assess_load();
        Mode current = mode_.load();
        Mode target = compute_target_mode(load);
        
        if (target != current) {
            // Degrade immediately, but recover gradually
            if (is_more_degraded(target, current)) {
                // Immediate degradation
                mode_.store(target);
                last_mode_change_ = now;
            } else {
                // Gradual recovery - step up one level
                Mode next = next_better_mode(current);
                mode_.store(next);
                last_mode_change_ = now;
            }
        }
    }
    
private:
    bool is_more_degraded(Mode a, Mode b) {
        return static_cast<int>(a) > static_cast<int>(b);
    }
    
    Mode next_better_mode(Mode current) {
        switch (current) {
            case Mode::MAINTENANCE: return Mode::MINIMAL;
            case Mode::MINIMAL:     return Mode::REDUCED;
            case Mode::REDUCED:     return Mode::FULL;
            case Mode::FULL:        return Mode::FULL;
        }
        return Mode::FULL;
    }
};
```

## Summary

| Concept | Key Takeaway |
|---------|--------------|
| **Deterministic Latency** | Bound worst-case latency, not average. Pre-allocate, lock memory, avoid syscalls. |
| **Priority Scheduling** | Critical work first. Avoid priority inversion with inheritance/ceiling/lock-free. |
| **Backpressure** | Signal overload upstream. Choose: block, drop, signal, or credits. |
| **Bounded Queues** | Always bound by size AND time. Know your capacity math. |
| **Graceful Overload** | Degrade gradually, shed load intelligently, recover automatically. |

### Real-Time System Checklist

1. **Pre-allocate all memory** at startup
2. **Lock pages in RAM** with `mlockall()`
3. **Use real-time scheduler** (`SCHED_FIFO`)
4. **Pin threads to cores** to avoid migration
5. **Avoid locks in critical path** (use lock-free)
6. **Bound all queues** by size and time
7. **Implement backpressure** before you need it
8. **Define degradation modes** explicitly
9. **Monitor latency percentiles** (P99, P99.9)
10. **Test under overload** before production
