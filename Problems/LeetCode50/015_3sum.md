# 015. 3Sum

## Problem Statement (paraphrased, detailed)
Given an integer array `nums`, return all unique triplets `[a, b, c]` such that `a + b + c = 0`. The order of numbers inside a triplet does not matter, and the output should not contain duplicate triplets.

### Examples
- `[-1,0,1,2,-1,-4]` → `[[-1,-1,2], [-1,0,1]]`
- `[0,1,1]` → `[]`
- `[0,0,0]` → `[[0,0,0]]`

## Intuition
After sorting, we can fix one number and then look for two numbers that sum to its negation using the two-pointer technique. Sorting also makes it easy to skip duplicates.

## Approach (Sort + Two Pointers)
1. Sort `nums`.
2. For each index `i` from `0` to `n-1`:
   - If `i > 0` and `nums[i] == nums[i-1]`, skip (avoid duplicate anchors).
   - Set `target = -nums[i]`, and initialize `l = i + 1`, `r = n - 1`.
   - While `l < r`:
     - If `nums[l] + nums[r] == target`, record triplet and move both pointers while skipping duplicates.
     - Else if sum is less than `target`, increment `l`.
     - Else decrement `r`.

## Correctness
- Sorting ensures that duplicates are adjacent, so we can skip duplicate anchors and pointer values to avoid repeated triplets. The two-pointer sweep enumerates all valid pairs for each fixed anchor without missing any.

## Complexity
- Time: `O(n^2)` (dominant two-pointer loop for each `i`).
- Space: `O(1)` extra (excluding the output).

## Edge Cases
- Fewer than 3 elements → return empty list.
- Many zeros or repeated values → de-duplication is critical.

## Variations & Follow-ups
- 3Sum Closest: track the closest sum to a target.
- 4Sum / k-Sum: generalize with recursion and pruning; time grows quickly.
