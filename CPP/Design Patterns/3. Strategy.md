# 1. What Problem Does the Strategy Pattern Solve?

### Core problem

> You have **multiple algorithms / behaviors** for the same task, and you choose between them using `if/else` or `switch`.

This leads to:

* Large conditional blocks
* Hard-to-extend code
* Violates Open/Closed Principle

---

## Example Problem

> Different **compression algorithms** for data before sending.

---

# 2. Without Strategy (Problematic)

```cpp
void sendData(const std::string& algo) {
    if (algo == "none") {
        std::cout << "Sending raw data\n";
    } else if (algo == "gzip") {
        std::cout << "Sending GZIP compressed data\n";
    } else if (algo == "lz4") {
        std::cout << "Sending LZ4 compressed data\n";
    }
}
```

### Problems

* Adding a new algorithm means editing this function
* Business logic mixed with algorithm selection
* Poor testability

---

# 3. Strategy Pattern (Classic Implementation)

## Step 1: Strategy Interface

```cpp
class CompressionStrategy {
public:
    virtual void compress() = 0;
    virtual ~CompressionStrategy() = default;
};
```

---

## Step 2: Concrete Strategies

```cpp
class NoCompression : public CompressionStrategy {
public:
    void compress() override {
        std::cout << "Sending raw data\n";
    }
};

class GzipCompression : public CompressionStrategy {
public:
    void compress() override {
        std::cout << "Sending GZIP compressed data\n";
    }
};

class Lz4Compression : public CompressionStrategy {
public:
    void compress() override {
        std::cout << "Sending LZ4 compressed data\n";
    }
};
```

---

## Step 3: Context (Uses the Strategy)

```cpp
class Sender {
public:
    explicit Sender(std::unique_ptr<CompressionStrategy> strategy)
        : strategy_(std::move(strategy)) {}

    void send() {
        strategy_->compress();
    }

    void setStrategy(std::unique_ptr<CompressionStrategy> strategy) {
        strategy_ = std::move(strategy);
    }

private:
    std::unique_ptr<CompressionStrategy> strategy_;
};
```

---

## Step 4: Usage

```cpp
int main() {
    Sender sender(std::make_unique<GzipCompression>());
    sender.send();

    sender.setStrategy(std::make_unique<Lz4Compression>());
    sender.send();
}
```

---

# 4. What Strategy Pattern Gives You

✔️ Algorithms are **encapsulated**
✔️ Easy to add new strategies
✔️ Runtime behavior change
✔️ No `if/else` explosion
✔️ Code follows Open/Closed Principle

---

# 5. When Strategy Pattern Is Useful

Use it when:

* You have **multiple ways** to do the same thing
* Algorithms change independently of the client
* Behavior must change **at runtime**

### Common examples

* Compression
* Encryption
* Routing policies
* Scheduling algorithms
* Media codecs
* Load-balancing strategies

---

# 6. Strategy vs Factory (Very Common Confusion)

| Factory               | Strategy              |
| --------------------- | --------------------- |
| Creates objects       | Executes behavior     |
| Used at creation time | Used during execution |
| Returns objects       | Operates on data      |

👉 Often used **together**:

* Factory selects which Strategy to use
* Strategy executes the behavior

---

# 7. Modern C++ Strategy (Using `std::function`)

For simpler cases:

```cpp
#include <functional>

class Sender {
public:
    using Strategy = std::function<void()>;

    explicit Sender(Strategy strategy) : strategy_(strategy) {}

    void send() {
        strategy_();
    }

private:
    Strategy strategy_;
};
```

Usage:

```cpp
Sender s([] { std::cout << "Lambda compression\n"; });
s.send();
```

✔️ Lightweight
❌ Less explicit structure

# 8. Common Pitfalls

### ❌ Overengineering

* Don’t create 10 classes for trivial behavior

### ❌ Tight coupling

* Strategy should not depend on Context internals

### ❌ Leaking ownership

* Use smart pointers

# 9. Real-World Telecom Example

```cpp
class RtpPacketizer {
public:
    explicit RtpPacketizer(std::unique_ptr<PacketizationStrategy> s)
        : strategy_(std::move(s)) {}

    void packetize() {
        strategy_->packetize();
    }
};
```

Different strategies:

* Audio packetization
* Video packetization
* DTMF packetization

---

# 10. One-Line Interview Answer

> “The Strategy pattern defines a family of algorithms, encapsulates each one, and makes them interchangeable at runtime without changing the client code.”
