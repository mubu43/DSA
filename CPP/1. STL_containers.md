Below is a **clean, minimal, practical usage guide** for each requested STL container, with **short self-contained examples** and **why/when you’d use them**.
I’ll avoid contrived examples and keep them close to **real systems code**.

---

## 1. `std::vector`

**Dynamic contiguous array (default container)**

### Use when

* You need a resizable list
* Fast iteration & random access
* Cache efficiency matters

### Example

```cpp
#include <vector>
#include <iostream>

int main() {
    std::vector<int> nums;

    nums.push_back(10);
    nums.push_back(20);
    nums.push_back(30);

    // Random access
    std::cout << nums[1] << "\n";   // 20

    // Iteration
    for (int n : nums) {
        std::cout << n << " ";
    }
}
```

### Key points

* `push_back()` → amortized O(1)
* Insertion in middle → O(n)
* Prefer `reserve()` when size is known

---

## 2. `std::queue`

**FIFO (First-In-First-Out) container adapter**

### Use when

* Order matters (tasks, packets, events)
* You only need front/back access

### Example

```cpp
#include <queue>
#include <iostream>

int main() {
    std::queue<int> q;

    q.push(1);
    q.push(2);
    q.push(3);

    while (!q.empty()) {
        std::cout << q.front() << " ";
        q.pop();
    }
}
```

### Key points

* No iteration
* Built on top of `std::deque` by default
* Interface enforces FIFO semantics

---

## 3. `std::stack`

**LIFO (Last-In-First-Out) container adapter**

### Use when

* You need reverse-order processing
* Function calls, undo operations

### Example

```cpp
#include <stack>
#include <iostream>

int main() {
    std::stack<int> s;

    s.push(10);
    s.push(20);
    s.push(30);

    while (!s.empty()) {
        std::cout << s.top() << " ";
        s.pop();
    }
}
```

### Key points

* No iteration
* `top()` gives last inserted element
* Usually backed by `std::deque`

---

## 4. `std::string`

**Dynamic string container**

### Use when

* Text manipulation
* Protocol parsing
* Logging, identifiers

### Example

```cpp
#include <string>
#include <iostream>

int main() {
    std::string msg = "Hello";

    msg += " World";

    std::cout << msg << "\n";
    std::cout << msg.length() << "\n";

    // Access characters
    std::cout << msg[0] << "\n";  // H
}
```

### Key points

* Manages memory automatically
* Supports concatenation, substring, search
* Use `std::string_view` for read-only parsing

---

## 5. `std::unordered_map`

**Hash table (fast lookup, no ordering)**

### Use when

* Key → value lookup
* Order doesn’t matter
* Performance is critical

### Example

```cpp
#include <unordered_map>
#include <iostream>
#include <string>

int main() {
    std::unordered_map<int, std::string> users;

    users[1] = "Alice";
    users[2] = "Bob";

    if (users.find(1) != users.end()) {
        std::cout << users[1] << "\n";
    }

    for (const auto& [id, name] : users) {
        std::cout << id << ": " << name << "\n";
    }
}
```

### Key points

* Average O(1) lookup
* No sorted order
* Hash function matters

---

## 6. `std::map`

**Ordered key-value container (Red-Black Tree)**

### Use when

* Keys must remain sorted
* Range queries are needed
* Deterministic iteration order

### Example

```cpp
#include <map>
#include <iostream>
#include <string>

int main() {
    std::map<int, std::string> users;

    users[3] = "Charlie";
    users[1] = "Alice";
    users[2] = "Bob";

    for (const auto& [id, name] : users) {
        std::cout << id << ": " << name << "\n";
    }
}
```

### Output

```
1: Alice
2: Bob
3: Charlie
```

### Key points

* O(log n) insert/find
* Sorted by key
* Stable iteration order

## Quick Comparison Summary

| Container       | Access Pattern | Ordered | Lookup   | Iteration |
| --------------- | -------------- | ------- | -------- | --------- |
| `vector`        | Random         | No      | O(1)     | Yes       |
| `queue`         | FIFO           | Yes     | N/A      | No        |
| `stack`         | LIFO           | Yes     | N/A      | No        |
| `string`        | Random         | N/A     | O(1)     | Yes       |
| `unordered_map` | Key-based      | No      | O(1) avg | Yes       |
| `map`           | Key-based      | Yes     | O(log n) | Yes       |

---

## Interview Tip (Very Important)

> **Use `vector` by default.**
> Choose `map` or `unordered_map` only when key-based lookup is required.
> Use `queue`/`stack` to enforce behavior, not storage.
