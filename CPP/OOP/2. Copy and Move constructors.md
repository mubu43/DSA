# The Big Picture (First)

For a class that **owns a resource** (heap memory, file, socket):

| Operation            | When it is used                               |
| -------------------- | --------------------------------------------- |
| **Copy constructor** | Creating a new object from an existing one    |
| **Copy assignment**  | Overwriting an existing object with another   |
| **Move constructor** | Creating a new object by *stealing* resources |
| **Move assignment**  | Overwriting by *stealing* resources           |

---

# Example Class: Owning Heap Memory

```cpp
#include <iostream>
#include <cstring>

class Buffer {
public:
    // Constructor
    Buffer(const char* str = "") {
        size_ = std::strlen(str) + 1;
        data_ = new char[size_];
        std::strcpy(data_, str);
        std::cout << "Constructor\n";
    }

    // Destructor
    ~Buffer() {
        delete[] data_;
        std::cout << "Destructor\n";
    }

    // 1️⃣ Copy Constructor
    Buffer(const Buffer& other) {
        size_ = other.size_;
        data_ = new char[size_];
        std::strcpy(data_, other.data_);
        std::cout << "Copy Constructor\n";
    }

    // 2️⃣ Copy Assignment
    Buffer& operator=(const Buffer& other) {
        std::cout << "Copy Assignment\n";

        if (this == &other)
            return *this;

        delete[] data_;  // clean existing resource

        size_ = other.size_;
        data_ = new char[size_];
        std::strcpy(data_, other.data_);

        return *this;
    }

    // 3️⃣ Move Constructor
    Buffer(Buffer&& other) noexcept {
        std::cout << "Move Constructor\n";

        data_ = other.data_;
        size_ = other.size_;

        other.data_ = nullptr;
        other.size_ = 0;
    }

    // 4️⃣ Move Assignment
    Buffer& operator=(Buffer&& other) noexcept {
        std::cout << "Move Assignment\n";

        if (this == &other)
            return *this;

        delete[] data_;  // clean existing resource

        data_ = other.data_;
        size_ = other.size_;

        other.data_ = nullptr;
        other.size_ = 0;

        return *this;
    }

private:
    char* data_{nullptr};
    size_t size_{0};
};
```

---

# 1️⃣ Copy Constructor

### When it’s called

```cpp
Buffer a("Hello");
Buffer b = a;    // copy constructor
```

### What it does

* Creates a **new object**
* Allocates **new memory**
* Copies data

### Why needed

To avoid **double free**:

```cpp
Buffer b = a;  // b must own its own copy
```

---

# 2️⃣ Copy Assignment Operator

### When it’s called

```cpp
Buffer a("Hello");
Buffer b("World");

b = a;   // copy assignment
```

### What it does

* Object already exists
* Cleans up old resource
* Deep-copies from `a`

### Key interview point

* Must handle **self-assignment**
* Must release existing resource

---

# 3️⃣ Move Constructor

### When it’s called

```cpp
Buffer a("Hello");
Buffer b = std::move(a);   // move constructor
```

### What it does

* **Steals** the resource
* No allocation
* Leaves source in a safe empty state

### Why it matters

* Huge performance improvement
* Used in:

  * Returning objects from functions
  * `std::vector` reallocation

---

# 4️⃣ Move Assignment Operator

### When it’s called

```cpp
Buffer a("Hello");
Buffer b("World");

b = std::move(a);   // move assignment
```

### What it does

* Cleans existing resource
* Steals from `a`
* Leaves `a` empty

---

# Seeing It in Action

```cpp
int main() {
    Buffer a("One");
    Buffer b = a;              // Copy Constructor

    Buffer c("Two");
    c = a;                     // Copy Assignment

    Buffer d = std::move(a);   // Move Constructor

    Buffer e("Three");
    e = std::move(b);          // Move Assignment
}
```

### Typical output order

```
Constructor
Copy Constructor
Constructor
Copy Assignment
Move Constructor
Constructor
Move Assignment
Destructor
...
```

# Rule of 5 (VERY IMPORTANT)

If you manage a resource, define:

1. Destructor
2. Copy constructor
3. Copy assignment
4. Move constructor
5. Move assignment

👉 Or better:

> **Use RAII types (`std::vector`, `std::unique_ptr`) and follow the Rule of 0**

---

# Why `noexcept` on move?

```cpp
Buffer(Buffer&&) noexcept;
```

Because:

* STL containers only move if it’s `noexcept`
* Otherwise they fall back to copying

---

# One-Line Interview Answer

> “Copy operations duplicate ownership, while move operations transfer ownership, enabling efficient resource management without unnecessary copying.”
