# 1. What Is Compile-Time Polymorphism?

> **Compile-time polymorphism** means the *decision of which function/code to call is made at compile time*, not at runtime.

There is:

* **No vtable**
* **No virtual dispatch**
* **No runtime overhead**

The compiler generates **different concrete code paths**.

---

# 2. Mechanisms for Compile-Time Polymorphism in C++

C++ supports compile-time polymorphism mainly via:

### 1️⃣ Function overloading

### 2️⃣ Operator overloading

### 3️⃣ Templates (most important)

Let’s focus on **templates**, because that’s where the real power is.

---

# 3. Simple Example: Template-Based Polymorphism

```cpp
template <typename T>
T add(T a, T b) {
    return a + b;
}

int main() {
    add(1, 2);               // T = int
    add(1.5, 2.5);           // T = double
}
```

### What the compiler does internally

The compiler **instantiates** the template:

```cpp
int add<int>(int a, int b);
double add<double>(double a, double b);
```

Each is a **completely separate function**.

---

# 4. How This Works Internally (Step-by-Step)

### Step 1: Template parsing (blueprint)

* Compiler treats templates as **incomplete code**
* No actual code generated yet

---

### Step 2: Template instantiation

When the compiler sees:

```cpp
add(1, 2);
```

It:

* Deduces `T = int`
* Generates a concrete function body

---

### Step 3: Type checking

If `T` does not support required operations:

```cpp
struct A {};
add(A{}, A{});   // compile-time error
```

Error occurs **during instantiation**, not runtime.

---

### Step 4: Code generation

Each instantiation is:

* Type-safe
* Optimizable
* Inlinable

This is why templates can be **faster than virtual functions**.

---

# 5. Example with `std::vector<T>`

```cpp
template <typename T>
void print(const std::vector<T>& v) {
    for (const auto& x : v)
        std::cout << x << " ";
}
```

Used as:

```cpp
print(std::vector<int>{1,2});
print(std::vector<std::string>{"a","b"});
```

### Internally

```cpp
void print(const std::vector<int>&);
void print(const std::vector<std::string>&);
```

Again: **two separate functions**.

---

# 6. Operator Overloading = Compile-Time Polymorphism

```cpp
struct Vec2 {
    float x, y;
};

Vec2 operator+(const Vec2& a, const Vec2& b) {
    return {a.x + b.x, a.y + b.y};
}
```

Resolved at **compile time** based on argument types.

---

# 7. Advanced Example: Static Polymorphism (CRTP)

This is **very important internally**.

```cpp
template <typename Derived>
class Base {
public:
    void interface() {
        static_cast<Derived*>(this)->implementation();
    }
};

class Derived : public Base<Derived> {
public:
    void implementation() {
        std::cout << "Derived implementation\n";
    }
};
```

### What happens

* No virtual functions
* Compiler knows exact type
* Call resolved at compile time

This is called **static polymorphism**.

---

# 8. Why Compile-Time Polymorphism Is Fast

### No vtable

Runtime polymorphism:

```
obj → vptr → vtable → function
```

Compile-time:

```
direct function call
```

### Enables:

* Inlining
* Constant propagation
* Dead code elimination

---

# 9. Templates vs Runtime Polymorphism (Clear Comparison)

| Feature     | Compile-Time        | Runtime       |
| ----------- | ------------------- | ------------- |
| Dispatch    | Compile time        | Runtime       |
| Overhead    | Zero                | vtable lookup |
| Flexibility | Less                | More          |
| Binary size | Larger (code bloat) | Smaller       |
| Type safety | Strong              | Weaker        |

---

# 11. Common Interview Traps

❌ *“Templates are runtime polymorphism”*
✔️ Templates are **compile-time polymorphism**

❌ *“Templates slow down code”*
✔️ They slow **compile time**, not runtime

---

# 12. One-Line Interview Answer

> “Compile-time polymorphism resolves function calls at compile time using templates, operator overloading, or overloading, generating type-specific code with zero runtime overhead.”
