Below is a **practical, minimal, interview-ready guide** to **C++ smart pointers**, showing **when to use which**, **how to use them**, and **common pitfalls**.

I’ll cover:

* `std::unique_ptr`
* `std::shared_ptr`
* `std::weak_ptr`
* `std::make_unique` / `std::make_shared`

---

# 1. `std::unique_ptr`

**Exclusive ownership (most important smart pointer)**

### Use when

* One owner
* Clear lifetime
* Default choice

### Basic usage

```cpp
#include <memory>
#include <iostream>

struct Session {
    int id;
    Session(int id) : id(id) {
        std::cout << "Session created\n";
    }
    ~Session() {
        std::cout << "Session destroyed\n";
    }
};

int main() {
    std::unique_ptr<Session> s = std::make_unique<Session>(1);

    std::cout << s->id << "\n";
}
```

### Ownership transfer (move semantics)

```cpp
std::unique_ptr<Session> createSession() {
    return std::make_unique<Session>(42); // move happens implicitly
}

int main() {
    auto session = createSession();
}
```

### Why it’s preferred

* No reference counting
* Zero overhead vs raw pointer
* Prevents accidental sharing

# 2. `std::shared_ptr`

**Shared ownership via reference counting**

### Use when

* Multiple components need the same object
* Lifetime is not clear
* Object lives until last user releases it

### Basic usage

```cpp
#include <memory>
#include <iostream>

struct Call {
    int id;
    Call(int id) : id(id) {
        std::cout << "Call created\n";
    }
    ~Call() {
        std::cout << "Call destroyed\n";
    }
};

int main() {
    std::shared_ptr<Call> c1 = std::make_shared<Call>(100);

    {
        std::shared_ptr<Call> c2 = c1;
        std::cout << c1.use_count() << "\n";  // 2
    }

    std::cout << c1.use_count() << "\n";      // 1
}
```

### Important

* Uses atomic reference counting
* Slight performance overhead
* Avoid in hot paths unless needed

# 3. `std::weak_ptr`

**Non-owning reference to a `shared_ptr`**

### Why it exists

* Breaks **cyclic references**
* Allows observing without extending lifetime

### Problem: cyclic reference

```cpp
struct A {
    std::shared_ptr<B> b;
};

struct B {
    std::shared_ptr<A> a;  // memory leak!
};
```

### Solution with `weak_ptr`

```cpp
#include <memory>
#include <iostream>

struct B;

struct A {
    std::shared_ptr<B> b;
};

struct B {
    std::weak_ptr<A> a;   // does not increase ref count
};

int main() {
    auto a = std::make_shared<A>();
    auto b = std::make_shared<B>();

    a->b = b;
    b->a = a;
}
```

### Accessing the object

```cpp
if (auto sp = weak.lock()) {
    // safe to use sp
}
```

# 4. Passing smart pointers to functions (VERY IMPORTANT)

### ❌ Wrong (copies shared_ptr unnecessarily)

```cpp
void process(std::shared_ptr<Session> s);
```

### ✅ Correct patterns

#### Read-only access

```cpp
void process(const Session* s);
```

#### Shared ownership needed

```cpp
void process(std::shared_ptr<Session> s);
```

#### Borrowing without ownership

```cpp
void process(const std::shared_ptr<Session>& s);
```

#### Unique ownership transfer

```cpp
void process(std::unique_ptr<Session> s);
```

# 5. Custom Deleter

**When resource is not memory**

### Example: file descriptor

```cpp
#include <memory>
#include <cstdio>

int main() {
    auto fileDeleter = [](FILE* f) {
        if (f) std::fclose(f);
    };

    std::unique_ptr<FILE, decltype(fileDeleter)>
        file(std::fopen("test.txt", "w"), fileDeleter);
}
```

# 6. Smart Pointers vs Raw Pointers (Rule of Thumb)

| Scenario                  | Use                     |
| ------------------------- | ----------------------- |
| Single owner              | `unique_ptr`            |
| Multiple owners           | `shared_ptr`            |
| Observer / back reference | `weak_ptr`              |
| Function parameters       | Raw pointer / reference |
| Legacy API                | Raw pointer             |

---

# 7. Common Interview Pitfalls

### ❌ Creating shared_ptr from raw pointer

```cpp
Foo* f = new Foo();
std::shared_ptr<Foo> p1(f);
std::shared_ptr<Foo> p2(f); // DOUBLE DELETE ❌
```

### ✅ Correct

```cpp
auto p = std::make_shared<Foo>();
```

---

# 8. Real-World Guidance (Systems / Telecom Code)

* Use **`unique_ptr` by default**
* Use **`shared_ptr` for session tables, call contexts**
* Use **`weak_ptr` for back-references**
* Avoid `shared_ptr` in fast packet paths
* Prefer **RAII over manual cleanup**

---
