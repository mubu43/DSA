## Autonomous Systems (AS)

### What is an AS?

The Internet is composed of thousands of **Autonomous Systems (AS)**:
- An AS is a network (or collection of networks) under a **single administrative control**
- Examples: ISPs, large corporations, universities
- Each AS has a unique **AS Number (ASN)**

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    Autonomous Systems Overview                           │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│                          THE INTERNET                                   │
│   ┌─────────────────────────────────────────────────────────────────┐  │
│   │                                                                 │  │
│   │   ┌─────────────┐       ┌─────────────┐       ┌─────────────┐  │  │
│   │   │   AS 100    │       │   AS 200    │       │   AS 300    │  │  │
│   │   │   (AT&T)    │◄─────►│  (Google)   │◄─────►│  (Netflix)  │  │  │
│   │   │             │       │             │       │             │  │  │
│   │   └──────┬──────┘       └──────┬──────┘       └─────────────┘  │  │
│   │          │                     │                               │  │
│   │          │     ┌─────────────┐ │                               │  │
│   │          └────►│   AS 400    │◄┘                               │  │

│   BGP connects ASes together                                            │
│                                                                         │

```

### Types of AS

| Type | Description | Example |
|------|-------------|---------|
| **Stub AS** | Single connection to Internet | Small business |
| **Multihomed AS** | Multiple connections, doesn't transit | Large enterprise |
| **Transit AS** | Carries traffic for other ASes | ISPs |

## Intradomain vs Interdomain Routing

### Two Levels of Routing

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    Routing Hierarchy                                     │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   INTERDOMAIN ROUTING (BGP)                                             │
│   ═══════════════════════════════════════════════════════════════       │
│   Between ASes, Policy-based, Path vector                               │
│                                                                         │
│        AS 100              AS 200              AS 300                   │
│   ┌─────────────┐     ┌─────────────┐     ┌─────────────┐              │
│   │  ┌───────┐  │     │  ┌───────┐  │     │  ┌───────┐  │              │
│   │  │ OSPF  │  │◄═══►│  │ IS-IS │  │◄═══►│  │  RIP  │  │              │
│   │  └───────┘  │ BGP │  └───────┘  │ BGP │  └───────┘  │              │
│   └─────────────┘     └─────────────┘     └─────────────┘              │
│                                                                         │
│   INTRADOMAIN ROUTING (IGP)                                             │
│   ───────────────────────────────────────────────────────────────       │
│   Within AS, Shortest path, Link-state or Distance vector               │
│   Examples: OSPF, IS-IS, RIP                                            │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### Comparison

| Aspect | Intradomain (IGP) | Interdomain (BGP) |
|--------|-------------------|-------------------|
| **Scope** | Within single AS | Between ASes |
| **Goal** | Shortest path | Policy compliance |
| **Metric** | Link cost | AS path, policies |
| **Scale** | Thousands of routers | Millions of prefixes |
| **Protocol** | OSPF, IS-IS, RIP | BGP |
| **Trust** | All routers trusted | Other ASes not trusted |

### Why Different Protocols?

1. **Scale**: BGP must handle the entire Internet routing table (~900K prefixes)
2. **Policy**: ASes have business relationships that affect routing decisions
3. **Autonomy**: Each AS controls its own internal routing
4. **Trust**: Cannot share internal topology with competitors

## BGP Overview

### What is BGP?

**BGP (Border Gateway Protocol)** is THE interdomain routing protocol:
- Currently BGP-4 (since 1995)
- **Path vector** protocol
- Runs over **TCP** (port 179)
- Exchanges **reachability information** (prefixes)

### BGP Basics

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         BGP Operation                                    │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   BGP Routers ("BGP speakers") establish TCP connections                │
│                                                                         │
│   ┌─────────────────┐                    ┌─────────────────┐           │
│   │    AS 100       │                    │    AS 200       │           │
│   │                 │     BGP Session    │                 │           │
│   │   ┌─────────┐   │    (TCP port 179)  │   ┌─────────┐   │           │
│   │   │ Border  │◄══╪════════════════════╪══►│ Border  │   │           │
│   │   │ Router  │   │                    │   │ Router  │   │           │
│   │   └─────────┘   │                    │   └─────────┘   │           │
│   │                 │                    │                 │           │
│   └─────────────────┘                    └─────────────────┘           │
│                                                                         │
│   They exchange:                                                        │
│   • Prefix reachability (e.g., "I can reach 10.1.0.0/16")             │
│   • AS path to reach prefix                                            │
│   • Various attributes (next-hop, local pref, etc.)                   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### BGP Message Types

| Message | Purpose |
|---------|---------|
| **OPEN** | Establish session, negotiate parameters |
| **UPDATE** | Announce new routes or withdraw old ones |
| **KEEPALIVE** | Maintain session (every 60 sec typically) |
| **NOTIFICATION** | Report errors, close session |

## BGP Path Vector Protocol

### How Path Vector Works

Unlike distance vector (just cost) or link-state (full topology), BGP uses **path vector**:
- Each route includes the **full AS path** to the destination
- Example: "To reach 10.1.0.0/16, go through AS 300 → AS 200 → AS 100"

```
┌─────────────────────────────────────────────────────────────────────────┐
│                      Path Vector Example                                 │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   AS 100 originates prefix 10.1.0.0/16                                 │
│                                                                         │
│                    ┌─────────┐                                          │
│                    │ AS 100  │  Announces: 10.1.0.0/16                 │
│                    │         │  Path: [100]                            │
│                    └────┬────┘                                          │
│                         │                                               │
│              ┌──────────┴──────────┐                                   │
│              ▼                     ▼                                   │
│        ┌─────────┐           ┌─────────┐                               │
│        │ AS 200  │           │ AS 300  │                               │
│        │         │           │         │                               │
│        │ Path:   │           │ Path:   │                               │
│        │ [200,100│           │[300,100]│                               │
│        └────┬────┘           └────┬────┘                               │
│             │                     │                                     │
│             └──────────┬──────────┘                                     │
│                        ▼                                               │
│                  ┌─────────┐                                           │
│                  │ AS 400  │  Receives two paths:                      │
│                  │         │  Path 1: [200, 100]                       │
│                  │         │  Path 2: [300, 100]                       │
│                  └─────────┘                                           │
│                                                                         │
│   AS 400 chooses based on path length, policy, etc.                    │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### Why Path Vector?

| Benefit | Explanation |
|---------|-------------|
| **Loop prevention** | If AS sees itself in path, reject route |
| **Policy control** | Filter or prefer based on AS path |
| **Path visibility** | Know exactly which ASes traffic traverses |
| **Scalability** | Only store path, not full topology |

## AS Relationships

### The Business of Routing

ASes have **business relationships** that determine routing policy:

### 1. Customer-Provider

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    Customer-Provider Relationship                        │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│                     ┌─────────────┐                                     │
│                     │  Provider   │  (e.g., AT&T)                      │
│                     │   ($$)      │                                     │
│                     └──────┬──────┘                                     │
│                            │                                            │
│                        $ $ │ $ $    Customer PAYS provider              │
│                            │        for transit                         │
│                            ▼                                            │
│                     ┌─────────────┐                                     │
│                     │  Customer   │  (e.g., Small ISP)                 │
│                     │             │                                     │
│                     └─────────────┘                                     │
│                                                                         │
│   • Customer pays for access to Internet via provider                  │
│   • Provider advertises customer's routes to everyone                  │
│   • Provider carries customer's traffic to anywhere                    │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 2. Peer-to-Peer (Peering)

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        Peering Relationship                              │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│         ┌─────────────┐           ┌─────────────┐                      │
│         │   Peer A    │◄═════════►│   Peer B    │                      │
│         │  (Comcast)  │  Peering  │  (Verizon)  │                      │
│         └─────────────┘   Link    └─────────────┘                      │
│                                                                         │
│   • Usually FREE (settlement-free peering)                             │
│   • Only exchange traffic TO EACH OTHER'S CUSTOMERS                    │
│   • Do NOT provide transit to rest of Internet                         │
│   • Mutually beneficial — avoid paying providers                       │
│                                                                         │
│   Traffic allowed:                                                      │
│   ✓ Comcast customer → Verizon customer                                │
│   ✓ Verizon customer → Comcast customer                                │
│   ✗ Third party → via Comcast → via Verizon → elsewhere               │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

```
│   │ Tier 3  │     │ Tier 3  │     Tier 3 (local/access)               │
│   │ ISP X   │     │ ISP Y   │                                         │
│   └────┬────┘     └─────────┘                                         │
│        │                                                               │
│        │ $                                                             │
│        ▼                                                               │
│   End customers                                                         │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### Export Rules Based on Relationships

| Route learned from | Announce to Customers? | Announce to Peers? | Announce to Providers? |
|--------------------|------------------------|--------------------|-----------------------|
| **Customer** | ✓ Yes | ✓ Yes | ✓ Yes |
| **Peer** | ✓ Yes | ✗ No | ✗ No |
| **Provider** | ✓ Yes | ✗ No | ✗ No |

**Key insight:** Only advertise routes that you **want to carry traffic for** (and get paid for, or it's your own customer).

## BGP Route Selection

### When Multiple Paths Exist

BGP routers often learn **multiple routes** to the same prefix. How to choose?

### BGP Decision Process

Routes are compared using multiple criteria in order:

```
┌─────────────────────────────────────────────────────────────────────────┐
│                      BGP Route Selection Process                         │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   Priority 1: LOCAL PREFERENCE (highest wins)                           │
│   ─────────────────────────────────────────────                        │
│   • Configured by network operator                                      │
│   • Prefer customer routes > peer routes > provider routes             │
│   • Stays within AS, not shared with neighbors                         │
│                                                                         │
│   Priority 2: AS PATH LENGTH (shortest wins)                            │
│   ─────────────────────────────────────────────                        │
│   • Count of ASes in path                                              │
│   • [200, 100] (length 2) beats [300, 250, 100] (length 3)             │
│                                                                         │
│   Priority 3: ORIGIN TYPE                                               │
│   ─────────────────────────────────────────────                        │
│   • IGP > EGP > Incomplete                                              │
│                                                                         │
│   Priority 4: MED (Multi-Exit Discriminator)                           │
│   ─────────────────────────────────────────────                        │
│   • Hint from neighbor about their preference                          │
│   • Lower MED preferred                                                │
│   • Only compared for routes from same AS                              │
│                                                                         │
│   Priority 5: eBGP over iBGP                                           │
│   ─────────────────────────────────────────────                        │
│   • Prefer externally learned routes                                   │
│                                                                         │
│   Priority 6: IGP COST to next-hop (lowest wins)                       │
│   ─────────────────────────────────────────────                        │
│   • "Hot potato" routing — get traffic out of your network fast       │
│                                                                         │
│   Priority 7: ROUTER ID (lowest wins)                                  │
│   ─────────────────────────────────────────────                        │
│   • Tiebreaker                                                         │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### Local Preference Example

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    Local Preference in Action                            │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   AS 400 receives routes to 10.0.0.0/8:                                │
│                                                                         │
│   ┌─────────────┐                         ┌─────────────┐              │
│   │  Provider   │                         │    Peer     │              │
│   │   (we pay)  │                         │   (free)    │              │
│   └──────┬──────┘                         └──────┬──────┘              │
│          │                                       │                      │
│          │ Path: [200,100]                       │ Path: [300,100]     │
│          │ Local Pref: 80                        │ Local Pref: 100     │
│          │                                       │                      │
│          └───────────────┬───────────────────────┘                      │
│                          ▼                                              │
│                    ┌─────────────┐                                      │
│                    │   AS 400    │                                      │
│                    │             │                                      │
│                    │ Chooses peer│  (Local pref 100 > 80)              │
│                    │   route!    │                                      │
│                    └─────────────┘                                      │
│                                                                         │
│   Even though provider path is shorter, local pref WINS                │
│   (prefer free peering over paid transit)                              │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

## eBGP and iBGP

### Two Flavors of BGP

| Type | Full Name | Purpose |
|------|-----------|---------|
| **eBGP** | External BGP | Between different ASes |
| **iBGP** | Internal BGP | Within same AS |

### Why iBGP?

When AS has **multiple border routers**, they need to share BGP routes with each other:

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         eBGP and iBGP                                    │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   AS 200                           AS 300                               │
│   ┌────┐                           ┌────┐                               │
│   │ R1 │                           │ R3 │                               │
│   └──┬─┘                           └──┬─┘                               │
│      │ eBGP                           │ eBGP                            │
│      │                                │                                 │
│   ═══╪════════════════════════════════╪═══                              │
│      │           AS 100               │                                 │
│      │                                │                                 │
│   ┌──▼─┐           iBGP            ┌──▼─┐                               │
│   │ BR1│◄═════════════════════════►│ BR2│   Border Routers              │
│   └────┘                           └────┘                               │
│      │              ▲                 │                                 │
│      │              │                 │                                 │
│      │         ┌────┴────┐            │                                 │
│      └────────►│ Internal│◄───────────┘    iBGP sessions               │
│                │ Routers │                                              │
│                └─────────┘                                              │
│                                                                         │
│   eBGP: Learn routes from other ASes                                   │
│   iBGP: Share those routes within AS                                   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### iBGP Full Mesh Problem

**Rule:** iBGP routes are NOT re-advertised to other iBGP peers (to prevent loops).

**Consequence:** Every iBGP router must peer with every other → **O(n²) sessions**.

**Solutions:**
1. **Route Reflectors** — designated routers re-advertise routes
2. **Confederations** — split AS into sub-ASes

## BGP Policy and Filtering

### Route Filtering

ASes can **filter** which routes they accept or advertise:

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        BGP Route Filtering                               │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   Incoming Filter (from neighbor):                                      │
│   • Reject routes with our own AS in path (loop prevention)            │
│   • Reject private address prefixes                                     │
│   • Reject overly specific prefixes (e.g., longer than /24)            │
│   • Reject known bogons                                                 │
│                                                                         │
│   Outgoing Filter (to neighbor):                                        │
│   • Only advertise customer routes to peers                            │
│   • Don't advertise peer routes to other peers                         │
│   • Prepend AS path to make route less attractive                      │
│   • Set MED to influence neighbor's choice                             │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### AS Path Prepending

Make a route **less attractive** by artificially lengthening the AS path:

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        AS Path Prepending                                │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   AS 100 wants traffic to prefer link via AS 200 over AS 300           │
│                                                                         │
│        ┌─────────┐              ┌─────────┐                            │
│        │ AS 200  │              │ AS 300  │                            │
│        │         │              │         │                            │
│        └────┬────┘              └────┬────┘                            │
│             │                        │                                  │
│   Announce: │                        │ Announce:                       │
│   [100]     │                        │ [100, 100, 100]                 │
│   (normal)  │                        │ (prepended)                     │
│             │                        │                                  │
│             └──────────┬─────────────┘                                  │
│                        │                                                │
│                  ┌─────▼─────┐                                          │
│                  │  AS 100   │                                          │
│                  │           │                                          │
│                  └───────────┘                                          │
│                                                                         │
│   Traffic from the Internet will prefer:                               │
│   Path [200, 100] (length 2) over [300, 100, 100, 100] (length 4)     │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### Traffic Engineering with BGP

| Technique | Controls | Direction |
|-----------|----------|-----------|
| **Local Preference** | Outbound traffic | Which exit to use |
| **AS Path Prepending** | Inbound traffic | Make path less attractive |
| **MED** | Inbound traffic | Hint to specific neighbor |
| **Communities** | Signaling | Tag routes with info |

## Summary

| Concept | Key Points |
|---------|------------|
| **AS** | Autonomous System, single administrative domain, has ASN |
| **IGP vs BGP** | IGP = within AS (OSPF), BGP = between ASes |
| **Path Vector** | Routes include full AS path, prevents loops |
| **Customer-Provider** | Customer pays for transit |
| **Peering** | Free exchange of customer traffic only |
| **Route Selection** | Local pref > AS path length > MED > IGP cost |
| **eBGP** | Between different ASes |
| **iBGP** | Within same AS, needs full mesh or route reflectors |
| **Prepending** | Artificially lengthen path to influence inbound traffic |

### BGP Attributes Summary

| Attribute | Scope | Purpose |
|-----------|-------|---------|
| **AS_PATH** | Transitive | List of ASes, loop prevention |
| **NEXT_HOP** | Transitive | IP of next router |
| **LOCAL_PREF** | Non-transitive | Prefer routes within AS |
| **MED** | Non-transitive | Hint entry point preference |
| **ORIGIN** | Transitive | How route was learned |
| **COMMUNITY** | Optional | Tagging for policy |
