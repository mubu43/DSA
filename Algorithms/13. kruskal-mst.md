# Kruskal's Algorithm for Minimum Spanning Tree

## Overview

Kruskal's algorithm is a **greedy algorithm** that finds the minimum spanning tree (MST) of a weighted undirected graph. It works by sorting all edges by weight and then adding edges to the MST in order of increasing weight, as long as they don't create a cycle.

## Algorithm Description

### Core Concept
A **minimum spanning tree** is a subgraph that:
- Connects all vertices in the graph
- Is a tree (connected and acyclic)
- Has the minimum possible total edge weight

### Algorithm Steps
1. **Sort** all edges by weight in ascending order
2. **Initialize** Union-Find data structure for cycle detection
3. **Iterate** through sorted edges:
   - If edge connects two different components (no cycle)
   - Add edge to MST and union the components
4. **Stop** when MST has (V-1) edges

## Implementation Details

### Union-Find Data Structure
Kruskal's algorithm relies heavily on the Union-Find (Disjoint Set Union) data structure:

```cpp
class UnionFind {
    vector<int> parent, rank;
    
    int find(int x) {
        if (parent[x] != x)
            parent[x] = find(parent[x]);  // Path compression
        return parent[x];
    }
    
    bool unionSets(int x, int y) {
        int rootX = find(x), rootY = find(y);
        if (rootX == rootY) return false;  // Already connected
        
        // Union by rank
        if (rank[rootX] < rank[rootY])
            parent[rootX] = rootY;
        else if (rank[rootX] > rank[rootY])
            parent[rootY] = rootX;
        else {
            parent[rootY] = rootX;
            rank[rootX]++;
        }
        return true;
    }
};
```

### Edge Processing
```cpp
struct Edge {
    int source, destination, weight;
    bool operator<(const Edge& other) const {
        return weight < other.weight;
    }
};

vector<Edge> kruskalMST() {
    sort(edges.begin(), edges.end());  // Sort by weight
    UnionFind uf(numVertices);
    vector<Edge> mst;
    
    for (const auto& edge : edges) {
        if (uf.unionSets(edge.source, edge.destination)) {
            mst.push_back(edge);
            if (mst.size() == numVertices - 1) break;
        }
    }
    return mst;
}
```

## Complexity Analysis

### Time Complexity
- **Sorting edges**: O(E log E)
- **Union-Find operations**: O(E × α(V)) where α is inverse Ackermann function
- **Overall**: **O(E log E)** (dominated by sorting)

### Space Complexity
- **Edge storage**: O(E)
- **Union-Find**: O(V)
- **Overall**: **O(V + E)**

## Key Properties

### Optimality
- **Cut Property**: For any cut of the graph, the minimum weight edge crossing the cut is in some MST
- **Cycle Property**: For any cycle in the graph, the maximum weight edge in the cycle is not in any MST
- **Greedy Choice**: Adding the minimum weight edge that doesn't create a cycle is always safe

### Correctness Proof
1. **Invariant**: At each step, the edges in MST can be extended to form an MST of the entire graph
2. **Greedy Choice**: The next minimum weight edge that doesn't create a cycle is safe to add
3. **Optimal Substructure**: An MST contains MSTs of its subgraphs

## Applications

### Network Design
- **Telecommunications**: Minimum cost to connect all cities with fiber optic cables
- **Transportation**: Cheapest road network connecting all towns
- **Utilities**: Minimum cost electrical grid or water distribution

### Clustering
- **Single-linkage clustering**: Remove the heaviest edges from MST to create clusters
- **Image segmentation**: Group similar pixels using MST-based approaches

### Approximation Algorithms
- **Traveling Salesman Problem**: 2-approximation using MST
- **Steiner Tree**: Approximation for connecting terminals with minimum cost

## Algorithm Variations

### Handling Equal Weights
When multiple edges have the same weight:
- Standard Kruskal's may produce different MSTs
- All are optimal with same total weight
- Tie-breaking rules can ensure deterministic output

### Reverse Delete Algorithm
- Start with all edges, remove heaviest edges that don't disconnect graph
- Dual approach to Kruskal's edge addition
- Same result but different perspective

## Practical Considerations

### When to Use Kruskal's
- **Sparse graphs**: When E << V², sorting dominates but is manageable
- **Pre-sorted edges**: When edges are already sorted or nearly sorted
- **Distributed computing**: Edge-centric approach works well in parallel

### Union-Find Optimizations
- **Path compression**: Makes find() nearly constant time
- **Union by rank**: Keeps trees shallow, improves performance
- **Combined**: Achieves O(α(n)) amortized time per operation

## Comparison with Prim's Algorithm

| Aspect | Kruskal's | Prim's |
|--------|-----------|---------|
| **Approach** | Edge-based, global | Vertex-based, local |
| **Data Structure** | Union-Find | Priority Queue |
| **Time Complexity** | O(E log E) | O(E log V) with binary heap |
| **Space Complexity** | O(V + E) | O(V + E) |
| **Best for** | Sparse graphs | Dense graphs |
| **Parallelization** | Easier | Harder |

## Implementation Tips

### Debugging Strategies
1. **Trace Union-Find state** after each edge consideration
2. **Verify MST properties**: (V-1) edges, connected, acyclic
3. **Check edge sorting** is correct
4. **Validate input graph** is connected

### Performance Optimization
1. **Early termination**: Stop when MST has (V-1) edges
2. **Edge filtering**: Remove obviously unnecessary edges
3. **Union-Find tuning**: Ensure path compression and union by rank
4. **Memory locality**: Consider edge representation for cache efficiency

## Common Mistakes

### Implementation Errors
- **Forgetting path compression** in Union-Find
- **Not handling disconnected graphs** properly
- **Incorrect tie-breaking** for equal weight edges
- **Off-by-one errors** in edge counting

### Conceptual Misunderstandings
- **Thinking it works on directed graphs** (MST is for undirected graphs)
- **Confusing with shortest path algorithms** (different problem)
- **Not understanding why greedy works** (cut/cycle properties)

## Extensions and Variations

### Minimum Bottleneck Spanning Tree
- Minimize the maximum edge weight in spanning tree
- Kruskal's algorithm solves this as a side effect
- Different from MST when costs represent capacity constraints

### Degree-Constrained MST
- Find MST where each vertex has degree ≤ k
- NP-hard in general
- Approximation algorithms exist

### Dynamic MST
- Maintain MST as edges are added/removed
- Link-cut trees enable polylogarithmic updates
- Important for network optimization problems
