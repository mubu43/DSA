# Depth-First Search (DFS) in Directed Graphs - Complete Guide

## Overview
**Depth-First Search (DFS)** in directed graphs is significantly more powerful than in undirected graphs, enabling algorithms like topological sorting, strongly connected components detection, and advanced cycle detection. The directional nature of edges creates new possibilities and complexities.

## Key Differences from Undirected Graphs

### Edge Direction Matters
```
In directed graphs:
- Edge u → v does NOT imply edge v → u
- Path from A to B ≠ Path from B to A
- Reachability is asymmetric
- More complex cycle detection needed
```

### Applications Unique to Directed Graphs
1. **Topological Sorting** - Order vertices respecting dependencies
2. **Strongly Connected Components** - Find maximal sets of mutually reachable vertices
3. **Dependency Analysis** - Project scheduling, course prerequisites
4. **Control Flow Analysis** - Program analysis, compiler optimization

## Core Algorithm (Same as Undirected)

### DFS Strategy
```
1. Start at a given vertex
2. Mark it as visited
3. Recursively visit all unvisited outgoing neighbors
4. Backtrack when no unvisited neighbors remain
```

### Key Implementation Detail
```cpp
// Only follow outgoing edges (direction matters!)
for (int neighbor : adjacencyList[vertex]) {
    if (!visited[neighbor]) {
        dfs(neighbor);
    }
}
```

## Advanced DFS Applications in Directed Graphs

### 1. Topological Sorting

#### Problem
Order vertices such that for every directed edge u → v, vertex u comes before v in the ordering.

#### Algorithm (DFS-based)
```cpp
topologicalSort():
    stack finishStack
    visited = [false] * n
    
    for each vertex v:
        if not visited[v]:
            dfsTopological(v, visited, finishStack)
            
    return reverse(finishStack)

dfsTopological(vertex, visited, stack):
    visited[vertex] = true
    
    for each neighbor in adjacencyList[vertex]:
        if not visited[neighbor]:
            dfsTopological(neighbor, visited, stack)
            
    stack.push(vertex)  // Add after all descendants processed
```

#### Key Insight
**Finish time order** in DFS gives reverse topological order. Vertices finished later have no dependencies on vertices finished earlier.

#### Example
```
Graph: 0→1→3, 0→2→3, 2→4
DFS finish order: 4, 3, 1, 2, 0
Topological order: 0, 2, 1, 4, 3 (or 0, 2, 4, 1, 3)
```

#### Applications
- **Course scheduling** (prerequisites)
- **Build systems** (dependency compilation)
- **Task scheduling** (project management)
- **Deadlock detection** (resource allocation)

### 2. Strongly Connected Components (SCCs)

#### Problem
Find maximal sets of vertices where every vertex is reachable from every other vertex in the same set.

#### Kosaraju's Algorithm
```cpp
findSCCs():
    // Step 1: Get finish times with DFS on original graph
    finishStack = dfsFinishTimes(originalGraph)
    
    // Step 2: Create transpose graph (reverse all edges)
    transposeGraph = createTranspose(originalGraph)
    
    // Step 3: DFS on transpose in reverse finish time order
    sccs = []
    visited = [false] * n
    
    while not finishStack.empty():
        vertex = finishStack.pop()
        if not visited[vertex]:
            scc = dfsComponent(transposeGraph, vertex, visited)
            sccs.add(scc)
            
    return sccs
```

#### Why It Works
1. **First DFS** finds vertices in decreasing finish time order
2. **Transpose** reverses edge directions
3. **Second DFS** on transpose finds SCCs because:
   - Vertices in same SCC remain strongly connected in transpose
   - Cross-SCC edges are reversed, preventing incorrect grouping

#### Example
```
Original: 0→1→2→0, 1→3→4→3
SCCs: {0,1,2}, {3,4}

Transpose: 0←1←2←0, 1←3←4←3
Same SCCs found by Kosaraju's algorithm
```

#### Applications
- **Social network analysis** (mutual influence groups)
- **Web page ranking** (link analysis)
- **Circuit analysis** (feedback loops)
- **Compiler optimization** (loop detection)

### 3. Cycle Detection in Directed Graphs

#### Problem
Detect if directed graph contains a cycle (much more complex than undirected case).

#### Algorithm (Using Recursion Stack)
```cpp
hasCycle():
    visited = [false] * n
    recStack = [false] * n  // Recursion stack tracking
    
    for each vertex v:
        if not visited[v]:
            if dfsCycle(v, visited, recStack):
                return true
    return false

dfsCycle(vertex, visited, recStack):
    visited[vertex] = true
    recStack[vertex] = true
    
    for neighbor in adjacencyList[vertex]:
        if not visited[neighbor]:
            if dfsCycle(neighbor, visited, recStack):
                return true
        else if recStack[neighbor]:
            return true  // Back edge found = cycle
            
    recStack[vertex] = false  // Remove from recursion stack
    return false
```

#### Key Insight
Unlike undirected graphs, we need **recursion stack tracking**. A cycle exists if we find a **back edge** to a vertex currently in the recursion stack.

#### Edge Classification in Directed Graphs
```
1. Tree edges: Part of DFS tree
2. Back edges: To ancestor in DFS tree (indicates cycle)
3. Forward edges: To descendant in DFS tree
4. Cross edges: To vertex in different subtree
```

#### Applications
- **Deadlock detection** (resource allocation graphs)
- **Dependency validation** (circular dependencies)
- **Workflow validation** (process loops)

### 4. Reachability Analysis

#### Problem
Find all vertices reachable from a given source vertex.

#### Algorithm
```cpp
findReachable(source):
    visited = [false] * n
    reachable = []
    dfsReachability(source, visited, reachable)
    return reachable

dfsReachability(vertex, visited, reachable):
    visited[vertex] = true
    reachable.add(vertex)
    
    for neighbor in adjacencyList[vertex]:
        if not visited[neighbor]:
            dfsReachability(neighbor, visited, reachable)
```

#### Applications
- **Security analysis** (privilege escalation paths)
- **Network analysis** (connectivity assessment)
- **Game AI** (reachable states)
- **Social networks** (influence propagation)

### 5. Path Finding in Directed Graphs

#### Key Difference from Undirected
- Path from A to B ≠ Path from B to A
- Must respect edge directions
- Multiple paths may exist with different properties

#### Algorithm (Same DFS approach, different interpretation)
```cpp
findPath(source, destination):
    visited = [false] * n
    path = []
    
    if dfsPath(source, destination, visited, path):
        return path
    return empty_path

dfsPath(current, destination, visited, path):
    visited[current] = true
    path.add(current)
    
    if current == destination:
        return true
        
    for neighbor in adjacencyList[current]:
        if not visited[neighbor]:
            if dfsPath(neighbor, destination, visited, path):
                return true
                
    path.removeLast()  // Backtrack
    return false
```

## Complexity Analysis

### Time Complexity: O(V + E)
- Same as undirected graphs
- Each vertex visited once
- Each directed edge examined once

### Space Complexity: O(V)
- Visited array: O(V)
- Recursion stack: O(V) worst case
- Additional arrays for specific algorithms (SCC, topological sort)

### Algorithm-Specific Complexities
```
Topological Sort: O(V + E)
SCC (Kosaraju): O(V + E) - two DFS passes
Cycle Detection: O(V + E)
Path Finding: O(V + E) worst case
```

## Implementation Patterns

### 1. Basic DFS with Direction Awareness
```cpp
void dfs(int vertex) {
    visited[vertex] = true;
    process(vertex);
    
    // Only follow outgoing edges
    for (int neighbor : outgoingEdges[vertex]) {
        if (!visited[neighbor]) {
            dfs(neighbor);
        }
    }
}
```

### 2. DFS with Timestamps
```cpp
int timer = 0;

void dfsWithTimestamps(int vertex) {
    visited[vertex] = true;
    discoveryTime[vertex] = ++timer;
    
    for (int neighbor : adj[vertex]) {
        if (!visited[neighbor]) {
            dfsWithTimestamps(neighbor);
        }
    }
    
    finishTime[vertex] = ++timer;
}
```

### 3. DFS with Recursion Stack Tracking
```cpp
bool dfsCycleDetection(int vertex) {
    visited[vertex] = true;
    recStack[vertex] = true;
    
    for (int neighbor : adj[vertex]) {
        if (!visited[neighbor]) {
            if (dfsCycleDetection(neighbor)) return true;
        } else if (recStack[neighbor]) {
            return true;  // Cycle found
        }
    }
    
    recStack[vertex] = false;  // Remove from stack
    return false;
}
```

## Graph Representations for Directed Graphs

### Adjacency List (Recommended)
```cpp
vector<vector<int>> adj(n);  // adj[u] contains outgoing neighbors of u
```

**Advantages**:
- Space efficient: O(V + E)
- Fast outgoing neighbor iteration
- Easy to implement transpose

### Adjacency Matrix
```cpp
vector<vector<bool>> adj(n, vector<bool>(n, false));
// adj[u][v] = true means edge u → v exists
```

**Advantages**:
- O(1) edge existence check
- Easy to transpose: transpose[v][u] = adj[u][v]
- Good for dense graphs

## Common Pitfalls

### 1. Confusing Directed with Undirected
```cpp
// WRONG: Adding both directions
addEdge(u, v) {
    adj[u].push_back(v);
    adj[v].push_back(u);  // Wrong for directed graph!
}

// CORRECT: Only one direction
addEdge(u, v) {
    adj[u].push_back(v);  // Only u → v
}
```

### 2. Incorrect Cycle Detection
```cpp
// WRONG: Using undirected graph cycle detection
if (visited[neighbor] && neighbor != parent) {
    return true;  // Wrong for directed graphs!
}

// CORRECT: Using recursion stack
if (recStack[neighbor]) {
    return true;  // Correct for directed graphs
}
```

### 3. Topological Sort on Cyclic Graph
```cpp
// Always check if graph is DAG before topological sort
if (hasCycle()) {
    throw "Cannot perform topological sort on cyclic graph";
}
return topologicalSort();
```

### 4. Forgetting Edge Direction in Path Finding
```cpp
// Remember: path from A to B ≠ path from B to A
// Always respect edge directions in directed graphs
```
