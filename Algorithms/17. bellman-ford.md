# 17. Bellman-Ford Algorithm for Shortest Path Tree

## Overview
Implementation of the **Bellman-Ford algorithm** for computing shortest path trees from a single source vertex in directed graphs with **potentially negative edge weights**. This algorithm can detect negative cycles and works with any weighted graph structure.

## Key Concepts

### Bellman-Ford Algorithm
- **Dynamic programming approach** to single-source shortest paths
- **Handles negative weights** unlike Dijkstra's algorithm
- **Detects negative cycles** in the graph
- **Relaxes all edges** V-1 times to ensure optimality

### Negative Weight Cycles
- A cycle where the sum of edge weights is negative
- Makes shortest paths **undefined** (can be arbitrarily short)
- Bellman-Ford can **detect** these cycles
- Critical for applications like currency arbitrage detection

### Edge Relaxation
- **Core operation**: Update distance if shorter path found
- **Condition**: `distance[u] + weight(u,v) < distance[v]`
- **Guarantee**: After V-1 iterations, shortest paths are found (if no negative cycles)

## Algorithm Steps

### 1. Initialization
- Set distance to source as 0
- Set all other distances to infinity
- Initialize predecessor array for path reconstruction

### 2. Relaxation Phase (V-1 iterations)
- For each iteration (1 to V-1):
  - For each edge (u,v) with weight w:
    - If `distance[u] + w < distance[v]`:
      - Update `distance[v] = distance[u] + w`
      - Set `predecessor[v] = u`

### 3. Negative Cycle Detection
- Run one more iteration over all edges
- If any edge can still be relaxed:
  - **Negative cycle exists**
  - Shortest paths are undefined

## Implementation Highlights

### Core Bellman-Ford Algorithm
```cpp
pair<vector<int>, vector<int>> bellmanFord(int source) {
    vector<int> distance(numVertices, INT_MAX);
    vector<int> predecessor(numVertices, -1);
    
    distance[source] = 0;
    
    // Relax all edges V-1 times
    for (int iteration = 1; iteration < numVertices; iteration++) {
        for (const auto& edge : allEdges) {
            int u = edge.from;
            int v = edge.to;
            int weight = edge.weight;
            
            if (distance[u] != INT_MAX && distance[u] + weight < distance[v]) {
                distance[v] = distance[u] + weight;
                predecessor[v] = u;
            }
        }
    }
    
    // Check for negative cycles
    for (const auto& edge : allEdges) {
        int u = edge.from;
        int v = edge.to;
        int weight = edge.weight;
        
        if (distance[u] != INT_MAX && distance[u] + weight < distance[v]) {
            // Negative cycle detected
            return {{}, {}};  // Return empty vectors
        }
    }
    
    return {distance, predecessor};
}
```

### Edge Relaxation Process
```cpp
// Relaxation condition
if (distance[u] + weight < distance[v]) {
    distance[v] = distance[u] + weight;
    predecessor[v] = u;
    updated = true;
}
```

### Negative Cycle Detection
```cpp
// After V-1 relaxations, check if any edge can still be relaxed
for (const auto& edge : allEdges) {
    if (distance[edge.from] + edge.weight < distance[edge.to]) {
        // Negative cycle exists!
        return false;
    }
}
```

## Complexity Analysis

| Aspect | Complexity | Description |
|--------|------------|-------------|
| **Time** | **O(VE)** | V-1 iterations × E edge relaxations |
| **Space** | **O(V)** | Distance and predecessor arrays |
| **Best Case** | O(E) | Early termination if no updates |
| **Worst Case** | O(VE) | Dense graph, all iterations needed |

### Detailed Complexity Breakdown
- **Initialization**: O(V)
- **Relaxation Phase**: O(VE) - V iterations of E edge checks
- **Cycle Detection**: O(E) - One more pass through all edges
- **Total**: O(V + VE + E) = O(VE)

## Key Features

### ✅ Advantages
- **Negative Weight Handling**: Works with negative edge weights
- **Cycle Detection**: Identifies negative weight cycles
- **Guaranteed Correctness**: Finds shortest paths if they exist
- **Simple Implementation**: Straightforward algorithm logic
- **Any Graph Structure**: Works with any directed graph

### ⚠️ Limitations
- **Slower than Dijkstra**: O(VE) vs O((V+E)logV) for non-negative weights
- **Single Source Only**: Computes paths from one source
- **Undefined with Negative Cycles**: Cannot compute shortest paths if negative cycles exist
- **Dense Graph Performance**: Poor performance on dense graphs

## Implementation Notes

### Early Termination Optimization
```cpp
bool updated = false;
for (const auto& edge : allEdges) {
    if (/* relaxation condition */) {
        // Perform relaxation
        updated = true;
    }
}
if (!updated) break;  // No changes, can terminate early
```

### Negative Cycle Handling
- Return empty vectors to indicate negative cycle
- Could alternatively return cycle vertices
- Applications might need different handling strategies

### Path Reconstruction
- Standard predecessor-based reconstruction
- Only valid if no negative cycles detected
- Infinite paths possible with negative cycles
