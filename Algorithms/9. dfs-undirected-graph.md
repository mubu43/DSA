# Depth-First Search (DFS) in Undirected Graphs - Complete Guide

## Overview
**Depth-First Search (DFS)** is a fundamental graph traversal algorithm that explores as far as possible along each branch before backtracking. In undirected graphs, DFS serves as the foundation for numerous important graph algorithms and applications.

## Core Algorithm Concept

### The DFS Strategy
```
1. Start at a given vertex
2. Mark it as visited
3. Recursively visit all unvisited neighbors
4. Backtrack when no unvisited neighbors remain
5. Continue until all reachable vertices are visited
```

### DFS Traversal Pattern
```
Example Graph:
    0
   / \
  1   2
 /     \
3       4

DFS from 0: 0 → 1 → 3 (backtrack) → 2 → 4
The exact order depends on adjacency list order
```

## Algorithm Implementations

### 1. Recursive DFS (Most Common)
```cpp
void dfs(vertex, visited[]):
    visited[vertex] = true
    process(vertex)                    // Visit vertex
    
    for each neighbor of vertex:
        if not visited[neighbor]:
            dfs(neighbor, visited)     // Recursive call
```

**Characteristics**:
- **Natural implementation** using function call stack
- **Easy to understand** and implement
- **Automatic backtracking** through recursion
- **Stack space**: O(h) where h is maximum depth

### 2. Iterative DFS (Using Explicit Stack)
```cpp
void dfsIterative(startVertex):
    stack.push(startVertex)
    
    while not stack.empty():
        current = stack.pop()
        
        if not visited[current]:
            visited[current] = true
            process(current)
            
            for each neighbor of current:
                if not visited[neighbor]:
                    stack.push(neighbor)
```

**Characteristics**:
- **Explicit stack management**
- **No recursion depth limitations**
- **Slightly different traversal order** than recursive
- **More control** over the traversal process

## Complexity Analysis

### Time Complexity: O(V + E)
- **V**: Number of vertices (each visited exactly once)
- **E**: Number of edges (each edge examined exactly twice in undirected graphs)
- **Why twice?**: Each edge u-v is examined once from u and once from v

### Space Complexity
- **Visited array**: O(V)
- **Recursion stack**: O(h) where h ≤ V (worst case: linear graph)
- **Total**: O(V)

### Detailed Analysis
```
For a graph with V vertices and E edges:
- Visit each vertex: O(V)
- Examine each edge twice: O(2E) = O(E)
- Total: O(V + E)

This is optimal since we must examine each vertex and edge at least once.
```

## DFS Applications in Undirected Graphs

### 1. Connected Components Detection

#### Problem
Find all connected components in an undirected graph.

#### Algorithm
```cpp
findConnectedComponents():
    componentCount = 0
    
    for each vertex v:
        if not visited[v]:
            componentCount++
            dfs(v)                    // Finds one complete component
            
    return componentCount
```

#### Example
```
Graph: 0-1  2-3  4
Components: {0,1}, {2,3}, {4}
Result: 3 connected components
```

**Applications**: 
- Social network analysis (friend groups)
- Network connectivity analysis
- Image processing (connected regions)

### 2. Cycle Detection

#### Problem
Determine if an undirected graph contains a cycle.

#### Algorithm
```cpp
bool hasCycle(vertex, parent, visited[]):
    visited[vertex] = true
    
    for each neighbor of vertex:
        if not visited[neighbor]:
            if hasCycle(neighbor, vertex, visited):
                return true
        else if neighbor != parent:
            return true              // Back edge found = cycle
            
    return false
```

#### Key Insight
In undirected graphs, a **back edge** (edge to already visited vertex that's not the parent) indicates a cycle.

#### Example
```
Graph: 0-1-2-3-0
When visiting 3, we see edge to 0 (already visited, not parent) → Cycle detected
```

### 3. Path Finding

#### Problem
Find a path between two given vertices.

#### Algorithm
```cpp
bool findPath(current, destination, visited[], path[]):
    visited[current] = true
    path.add(current)
    
    if current == destination:
        return true                  // Path found
        
    for each neighbor of current:
        if not visited[neighbor]:
            if findPath(neighbor, destination, visited, path):
                return true
                
    path.removeLast()               // Backtrack
    return false
```

#### Note
DFS finds **a path** but not necessarily the **shortest path**. For shortest paths, use BFS.

### 4. Bipartite Graph Detection

#### Problem
Determine if a graph can be colored with two colors such that no adjacent vertices have the same color.

#### Algorithm
```cpp
bool isBipartite(vertex, color[], currentColor):
    color[vertex] = currentColor
    
    for each neighbor of vertex:
        if color[neighbor] == -1:            // Uncolored
            if not isBipartite(neighbor, color, 1-currentColor):
                return false
        else if color[neighbor] == currentColor:
            return false                     // Same color conflict
            
    return true
```

#### Applications
- Task scheduling (no conflicts)
- Matching problems
- Graph coloring problems

### 5. Bridge Finding (Tarjan's Algorithm)

#### Problem
Find all bridges (cut edges) - edges whose removal increases the number of connected components.

#### Algorithm Concept
```cpp
Use DFS with discovery times and low values:
- discovery[v]: Time when vertex v is first visited
- low[v]: Lowest discovery time reachable from v

Edge u-v is a bridge if: low[v] > discovery[u]
```

#### Applications
- Network reliability analysis
- Finding critical connections
- Circuit design

### 6. Articulation Points (Cut Vertices)

#### Problem
Find vertices whose removal increases the number of connected components.

#### Algorithm Conditions
A vertex u is an articulation point if:
1. **Root of DFS tree** with more than one child, OR
2. **Non-root vertex** with child v such that low[v] ≥ discovery[u]

#### Applications
- Network vulnerability analysis
- Social network key players
- Transportation hub identification

## DFS Tree Properties

### DFS Tree Formation
When DFS traverses a graph, it forms a **DFS tree** (or forest if disconnected):
- **Tree edges**: Edges used in DFS traversal
- **Back edges**: Edges to ancestors in DFS tree
- **Forward/Cross edges**: Don't exist in undirected graphs!

### Edge Classification in Undirected Graphs
```
Only two types of edges exist:
1. Tree edges: Part of DFS tree
2. Back edges: Connect descendant to ancestor

Forward and cross edges don't exist in undirected graphs
because of the undirected nature.
```

## Implementation Variants

### 1. Basic Traversal
```cpp
void dfs(int v) {
    visited[v] = true;
    process(v);
    
    for (int u : adj[v]) {
        if (!visited[u]) {
            dfs(u);
        }
    }
}
```

### 2. With Parent Tracking
```cpp
void dfs(int v, int parent) {
    visited[v] = true;
    
    for (int u : adj[v]) {
        if (u != parent) {                // Avoid going back to parent
            if (!visited[u]) {
                dfs(u, v);
            } else {
                // Back edge found
            }
        }
    }
}
```

### 3. With Timestamps
```cpp
int timer = 0;

void dfs(int v) {
    visited[v] = true;
    discovery[v] = timer++;
    
    for (int u : adj[v]) {
        if (!visited[u]) {
            dfs(u);
        }
    }
    
    finish[v] = timer++;
}
```

## Graph Representations for DFS

### 1. Adjacency List (Recommended)
```cpp
vector<vector<int>> adj(n);
// Space: O(V + E), Iteration: O(degree(v))
```

**Advantages**:
- Space efficient for sparse graphs
- Fast neighbor iteration
- Easy to implement

### 2. Adjacency Matrix
```cpp
vector<vector<bool>> adj(n, vector<bool>(n, false));
// Space: O(V²), Iteration: O(V)
```

**Advantages**:
- O(1) edge existence check
- Good for dense graphs
- Simple implementation

### 3. Edge List
```cpp
vector<pair<int, int>> edges;
// Space: O(E), but inefficient for DFS
```

**Disadvantages**:
- Inefficient for finding neighbors
- Not recommended for DFS implementation

## Performance Considerations

### Best Case Scenarios
- **Sparse graphs**: E << V² (adjacency list shines)
- **Deep graphs**: DFS explores deeply efficiently
- **Tree-like structures**: No redundant edge examinations

### Worst Case Scenarios
- **Dense graphs**: E ≈ V² (consider adjacency matrix)
- **Very deep graphs**: Stack overflow risk with recursion
- **Wide graphs**: BFS might be more appropriate

### Optimization Techniques
```cpp
1. Use iterative version for very deep graphs
2. Pre-sort adjacency lists for consistent ordering
3. Use bit vectors for visited array (memory efficiency)
4. Consider parallel DFS for very large graphs
```

## Comparison with BFS

| Aspect | DFS | BFS |
|--------|-----|-----|
| **Strategy** | Go deep first | Go wide first |
| **Data Structure** | Stack (recursion) | Queue |
| **Space Complexity** | O(h) height | O(w) width |
| **Shortest Path** | No guarantee | Guarantees shortest |
| **Applications** | Connectivity, cycles | Shortest paths, levels |
| **Implementation** | Simpler (recursive) | Slightly more complex |

## Common Pitfalls and Debugging

### 1. Infinite Recursion
```cpp
// WRONG: Forgetting to mark as visited
void dfs(int v) {
    for (int u : adj[v]) {
        dfs(u);                    // Will recurse infinitely!
    }
}

// CORRECT: Mark visited first
void dfs(int v) {
    visited[v] = true;
    for (int u : adj[v]) {
        if (!visited[u]) {
            dfs(u);
        }
    }
}
```

### 2. Parent Confusion in Cycle Detection
```cpp
// WRONG: Not tracking parent
if (visited[neighbor]) {
    return true;                   // False positive!
}

// CORRECT: Check if neighbor is not parent
if (visited[neighbor] && neighbor != parent) {
    return true;                   // Real back edge
}
```

### 3. Stack Overflow
```cpp
// For very deep graphs, use iterative DFS
// or increase stack size if using recursion
```

## Quick Revision Checklist

### 🎯 Core Concepts
1. **DFS explores depth-first** - goes as deep as possible before backtracking
2. **Time complexity O(V + E)** - visits each vertex and examines each edge
3. **Space complexity O(V)** - for visited array and recursion stack
4. **Two implementations** - recursive (simpler) and iterative (no stack limit)
5. **Many applications** - connectivity, cycles, paths, bipartite checking

### 🧠 Key Algorithms
1. **Connected Components**: Run DFS from each unvisited vertex
2. **Cycle Detection**: Look for back edges (to non-parent visited vertex)
3. **Path Finding**: Use DFS with backtracking
4. **Bipartite Check**: Two-color the graph during DFS
5. **Bridges/Cut Vertices**: Use Tarjan's algorithm with discovery times

### 🚨 Common Mistakes
1. **Forgetting to mark visited** - causes infinite recursion
2. **Wrong parent handling** - false cycle detection
3. **Stack overflow** - use iterative for very deep graphs
4. **Edge direction confusion** - remember undirected edges go both ways
5. **Initialization errors** - reset visited array between calls

### ⚡ Implementation Tips
1. **Use adjacency list** for sparse graphs
2. **Mark visited immediately** when entering DFS
3. **Track parent vertex** for cycle detection
4. **Use iterative version** for deep graphs
5. **Consider timestamps** for advanced algorithms

### 🔧 Debugging Strategies
1. **Print traversal order** - verify expected DFS behavior
2. **Visualize small graphs** - trace algorithm by hand
3. **Check edge cases** - single vertex, disconnected components
4. **Use assertions** - verify invariants during execution
5. **Test with known graphs** - trees, cycles, complete graphs
