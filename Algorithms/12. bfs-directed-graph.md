# Breadth-First Search (BFS) in Directed Graphs - Complete Guide

## Overview
**Breadth-First Search (BFS)** in directed graphs maintains its level-by-level exploration strategy while respecting edge directions. This creates powerful applications for analyzing directional relationships, information flow, and asymmetric connectivity patterns.

## Key Differences from Undirected Graphs

### Edge Direction Constraints
```
In directed graphs:
- Can only traverse outgoing edges from current vertex
- Shortest path from A to B ≠ shortest path from B to A
- Reachability is asymmetric: A can reach B doesn't mean B can reach A
- Level structure depends on edge directions
```

### Unique Applications
```
1. Web link analysis (PageRank foundation)
2. Social influence propagation
3. Information flow modeling
4. Dependency chain analysis
5. Communication protocol routing
```

## Core Algorithm (Direction-Aware)

### BFS Strategy for Directed Graphs
```
1. Start at source vertex, add to queue
2. Mark as visited
3. While queue not empty:
   a. Remove vertex from front of queue
   b. Process vertex
   c. Add all unvisited outgoing neighbors to queue
   d. Mark neighbors as visited when adding
4. Continue until queue empty or target found
```

### Key Implementation Detail
```cpp
// Only follow outgoing edges (direction matters!)
for (int neighbor : adjacencyList[current]) {
    if (!visited[neighbor]) {
        visited[neighbor] = true;
        queue.push(neighbor);
    }
}
```

## Advanced BFS Applications in Directed Graphs

### 1. Shortest Path in Directed Graphs

#### Problem
Find shortest path from source to destination respecting edge directions.

#### Algorithm
```cpp
shortestDirectedPath(source, destination):
    queue.push(source)
    visited[source] = true
    parent[source] = -1
    
    while not queue.empty():
        current = queue.front()
        queue.pop()
        
        if current == destination:
            return reconstructPath(parent, destination)
            
        // Only follow outgoing edges
        for neighbor in outgoingEdges[current]:
            if not visited[neighbor]:
                visited[neighbor] = true
                parent[neighbor] = current
                queue.push(neighbor)
                
    return no_path_found
```

#### Key Insight
**Direction matters**: Path A→B may exist while path B→A doesn't. BFS still guarantees shortest path in terms of number of edges.

#### Example
```
Graph: 0→1→3, 0→2→3
Shortest path 0→3: 0→2→3 (length 2)
No path exists from 3→0 (direction constraint)
```

#### Applications
- **Web crawling**: Following hyperlinks
- **Social networks**: Information propagation paths
- **Transportation**: One-way street navigation
- **Communication**: Message routing in networks

### 2. Reachability Analysis

#### Algorithm

findReachableVertices(source):

### 3. Multi-Source BFS

#### Problem
Find shortest distances from any of multiple sources, respecting directions.

#### Algorithm
```cpp
multiSourceBFS(sources):
    queue = empty
    distance = [-1] * n
    
    // Initialize all sources
    for source in sources:
        queue.push(source)
        distance[source] = 0
        
    while not queue.empty():
        current = queue.front()
        queue.pop()
        
        // Only follow outgoing edges
        for neighbor in outgoingEdges[current]:
            if distance[neighbor] == -1:  // Not visited
                distance[neighbor] = distance[current] + 1
                queue.push(neighbor)
                
    return distance
```

#### Applications
- **Facility location**: Find nearest service center
- **Epidemic modeling**: Spread from multiple sources
- **Fire/flood simulation**: Propagation from multiple origins
- **Network broadcast**: Message spread from multiple senders

### 4. Level-Order Analysis in Directed Graphs

#### Problem
Analyze vertices at each level of directed reachability from source.

#### Algorithm
```cpp
levelOrderAnalysis(source):
    queue.push(source)
    visited[source] = true
    levels = []
    
    while not queue.empty():
        levelSize = queue.size()
        currentLevel = []
        
        for i = 0 to levelSize-1:
            current = queue.front()
            queue.pop()
            currentLevel.add(current)
            
            // Only follow outgoing edges
            for neighbor in outgoingEdges[current]:
                if not visited[neighbor]:
                    visited[neighbor] = true
                    queue.push(neighbor)
                    
        levels.add(currentLevel)
        
    return levels
```

#### Applications
- **Organizational hierarchy**: Management levels
- **Information cascade**: Influence levels in social networks
- **Dependency analysis**: Build order levels
- **Game AI**: Decision tree levels

## Complexity Analysis

### Time Complexity: O(V + E)
- Each vertex visited at most once
- Each directed edge examined at most once
- Same complexity as undirected BFS

### Space Complexity: O(V)
- Visited array: O(V)
- Queue space: O(V) worst case
- Parent tracking: O(V)

### Algorithm-Specific Complexities
```
Shortest Path: O(V + E)
Reachability: O(V + E)
Multi-source BFS: O(V + E)
Level-order: O(V + E)
Weak Components: O(V + E)
Bidirectional BFS: O(V + E) but faster in practice
```

## Implementation Patterns

### 1. Basic Directed BFS
```cpp
void directedBFS(int source) {
    queue<int> q;
    vector<bool> visited(n, false);
    
    q.push(source);
    visited[source] = true;
    
    while (!q.empty()) {
        int current = q.front();
        q.pop();
        process(current);
        
        // Only follow outgoing edges
        for (int neighbor : outgoingEdges[current]) {
            if (!visited[neighbor]) {
                visited[neighbor] = true;
                q.push(neighbor);
            }
        }
    }
}
```

## Directed vs Undirected BFS Comparison

| Aspect | Directed BFS | Undirected BFS |
|--------|--------------|----------------|
| **Edge Traversal** | Only outgoing edges | Both directions |
| **Reachability** | Asymmetric (A→B ≠ B→A) | Symmetric (A↔B) |
| **Shortest Path** | Directional constraint | Bidirectional |
| **Applications** | Flow, influence, dependency | Distance, connectivity |
| **Complexity** | Same O(V + E) | Same O(V + E) |
| **Implementation** | Direction-aware | Direction-agnostic |

## Common Pitfalls

### 1. Ignoring Edge Direction
```cpp
// WRONG: Treating directed as undirected
for (int neighbor : adjacencyList[current]) {
    // This follows outgoing edges only - correct for directed
}

// Don't add reverse edges unless graph is actually bidirectional
adj[u].push_back(v);
adj[v].push_back(u);  // Wrong for directed graph!
```

### 2. Incorrect Path Reconstruction
```cpp
// Remember: path A→B doesn't guarantee path B→A
if (pathExists(A, B)) {
    // Don't assume pathExists(B, A) is also true
}
```

### 3. Bidirectional BFS Implementation
```cpp
// Need reverse graph for backward search
// Can't just reverse the search direction
vector<vector<int>> reverseAdj(n);
for (int u = 0; u < n; u++) {
    for (int v : adj[u]) {
        reverseAdj[v].push_back(u);  // Reverse edge u→v to v→u
    }
}
```

### 4. Multi-Source Initialization
```cpp
// Initialize ALL sources before starting BFS
for (int source : sources) {
    distance[source] = 0;
    queue.push(source);
}
// Then start BFS - don't initialize sources during BFS
```

### 🧠 Key Algorithms
1. **Directed shortest path**: BFS with parent tracking
2. **Reachability analysis**: BFS to find all reachable vertices
3. **Multi-source BFS**: Simultaneous expansion from multiple sources
4. **Level-order analysis**: Process vertices by directed distance
5. **Weak connectivity**: Treat as undirected for components

### 🚨 Common Mistakes
1. **Adding bidirectional edges** when graph is directed
2. **Ignoring edge constraints** in pathfinding
3. **Assuming symmetric reachability** (A→B implies B→A)
4. **Wrong reverse graph** construction for bidirectional BFS
5. **Incorrect multi-source initialization** order

### ⚡ Implementation Tips
1. **Use adjacency list** for outgoing edges only
2. **Mark visited when adding** to queue, not when processing
3. **Track parents correctly** for path reconstruction
4. **Consider bidirectional BFS** for long paths
5. **Precompute reverse graph** when needed

1. **Visualize edge directions** clearly
