# 15. Shortest Path Tree (SPT) in Edge-Weighted Directed Graph

## Overview
Implementation of **Dijkstra's algorithm** for computing the shortest path tree from a given source vertex in a directed graph with **non-negative edge weights**. This algorithm efficiently finds the shortest paths from a single source to all other vertices.

## Key Concepts

### Shortest Path Tree (SPT)
- A tree rooted at the source vertex
- Contains shortest paths from source to all reachable vertices
- For a graph with V vertices, SPT has at most V-1 edges
- Each vertex appears exactly once in the tree

### Dijkstra's Algorithm
- **Greedy algorithm** that maintains a set of vertices with known shortest distances
- Uses a **priority queue** (min-heap) for efficient vertex selection
- **Relaxation**: Updates distance if a shorter path is found
- **Non-negative weights only**: Cannot handle negative edge weights

## Algorithm Steps

1. **Initialize**: Set distance to source as 0, all others as infinity
2. **Priority Queue**: Insert all vertices with their distances
3. **Extract Minimum**: Get vertex with smallest distance
4. **Relax Edges**: Update distances to adjacent vertices
5. **Repeat**: Until all reachable vertices are processed

## Implementation Highlights

### Core Data Structures
```cpp
std::vector<int> distance;      // Shortest distances
std::vector<int> predecessor;   // Path reconstruction
std::priority_queue<pair<int,int>> pq;  // Min-heap
```

### Relaxation Process
```cpp
if (distance[u] + weight < distance[v]) {
    distance[v] = distance[u] + weight;
    predecessor[v] = u;
    pq.push({distance[v], v});
}
```

## Complexity Analysis

| Aspect | Complexity |
|--------|------------|
| **Time** | O((V + E) log V) |
| **Space** | O(V) |
| **Best Case** | O(V log V) - sparse graph |
| **Worst Case** | O(E log V) - dense graph |

Where:
- V = number of vertices
- E = number of edges

## Key Features

### ✅ Advantages
- **Optimal**: Finds shortest paths guaranteed
- **Efficient**: Good performance with priority queue
- **Versatile**: Works for both directed and undirected graphs
- **SPT Construction**: Builds complete shortest path tree

### ⚠️ Limitations
- **Non-negative weights only**: Cannot handle negative edges
- **Single source**: Computes paths from one source only
- **Memory usage**: Requires O(V) additional space

## Performance Characteristics

### Priority Queue Impact
- **Binary Heap**: O(log V) per operation
- **Fibonacci Heap**: O(1) amortized decrease-key
- **Array**: O(V) for dense graphs

### Graph Density Effects
- **Sparse (E ≈ V)**: O(V log V)
- **Dense (E ≈ V²)**: O(V² log V)

## Implementation Notes

### Path Reconstruction
- Use predecessor array to trace back paths
- Start from target, follow predecessors to source
- Reverse the path for source-to-target order

### Edge Cases
- **Disconnected vertices**: Distance remains infinity
- **Self-loops**: Handled correctly with non-negative weights
- **Source vertex**: Distance is always 0
