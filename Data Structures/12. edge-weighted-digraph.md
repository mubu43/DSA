# Edge-Weighted Directed Graph (Digraph) Data Structure

## Overview

An **edge-weighted directed graph** (also called edge-weighted digraph) is a directed graph where each edge has both a specific direction (from source to destination) and an associated numerical weight. This combines the asymmetric relationship properties of directed graphs with the cost/distance information of weighted edges, making it essential for advanced graph algorithms.

## Key Concepts

### What is an Edge-Weighted Digraph?

An edge-weighted digraph extends a simple directed graph by assigning numerical weights to directed edges. Each edge has:
- **Direction**: From source vertex to destination vertex
- **Weight**: Numerical value representing cost, distance, capacity, etc.
- **Asymmetry**: Edge from A to B is different from edge from B to A

### Directed Edge Representation

Each directed edge in our implementation contains:
```cpp
struct DirectedEdge {
    int from;      // Source vertex
    int to;        // Destination vertex  
    double weight; // Edge weight/cost
}
```

### Key Differences from Undirected Weighted Graphs

| Aspect | Undirected Weighted | Directed Weighted |
|--------|-------------------|------------------|
| **Edge Direction** | Bidirectional | Unidirectional |
| **Storage** | Edge stored twice | Edge stored once per direction |
| **Relationships** | Symmetric | Asymmetric |
| **Degree** | Single degree | In-degree + Out-degree |
| **Applications** | Mutual connections | Hierarchical/flow relationships |

## Data Structure Implementation

### Dual Adjacency Lists

The implementation uses two adjacency lists for efficiency:

1. **Forward Adjacency List**: Stores outgoing edges for each vertex
2. **Reverse Adjacency List**: Stores incoming edges for each vertex

This dual structure enables:
- **O(1)** access to outgoing edges (successors)
- **O(1)** access to incoming edges (predecessors)
- **Efficient** in-degree and out-degree calculations

### Key Operations

| Operation | Description | Time Complexity |
|-----------|-------------|-----------------|
| `addEdge(source, dest, weight)` | Add weighted directed edge | O(1) |
| `removeEdge(source, dest)` | Remove directed edge | O(out-degree(source)) |
| `hasEdge(source, dest)` | Check if directed edge exists | O(out-degree(source)) |
| `getEdgeWeight(source, dest)` | Get weight of specific edge | O(out-degree(source)) |
| `getOutgoingEdges(v)` | Get all outgoing edges | O(out-degree(v)) |
| `getIncomingEdges(v)` | Get all incoming edges | O(in-degree(v)) |
| `getSuccessorsWithWeights(v)` | Get successors and weights | O(out-degree(v)) |
| `getPredecessorsWithWeights(v)` | Get predecessors and weights | O(in-degree(v)) |

### Vertex Classification

Vertices are classified based on their connectivity:

- **Source Vertices**: In-degree = 0, Out-degree > 0 (starting points)
- **Sink Vertices**: Out-degree = 0, In-degree > 0 (ending points)
- **Isolated Vertices**: In-degree = 0, Out-degree = 0 (disconnected)
- **Internal Vertices**: In-degree > 0, Out-degree > 0 (intermediate nodes)

### Memory Complexity

- **Space**: O(V + E) where V is vertices and E is directed edges
- Each directed edge is stored twice (forward and reverse adjacency lists)

## Algorithm Applications

Edge-weighted digraphs are fundamental for:

### Shortest Path Algorithms
- **Dijkstra's Algorithm**: Non-negative weights in directed graphs
- **Bellman-Ford Algorithm**: Handles negative weights, detects cycles
- **Topological Sort + Relaxation**: Shortest paths in DAGs

### Network Flow Algorithms
- **Maximum Flow**: Edge capacities as weights
- **Minimum Cost Flow**: Combining flow constraints with costs
- **Assignment Problems**: Bipartite matching with costs

### Graph Analysis
- **Strongly Connected Components**: Finding cycles in directed graphs
- **Topological Ordering**: DAG vertex ordering
- **Critical Path Method**: Project scheduling with dependencies

## Implementation Features

### Directional Operations
- **Outgoing Edges**: All edges leaving a vertex
- **Incoming Edges**: All edges entering a vertex
- **Successors**: Vertices reachable in one step
- **Predecessors**: Vertices that can reach current vertex in one step

### Degree Analysis
- **Out-Degree**: Number of outgoing edges
- **In-Degree**: Number of incoming edges
- **Degree Difference**: Out-degree minus in-degree

### Edge Management
- **Direction Validation**: Ensures proper source-to-destination flow
- **Weight Updates**: Modify existing edge weights
- **Duplicate Prevention**: Checks for existing directed edges

### Graph Analysis
- **Vertex Classification**: Identify sources, sinks, isolated vertices
- **Weight Statistics**: Min/max/average edge weights
- **Structural Properties**: Cycle detection capabilities

## Performance Considerations

### Advantages
- **Directional Efficiency**: Fast access to both incoming and outgoing edges
- **Algorithm Ready**: Direct support for directed graph algorithms
- **Flexible Weights**: Supports various weight types and ranges
- **Comprehensive Analysis**: Rich vertex and edge information

### Trade-offs
- **Memory Overhead**: Dual adjacency lists require more storage
- **Complexity**: More complex than undirected graphs
- **Maintenance Cost**: Updates require modifying both adjacency lists

## Best Practices

### Design Considerations
1. **Weight Semantics**: Clearly define what weights represent
2. **Direction Meaning**: Ensure edge directions match real-world relationships
3. **Negative Weights**: Consider implications for algorithms
4. **Scale Balance**: Keep weights in appropriate ranges

### Implementation Tips
1. **Dual Storage**: Maintain both forward and reverse adjacency lists
2. **Validation**: Always validate vertex indices and edge directions
3. **Consistency**: Ensure edge updates maintain both adjacency lists
4. **Performance**: Use efficient data structures for frequent operations

### Algorithm Integration
1. **Dijkstra's**: Requires non-negative weights
2. **Bellman-Ford**: Handles negative weights, detects negative cycles
3. **Topological Sort**: Requires DAG (no cycles)
4. **Flow Algorithms**: Treat weights as capacities

This edge-weighted digraph implementation provides a comprehensive foundation for advanced graph algorithms and real-world applications where both direction and cost matter, making it an essential data structure for optimization problems in computer science and engineering.
