# Edge-Weighted Graph Data Structure

## Overview

An **edge-weighted graph** is a graph where each edge has an associated numerical weight (also called cost or distance). This is a fundamental data structure used in many important graph algorithms such as shortest path algorithms (Dijkstra's, Bellman-Ford) and minimum spanning tree algorithms (Kruskal's, Prim's).

## Key Concepts

### What is an Edge-Weighted Graph?

Unlike a simple graph where edges only represent connections, an edge-weighted graph assigns a numerical value to each edge. This weight typically represents:
- **Distance** between locations
- **Cost** of traveling between points
- **Time** required for traversal
- **Capacity** of a connection
- **Strength** of a relationship

### Edge Representation

Each edge in our implementation is represented by an `Edge` structure containing:
```cpp
struct Edge {
    int from;      // Source vertex
    int to;        // Destination vertex  
    double weight; // Edge weight/cost
}
```

### Undirected vs Directed Edge-Weighted Graphs

- **Undirected**: Each edge can be traversed in both directions with the same weight
- **Directed**: Each edge has a specific direction and weight (not covered in this implementation)

## Data Structure Implementation

### Core Components

1. **Adjacency List**: Each vertex maintains a list of `Edge` objects
2. **Edge Object**: Contains source, destination, and weight information
3. **Vertex Operations**: Add/remove edges, query neighbors with weights
4. **Graph Operations**: Calculate total weight, find min/max weight edges

### Key Operations

| Operation | Description | Time Complexity |
|-----------|-------------|-----------------|
| `addEdge(v1, v2, weight)` | Add weighted edge between vertices | O(1) |
| `removeEdge(v1, v2)` | Remove edge between vertices | O(degree(v)) |
| `hasEdge(v1, v2)` | Check if edge exists | O(degree(v)) |
| `getEdgeWeight(v1, v2)` | Get weight of specific edge | O(degree(v)) |
| `getNeighborsWithWeights(v)` | Get neighbors and their weights | O(degree(v)) |
| `getAllEdges()` | Get all edges in graph | O(V + E) |
| `getTotalWeight()` | Sum of all edge weights | O(E) |

### Memory Complexity

- **Space**: O(V + E) where V is vertices and E is edges
- Each edge is stored twice (once for each endpoint in undirected graph)

## Algorithm Applications

Edge-weighted graphs are essential for:

### Shortest Path Algorithms
- **Dijkstra's Algorithm**: Non-negative weights
- **Bellman-Ford Algorithm**: Handles negative weights
- **Floyd-Warshall Algorithm**: All-pairs shortest paths

### Minimum Spanning Tree
- **Kruskal's Algorithm**: Edge-centric approach
- **Prim's Algorithm**: Vertex-centric approach

### Network Flow
- **Maximum Flow**: Edge capacities as weights
- **Minimum Cost Flow**: Combining flow and cost

## Implementation Features

### Edge Management
- **Duplicate Prevention**: Checks for existing edges
- **Weight Updates**: Modify existing edge weights
- **Validation**: Prevents self-loops and invalid vertices

### Graph Analysis
- **Statistics**: Min/max/average edge weights
- **Degree Analysis**: Vertex connectivity with weights
- **Total Weight**: Sum of all edge weights

### Visualization Support
- **Adjacency Display**: Shows neighbors with weights
- **Edge Listing**: Sorted by weight for analysis
- **Pattern Demonstration**: Various graph structures

## Performance Considerations

### Advantages
- **Flexibility**: Supports various weight types (distance, cost, etc.)
- **Algorithm Ready**: Direct input for weighted graph algorithms
- **Efficient Queries**: Fast neighbor and weight lookups

### Trade-offs
- **Memory Overhead**: Additional weight storage per edge
- **Complexity**: More complex than unweighted graphs
- **Validation Costs**: Weight-related checks and operations

## Comparison with Unweighted Graphs

| Aspect | Unweighted Graph | Edge-Weighted Graph |
|--------|------------------|---------------------|
| **Edge Info** | Connection only | Connection + weight |
| **Memory** | Lower | Higher (weight storage) |
| **Algorithms** | Basic traversal | Optimization algorithms |
| **Applications** | Simple relationships | Cost/distance optimization |
| **Complexity** | Simpler | More sophisticated |

## Best Practices

### Design Considerations
1. **Weight Type**: Choose appropriate data type (int vs double)
2. **Negative Weights**: Consider if negative weights are meaningful
3. **Weight Scale**: Ensure weights are in appropriate range
4. **Precision**: Balance between accuracy and performance

### Implementation Tips
1. **Validation**: Always validate vertex indices and weights
2. **Consistency**: Maintain weight consistency in undirected graphs
3. **Edge Cases**: Handle zero weights and infinite weights appropriately
4. **Performance**: Use efficient data structures for frequent operations
