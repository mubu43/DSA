# Binary Search Tree (BST) - Complete Guide

## Overview
A **Binary Search Tree** is a hierarchical data structure that maintains elements in sorted order, enabling efficient searching, insertion, and deletion operations. It's a fundamental data structure that forms the basis for many advanced tree structures.

## BST Property (The Golden Rule)
For any node N in a BST:
- **All nodes in the left subtree** have values **< N.value**
- **All nodes in the right subtree** have values **> N.value**  
- **Both subtrees** are also valid BSTs

```
Example BST:
        50
       /  \
      30   70
     / |   | \
    20 40 60 80
```

## Key Properties
- **Time Complexity (Average)**: O(log n) for search, insert, delete
- **Time Complexity (Worst)**: O(n) when tree becomes skewed
- **Space Complexity**: O(n) for storing n nodes + O(log n) recursive stack
- **Ordering**: Inorder traversal gives sorted sequence
- **No Duplicates**: Traditional BSTs don't allow duplicate values

## Core Operations

### 1. Search Operation

#### Algorithm
```cpp
bool search(node, target):
    if node == null:
        return false
    
    if target == node.data:
        return true
    elif target < node.data:
        return search(node.left, target)
    else:
        return search(node.right, target)
```

#### Search Path Example
```
Search for 40 in tree:
50 → 30 → 40 ✓ Found!

Search for 25 in tree:
50 → 30 → 20 → null ✗ Not found

Time: O(log n) average, O(n) worst case
```

### 2. Insertion Operation

#### Algorithm
```cpp
insert(node, value):
    if node == null:
        return new Node(value)
    
    if value < node.data:
        node.left = insert(node.left, value)
    elif value > node.data:
        node.right = insert(node.right, value)
    // If value == node.data, don't insert (no duplicates)
    
    return node
```

#### Insertion Example
```
Insert 35 into tree:
        50
       /  \
      30   70
     / |   | \
    20 40 60 80

Step 1: 35 < 50, go left
Step 2: 35 > 30, go right  
Step 3: 35 < 40, go left
Step 4: null position found, insert 35

Result:
        50
       /  \
      30   70
     / |   | \
    20 40 60 80
      /
     35
```

### 3. Deletion Operation (Most Complex)

Deletion has **three cases** based on the node's children:

#### Case 1: Node with No Children (Leaf Node)
```cpp
// Simply remove the node
delete node
return null
```

#### Case 2: Node with One Child
```cpp
// Replace node with its child
if node.left == null:
    temp = node.right
    delete node
    return temp
else:
    temp = node.left
    delete node
    return temp
```

#### Case 3: Node with Two Children (Complex)
```cpp
// Find inorder successor (smallest in right subtree)
successor = findMin(node.right)

// Replace node's data with successor's data
node.data = successor.data

// Delete the successor (which has at most one child)
node.right = delete(node.right, successor.data)
```

#### Deletion Example - Two Children
```
Delete 30 from tree:
        50
       /  \
     [30]  70
     / |   | \
    20 40 60 80

Step 1: Find inorder successor of 30 → 40 (smallest in right subtree)
Step 2: Replace 30's data with 40's data
Step 3: Delete original 40 node

Result:
        50
       /  \
      40   70
     /     | \
    20    60 80
```

## Tree Traversals

### 1. Inorder Traversal (Left, Root, Right)
- **Result**: Sorted sequence for BST
- **Use**: Getting elements in sorted order
```cpp
inorder(node):
    if node != null:
        inorder(node.left)
        visit(node)
        inorder(node.right)
```

### 2. Preorder Traversal (Root, Left, Right)  
- **Result**: Root-first ordering
- **Use**: Creating copy of tree, prefix expressions
```cpp
preorder(node):
    if node != null:
        visit(node)
        preorder(node.left)
        preorder(node.right)
```

### 3. Postorder Traversal (Left, Right, Root)
- **Result**: Children before parent
- **Use**: Deleting tree, postfix expressions
```cpp
postorder(node):
    if node != null:
        postorder(node.left)
        postorder(node.right)
        visit(node)
```

### 4. Level Order Traversal (Breadth-First)
- **Result**: Level by level
- **Use**: Printing tree structure, finding depth
```cpp
levelOrder(root):
    queue.push(root)
    while !queue.empty():
        node = queue.pop()
        visit(node)
        if node.left: queue.push(node.left)
        if node.right: queue.push(node.right)
```

## Traversal Example
```
Tree:      50
          /  \
         30   70
        / |   | \
       20 40 60 80

Inorder:    20, 30, 40, 50, 60, 70, 80  (sorted!)
Preorder:   50, 30, 20, 40, 70, 60, 80  (root first)
Postorder:  20, 40, 30, 60, 80, 70, 50  (children first)
Level:      50, 30, 70, 20, 40, 60, 80  (level by level)
```

## Advanced Operations

### Find Minimum/Maximum
```cpp
// Minimum: leftmost node
findMin(node):
    while node.left != null:
        node = node.left
    return node

// Maximum: rightmost node  
findMax(node):
    while node.right != null:
        node = node.right
    return node
```

### Find Predecessor/Successor
```cpp
// Predecessor: largest value smaller than target
// Successor: smallest value larger than target

predecessor(root, target):
    predecessor = null
    while root != null:
        if target > root.data:
            predecessor = root
            root = root.right
        else:
            root = root.left
    return predecessor
```

### Range Queries
```cpp
// Find all values in range [min, max]
rangeQuery(node, min, max, result):
    if node == null: return
    
    if node.data >= min:
        rangeQuery(node.left, min, max, result)
    
    if min <= node.data <= max:
        result.add(node.data)
    
    if node.data <= max:
        rangeQuery(node.right, min, max, result)
```

## Complexity Analysis

### Time Complexities

| Operation | Average Case | Worst Case | Best Case |
|-----------|--------------|------------|-----------|
| Search    | O(log n)     | O(n)       | O(1)      |
| Insert    | O(log n)     | O(n)       | O(1)      |
| Delete    | O(log n)     | O(n)       | O(1)      |
| Traversal | O(n)         | O(n)       | O(n)      |
| Min/Max   | O(log n)     | O(n)       | O(1)      |

### Why O(log n) Average Case?
- **Height of balanced BST**: log₂(n)
- **Each operation**: Goes down one level per step
- **Total steps**: Equal to height = O(log n)

### Why O(n) Worst Case?
When BST becomes **skewed** (like a linked list):
```
Skewed BST:
10
 \
  20
   \
    30
     \
      40
```
- **Height**: n (instead of log n)
- **Operations degrade**: To linear time

## BST vs Other Data Structures

| Structure    | Search  | Insert  | Delete  | Sorted Output | Memory |
|--------------|---------|---------|---------|---------------|--------|
| BST          | O(log n)| O(log n)| O(log n)| O(n)          | Low    |
| Array        | O(n)    | O(n)    | O(n)    | O(n log n)    | Low    |
| Sorted Array | O(log n)| O(n)    | O(n)    | O(n)          | Low    |
| Hash Table   | O(1)    | O(1)    | O(1)    | O(n log n)    | High   |
| Linked List  | O(n)    | O(1)    | O(n)    | O(n log n)    | Low    |

## Advantages and Disadvantages

### ✅ Advantages
1. **Efficient searching** - O(log n) average case
2. **Sorted output** - Inorder traversal gives sorted sequence
3. **Dynamic size** - Can grow/shrink as needed
4. **Range queries** - Efficiently find values in range
5. **Predecessor/Successor** - Easy to find adjacent values
6. **Memory efficient** - No extra memory like hash tables

### ❌ Disadvantages  
1. **Can become unbalanced** - Worst case O(n) operations
2. **No constant time operations** - Unlike hash tables
3. **Extra memory overhead** - Pointers for each node
4. **Complex deletion** - Three cases to handle
5. **No cache locality** - Random memory access patterns

## Balancing Issues and Solutions

### The Skewing Problem
```
Inserting sorted data: 10, 20, 30, 40, 50

Results in:
10
 \
  20
   \
    30
     \
      40
       \
        50
```
**Height**: 5 (should be 3 for 5 nodes)
**Performance**: Degrades to O(n)

### Solutions: Self-Balancing Trees
1. **AVL Trees** - Height difference ≤ 1
2. **Red-Black Trees** - Color-based balancing
3. **Splay Trees** - Move accessed nodes to root
4. **B-Trees** - Multi-way trees for databases

## Implementation Best Practices

### 1. Recursive vs Iterative
```cpp
// Recursive: Cleaner, easier to understand
Node* insertRecursive(Node* node, T value) {
    if (node == nullptr) return new Node(value);
    // ... recursive calls
}

// Iterative: More memory efficient
void insertIterative(T value) {
    Node* current = root;
    Node* parent = nullptr;
    // ... iterative logic with loops
}
```

### 2. Memory Management
```cpp
// Always provide destructor
~BinarySearchTree() {
    destroyTree(root);
}

void destroyTree(Node* node) {
    if (node != nullptr) {
        destroyTree(node->left);
        destroyTree(node->right);
        delete node;
    }
}
```

## Common Interview Questions

### 1. Validate BST
```cpp
bool isValidBST(node, min, max):
    if node == null: return true
    if node.data <= min or node.data >= max: return false
    return isValidBST(node.left, min, node.data) and
           isValidBST(node.right, node.data, max)
```

### 2. Lowest Common Ancestor
```cpp
Node* LCA(node, p, q):
    if p.data < node.data and q.data < node.data:
        return LCA(node.left, p, q)
    elif p.data > node.data and q.data > node.data:
        return LCA(node.right, p, q)
    else:
        return node  // Split point
```

### 3. Convert Sorted Array to BST
```cpp
Node* sortedArrayToBST(arr, start, end):
    if start > end: return null
    
    mid = (start + end) / 2
    node = new Node(arr[mid])
    
    node.left = sortedArrayToBST(arr, start, mid-1)
    node.right = sortedArrayToBST(arr, mid+1, end)
    
    return node
```

## Performance Optimization Tips

### 1. Choose Right Insertion Order
```cpp
// BAD: Creates skewed tree
insert(1), insert(2), insert(3), insert(4)

// GOOD: Creates balanced tree  
insert(2), insert(1), insert(3), insert(4)
```

### 2. Monitor Tree Balance
```cpp
double balanceFactor = height / log2(size + 1)
// 1.0 = perfect balance
// >1.5 = consider rebalancing
```


## Quick Revision Checklist

### 🎯 Essential Concepts
1. **BST Property**: Left < Root < Right for all nodes
2. **Three deletion cases**: No children, one child, two children
3. **Inorder traversal**: Gives sorted output
4. **Complexity**: O(log n) average, O(n) worst case
5. **Balancing**: Critical for maintaining performance

### 🧠 Memory Aids
- **"Left-Root-Right"**: BST property and inorder traversal
- **"Find successor"**: For two-children deletion case
- **"Height = Performance"**: Lower height = better performance
- **"Sorted insertion = Skewed tree"**: Always randomize if possible

### 🚨 Common Pitfalls
1. **Forgetting BST property** during insertion/deletion
2. **Memory leaks** - not deleting nodes properly
3. **Stack overflow** - deep recursion on skewed trees
4. **Wrong successor** - in deletion of two-children nodes
5. **Boundary cases** - empty tree, single node operations

### ⚡ Interview Success Tips
1. **Draw the tree** - Visualize operations step by step
2. **Handle edge cases** - Empty tree, single node, duplicates
3. **Discuss complexity** - Both average and worst case
4. **Mention balancing** - Show awareness of performance issues
5. **Code defensively** - Check for null pointers, validate inputs

BST is a cornerstone data structure that bridges basic arrays/lists with advanced balanced trees. Master it thoroughly as it appears frequently in interviews and forms the foundation for understanding more complex tree structures!
