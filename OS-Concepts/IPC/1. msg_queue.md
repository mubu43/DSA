# Message Queue IPC in Linux

## What is a Message Queue?

A **message queue** is an IPC mechanism that allows processes to exchange data in the form of **discrete messages**. Unlike pipes (which are byte streams), message queues preserve **message boundaries** — each message is an atomic unit.

```
Process A                  Message Queue                 Process B
   |                      ┌───────────┐                     |
   |──── msg1 ───────────▶│  [msg1]   │                     |
   |──── msg2 ───────────▶│  [msg2]   │◀──── receive ───────|
   |                      │  [msg3]   │                     |
   |                      └───────────┘                     |
                          (FIFO order, with priorities)
```

## Types of Message Queues in Linux

| Type | API | Persistence | Features |
|------|-----|-------------|----------|
| **System V** | `msgget()`, `msgsnd()`, `msgrcv()` | Kernel | Legacy, more complex |
| **POSIX** | `mq_open()`, `mq_send()`, `mq_receive()` | Kernel or FS | Modern, cleaner API |

This guide focuses on **POSIX message queues** (the recommended approach).

## POSIX Message Queue API

### Core Functions

| Function | Purpose | Returns |
|----------|---------|---------|
| `mq_open()` | Create or open a queue | Queue descriptor (`mqd_t`) |
| `mq_send()` | Send a message | 0 on success, -1 on error |
| `mq_receive()` | Receive a message | Bytes received, or -1 |
| `mq_close()` | Close queue descriptor | 0 or -1 |
| `mq_unlink()` | Remove the queue | 0 or -1 |
| `mq_getattr()` | Get queue attributes | 0 or -1 |
| `mq_setattr()` | Set queue attributes | 0 or -1 |
| `mq_notify()` | Register for notifications | 0 or -1 |

### Queue Attributes (`struct mq_attr`)

```c
struct mq_attr {
    long mq_flags;    // Flags: 0 or O_NONBLOCK
    long mq_maxmsg;   // Max number of messages in queue
    long mq_msgsize;  // Max message size (bytes)
    long mq_curmsgs;  // Current messages in queue (read-only)
};
```

## Basic Example

### Sender

```cpp
#include <mqueue.h>
#include <fcntl.h>
#include <cstring>
#include <iostream>

int main() {
    const char* QUEUE = "/my_queue";
    
    // Set attributes
    struct mq_attr attr = {0, 10, 256, 0};  // max 10 msgs, 256 bytes each
    
    // Create/open queue
    mqd_t mq = mq_open(QUEUE, O_CREAT | O_WRONLY, 0644, &attr);
    if (mq == (mqd_t)-1) { perror("mq_open"); return 1; }
    
    // Send message
    const char* msg = "Hello from sender!";
    mq_send(mq, msg, strlen(msg) + 1, 0);  // priority 0
    
    mq_close(mq);
    return 0;
}
```

### Receiver

```cpp
#include <mqueue.h>
#include <iostream>

int main() {
    const char* QUEUE = "/my_queue";
    
    // Open existing queue
    mqd_t mq = mq_open(QUEUE, O_RDONLY);
    if (mq == (mqd_t)-1) { perror("mq_open"); return 1; }
    
    // Get attributes
    struct mq_attr attr;
    mq_getattr(mq, &attr);
    
    // Receive message
    char buffer[256];
    unsigned int prio;
    ssize_t bytes = mq_receive(mq, buffer, attr.mq_msgsize, &prio);
    
    if (bytes > 0) {
        std::cout << "Received: " << buffer << std::endl;
    }
    
    mq_close(mq);
    mq_unlink(QUEUE);  // Remove queue when done
    return 0;
}
```

### Compile and Run

```bash
# Compile (requires -lrt for POSIX message queues)
g++ -o sender sender.cpp -lrt
g++ -o receiver receiver.cpp -lrt

# Run
./sender
./receiver
```

## Message Priorities

Messages can have priorities (0 = lowest). Higher priority messages are received first.

```cpp
// Send with different priorities
mq_send(mq, "low priority", 13, 0);    // priority 0
mq_send(mq, "high priority", 14, 10);  // priority 10

// Receiver gets "high priority" first!
```

## Blocking vs Non-Blocking

### Blocking (default)
```cpp
mqd_t mq = mq_open(QUEUE, O_RDONLY);
mq_receive(mq, buffer, size, &prio);  // Blocks until message available
```

### Non-Blocking
```cpp
mqd_t mq = mq_open(QUEUE, O_RDONLY | O_NONBLOCK);
if (mq_receive(mq, buffer, size, &prio) == -1) {
    if (errno == EAGAIN) {
        // No message available
    }
}
```

### Timed Operations
```cpp
struct timespec timeout;
clock_gettime(CLOCK_REALTIME, &timeout);
timeout.tv_sec += 5;  // 5 second timeout

ssize_t bytes = mq_timedreceive(mq, buffer, size, &prio, &timeout);
if (bytes == -1 && errno == ETIMEDOUT) {
    // Timed out
}
```

## Queue Name Rules

- Must start with `/`
- No additional `/` characters allowed
- Max length: typically 255 characters
- Examples: `/my_queue`, `/app_messages`, `/worker_1`

## Viewing Queues on Linux

Message queues are visible in the filesystem (if mounted):

```bash
# Mount the message queue filesystem (if not mounted)
sudo mkdir -p /dev/mqueue
sudo mount -t mqueue none /dev/mqueue

# List queues
ls -la /dev/mqueue/

# View queue info
cat /dev/mqueue/my_queue

# Remove a queue
rm /dev/mqueue/my_queue
```

## System Limits

Check and modify limits:

```bash
# View limits
cat /proc/sys/fs/mqueue/msg_max       # Max messages per queue
cat /proc/sys/fs/mqueue/msgsize_max   # Max message size
cat /proc/sys/fs/mqueue/queues_max    # Max queues system-wide

# Modify (as root)
echo 100 > /proc/sys/fs/mqueue/msg_max
```

## Comparison: Message Queue vs Other IPC

| Feature | Pipe | Message Queue | Shared Memory | Socket |
|---------|------|---------------|---------------|--------|
| **Data Format** | Byte stream | Discrete messages | Raw memory | Byte stream |
| **Message Boundaries** | No | Yes | No | Depends |
| **Priority Support** | No | Yes | No | No |
| **Bidirectional** | No | Yes (separate queues) | Yes | Yes |
| **Unrelated Processes** | Named pipes only | Yes | Yes | Yes |
| **Network Support** | No | No | No | Yes |
| **Persistence** | No | Until unlinked | Until removed | No |
| **Performance** | Medium | Medium | Fast | Medium-Slow |

## When to Use Message Queues

### ✅ Good Use Cases
- **Request-response patterns** between processes
- **Producer-consumer** scenarios
- **Priority-based processing** (urgent messages first)
- **Decoupled communication** (sender/receiver run independently)
- **Message logging** and auditing

### ❌ Not Ideal For
- **Large data transfers** (use shared memory)
- **Network communication** (use sockets)
- **Tight synchronization** (use semaphores/mutexes)
- **Simple streaming** (use pipes)

## Error Handling

```cpp
mqd_t mq = mq_open("/queue", O_RDONLY);
if (mq == (mqd_t)-1) {
    switch (errno) {
        case ENOENT: cerr << "Queue doesn't exist" << endl; break;
        case EACCES: cerr << "Permission denied" << endl; break;
        case EMFILE: cerr << "Too many open descriptors" << endl; break;
        case ENAMETOOLONG: cerr << "Queue name too long" << endl; break;
        default: perror("mq_open");
    }
}
```

## Complete Producer-Consumer Example

### Producer (sends multiple messages)

```cpp
#include <mqueue.h>
#include <cstring>
#include <iostream>
#include <sstream>
#include <unistd.h>

int main() {
    struct mq_attr attr = {0, 10, 256, 0};
    mqd_t mq = mq_open("/work_queue", O_CREAT | O_WRONLY, 0644, &attr);
    
    for (int i = 1; i <= 5; i++) {
        std::ostringstream oss;
        oss << "Task #" << i;
        std::string msg = oss.str();
        
        mq_send(mq, msg.c_str(), msg.size() + 1, i);  // Priority = task number
        std::cout << "Sent: " << msg << std::endl;
        sleep(1);
    }
    
    mq_close(mq);
    return 0;
}
```

### Consumer (receives in priority order)

```cpp
#include <mqueue.h>
#include <iostream>

int main() {
    mqd_t mq = mq_open("/work_queue", O_RDONLY);
    struct mq_attr attr;
    mq_getattr(mq, &attr);
    
    char buffer[256];
    unsigned int prio;
    
    while (true) {
        ssize_t bytes = mq_receive(mq, buffer, attr.mq_msgsize, &prio);
        if (bytes > 0) {
            std::cout << "Processing: " << buffer << " (priority " << prio << ")" << std::endl;
        }
    }
    
    mq_close(mq);
    mq_unlink("/work_queue");
    return 0;
}
```

## Key Takeaways

1. **Message boundaries are preserved** — unlike pipes, each send/receive is atomic
2. **Priority support** — urgent messages can jump the queue
3. **Named access** — unrelated processes can communicate via queue name
4. **Kernel managed** — queues persist until explicitly unlinked
5. **Link with `-lrt`** — required for POSIX message queue functions
6. **Buffer size matters** — receive buffer must be ≥ `mq_msgsize`
