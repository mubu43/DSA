## What is Routing?

**Routing** is the process of determining the **best path** to reach a destination.

Routing protocols form the **control plane** of the network layer, and are responsible for:
1. Coming up with a set of routes for any destination
2. Picking the best route to install into the forwarding table

```
┌─────────────────────────────────────────────────────────────────────────┐
│                       Routing: Finding the Best Path                    │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│                              ┌───┐                                      │
│                         ┌───►│ B │───┐                                 │
│                         │    └───┘   │                                 │
│                    2    │            │  3                              │
│   ┌───┐                 │            ▼                                 │
│   │ A │────────────────►│         ┌───┐                                │
│   └───┘        5        │         │ D │                                │
│       │                 │         └───┘                                │
│       │                 │            ▲                                 │
│       │    1       ┌───┐│    1       │                                 │
│       └───────────►│ C │┴────────────┘                                 │
│                    └───┘                                               │
│                                                                         │
│   Question: What's the best path from A to D?                          │
│   • A → D (direct): cost 5                                             │
│   • A → B → D: cost 2 + 3 = 5                                          │
│   • A → C → D: cost 1 + 1 = 2  ← BEST PATH!                           │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

## Routing Protocol Phases

Any routing protocol roughly consists of two phases:

| Phase | Description |
|-------|-------------|
| **Route Advertisements** | Information about destinations is exchanged via messages |
| **Best Route Computation** | A best route is chosen to be installed into the forwarding table |

---

## Path Selection Criteria

### Intra-domain Routing

Usually, intra-domain routing protocols pick the **shortest cost path**:
- Every link has a **metric**
- The path that minimizes the sum of all link metrics is chosen as the best path

### How Are Metrics Chosen?

Metrics can be based on:

| Metric Type | Description |
|-------------|-------------|
| **Hop count** | Number of routers traversed (simplest) |
| **Bandwidth** | Higher bandwidth = lower metric |
| **Latency** | Lower delay = lower metric |
| **Physical distance** | Shorter distance = lower metric |
| **Reliability** | More reliable links = lower metric |

In general, metrics are based on the **desirability of using the link**.

### Inter-domain Routing

Inter-domain routing protocols may use other criteria like **policy**. Network operators may also wish to balance load across links (**traffic engineering**).

But usually, the simplest way to pick a path is **shortest path** or **least cost path**.

## Load-Sensitive vs Load-Insensitive Routing

### Load-Insensitive (Most Common)

Most routing protocols do **not** pick the best path based on congestion, as it can lead to **oscillations and instability**.

That is, link metrics do not depend on current load level.

### Why Avoid Load-Sensitive Routing?

```
┌─────────────────────────────────────────────────────────────────────────┐
│              Load-Sensitive Routing: Oscillation Problem                │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   Time T1: Link X is congested                                          │
│   ┌───┐  high load   ┌───┐                                             │
│   │ A │══════════════│ B │   All flows avoid Link X                    │
│   └───┘              └───┘                                             │
│       ╲    low load   ╱                                                │
│        ╲─────────────╱                                                 │
│             via C                                                       │
│                                                                         │
│   Time T2: Now Link via C is congested!                                │
│   ┌───┐   low load   ┌───┐                                             │
│   │ A │──────────────│ B │   All flows move back to Link X             │
│   └───┘              └───┘                                             │
│       ╲   high load   ╱                                                │
│        ╲═════════════╱                                                 │
│             via C                                                       │
│                                                                         │
│   ⚠ OSCILLATION: Flows keep moving back and forth!                    │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

**Example:** If some link is loaded and its metric increases, all flows may move away from it, leading to load on another link, and all flows will move back again.

## Static vs Dynamic Routing

### Static Routing

For small networks and/or networks that rarely change, **manually setting the route once** is sufficient. This is called **static routing**.

| Pros | Cons |
|------|------|
| Simple to configure | Doesn't adapt to failures |
| Predictable | Manual updates required |
| No routing protocol overhead | Doesn't scale |

### Dynamic Routing

For more complicated networks, **dynamic routing protocols** are used, that adapt routes in response to changes in network topology.

We will study two classes of dynamic routing protocols:
1. **Link State (LS)** routing protocols
2. **Distance Vector (DV)** routing protocols

---

## Link State (LS) Routing

### Philosophy

> **"Tell about your neighbors to everyone"**

### How It Works

1. Each node collects information about all its **neighbors** and the **link metrics**
2. This **LSA (Link State Announcement)** of every node is **flooded** through the entire network
3. At the end of it, each node has a **complete view of the network graph**
4. Each node then independently runs **Dijkstra's shortest path algorithm** to get the shortest path to every destination
5. Based on the shortest paths, each node figures out the **next hop** for every destination

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    Link State Routing: Step by Step                     │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   Step 1: Each router discovers its neighbors                          │
│                                                                         │
│   Router A knows:          Router B knows:         Router C knows:     │
│   • Link to B, cost 2      • Link to A, cost 2     • Link to A, cost 1 │
│   • Link to C, cost 1      • Link to D, cost 3     • Link to D, cost 1 │
│                                                                         │
│   Step 2: Flood LSAs to all routers                                    │
│                                                                         │
│   ┌─────────────────────────────────────────────────────────────────┐  │
│   │   Every router receives LSAs from ALL other routers             │  │
│   │   Now every router knows the COMPLETE network topology          │  │
│   └─────────────────────────────────────────────────────────────────┘  │
│                                                                         │
│   Step 3: Each router independently runs Dijkstra                      │
│                                                                         │
│   Router A computes:                                                    │
│   • Shortest path to B: A → B (cost 2)                                 │
│   • Shortest path to C: A → C (cost 1)                                 │
│   • Shortest path to D: A → C → D (cost 2)                             │
│                                                                         │
│   Step 4: Populate forwarding table                                    │
│                                                                         │
│   ┌───────────────┬───────────────┐                                    │
│   │  Destination  │   Next Hop    │                                    │
│   ├───────────────┼───────────────┤                                    │
│   │      B        │      B        │                                    │
│   │      C        │      C        │                                    │
│   │      D        │      C        │  (via C to reach D)                │
│   └───────────────┴───────────────┘                                    │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### Dijkstra's Algorithm Summary

Dijkstra's algorithm finds the shortest path from a source node to all other nodes:

1. Initialize distances: source = 0, all others = ∞
2. Mark source as current node
3. Update distances to neighbors: $d[neighbor] = \min(d[neighbor], d[current] + cost[current, neighbor])$
4. Mark current node as visited
5. Select unvisited node with smallest distance as new current
6. Repeat until all nodes visited

## Distance Vector (DV) Routing

### Philosophy

> **"Tell about everyone to your neighbors"**

### How It Works

1. Every node exchanges a **distance vector** (a vector containing its estimate of distance to each destination) with its neighbors
2. Upon receiving a neighbor's distance vector, a node updates its distance vector by:
   - Adding its link cost to the neighbor's distance vector
   - If a better path is found through the neighbor, it updates its best route
3. This is called the **Bellman-Ford update algorithm**

### The Bellman-Ford Equation

For each destination $x$:

$$d_x(y) = \min_{v \in neighbors} \{ c(x,v) + d_v(y) \}$$

Where:
- $d_x(y)$ = distance from node $x$ to destination $y$
- $c(x,v)$ = cost of link from $x$ to neighbor $v$
- $d_v(y)$ = neighbor $v$'s distance to destination $y$

```
┌─────────────────────────────────────────────────────────────────────────┐
│                 Distance Vector Routing: Example                         │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   Network:    A ───2─── B                                               │
│               │         │                                               │
│               1         3                                               │
│               │         │                                               │
│               C ───1─── D                                               │
│                                                                         │
│   Initial Distance Vectors (each node only knows direct neighbors):    │
│                                                                         │
│   Node A: {A:0, B:2, C:1, D:∞}                                         │
│   Node B: {A:2, B:0, C:∞, D:3}                                         │
│   Node C: {A:1, B:∞, C:0, D:1}                                         │
│   Node D: {A:∞, B:3, C:1, D:0}                                         │
│                                                                         │
│   After exchanging with neighbors and updating:                        │
│                                                                         │
│   Node A receives from C: distance to D = 1                            │
│   Node A updates: d_A(D) = min(∞, 1 + 1) = 2                          │
│                                                                         │
│   Final Distance Vectors:                                               │
│   Node A: {A:0, B:2, C:1, D:2}  (via C to reach D)                     │
│   Node B: {A:2, B:0, C:3, D:3}  (via A to reach C)                     │
│   Node C: {A:1, B:3, C:0, D:1}  (via A to reach B)                     │
│   Node D: {A:2, B:3, C:1, D:0}  (via C to reach A)                     │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### Count to Infinity Problem

Distance vector has the **"count to infinity"** problem.

**Example:** If a link fails, bad news travels slowly:

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    Count to Infinity Problem                             │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   Initial: A ───1─── B ───1─── C                                       │
│                                                                         │
│   Distance vectors: A knows d(C) = 2 via B                             │
│                     B knows d(C) = 1 direct                            │
│                                                                         │
│   Link B-C fails: A ───1─── B    X    C                                │
│                                                                         │
│   B updates: d(C) = ∞? No! B asks A, A says "I can reach C in 2"      │
│   B thinks: "I can reach C via A in 1 + 2 = 3"                         │
│                                                                         │
│   A updates: "B says it can reach C in 3"                              │
│   A thinks: "I can reach C via B in 1 + 3 = 4"                         │
│                                                                         │
│   B updates: "A says it can reach C in 4"                              │
│   B thinks: "I can reach C via A in 1 + 4 = 5"                         │
│                                                                         │
│   ... continues until distance reaches infinity!                        │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### Solutions to Count to Infinity

| Solution | Description |
|----------|-------------|
| **Split Horizon** | Don't advertise a route back to the neighbor you learned it from |
| **Poisoned Reverse** | Advertise the route back as infinity |

## Common Routing Protocols

### OSPF (Open Shortest Path First)

A popular **intra-domain routing protocol** that uses simple LS routing logic.

| Feature | Description |
|---------|-------------|
| **Type** | Link State |
| **Algorithm** | Dijkstra's shortest path |
| **Scalability** | Supports hierarchical areas |
| **Convergence** | Fast |

### RIP (Routing Information Protocol)

A simple **DV protocol**.

| Feature | Description |
|---------|-------------|
| **Type** | Distance Vector |
| **Algorithm** | Bellman-Ford |
| **Metric** | Hop count (max 15) |
| **Updates** | Periodic broadcasts |

---

## Comparison: Link State vs Distance Vector

| Aspect | Link State | Distance Vector |
|--------|------------|-----------------|
| **Knowledge** | Complete topology | Only neighbor distances |
| **Algorithm** | Dijkstra | Bellman-Ford |
| **Message complexity** | O(N × E) messages | Exchange with neighbors only |
| **Convergence** | Fast | Can be slow (count to infinity) |
| **Memory** | Stores full topology | Stores distance vector only |
| **Example Protocol** | OSPF | RIP |
