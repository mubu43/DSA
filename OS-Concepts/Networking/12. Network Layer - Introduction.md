## The Network Layer Overview

So far, we have studied the network edge (application and transport layers). Now we come to the **network core**.

The network or IP layer:
1. Takes transport layer payload (e.g., TCP segments)
2. Encapsulates it in an IP header to get **IP datagrams**
3. The IP datagrams have a source and destination IP address
4. The job of the network layer is to **transport this IP datagram from the source IP to the destination IP**

### Where Does the Network Layer Run?

The network layer runs on **every node that has an IP address**, including:
- End hosts
- IP routers that connect end hosts

This is unlike the transport layer, which only runs on end hosts.

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    Network Layer in Action                               │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   Host A                                                  Host B        │
│   ┌───────┐                                              ┌───────┐     │
│   │ App   │                                              │ App   │     │
│   ├───────┤                                              ├───────┤     │
│   │ TCP   │                                              │ TCP   │     │
│   ├───────┤                                              ├───────┤     │
│   │  IP   │                                              │  IP   │     │
│   └───┬───┘                                              └───▲───┘     │
│       │                                                      │         │
│       │    ┌─────────┐    ┌─────────┐    ┌─────────┐        │         │
│       └───►│ Router  │───►│ Router  │───►│ Router  │────────┘         │
│   Ethernet │  R_A    │    │  Core   │    │   R_B   │  WiFi            │
│            │  (IP)   │    │  (IP)   │    │  (IP)   │                   │
│            └─────────┘    └─────────┘    └─────────┘                   │
│                                                                         │
│   Note: Adjacent IP hosts can be connected by different L2 technologies│
│   (Ethernet, WiFi, Satellite, etc.). The LINK LAYER handles moving    │
│   datagrams from one IP hop to the next.                               │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

Consider a host A connected over an Ethernet LAN to its "first-hop" IP router R_A, that wants to communicate with host B, which is connected to its IP router R_B.

> **Important:** Adjacent IP hosts (especially end hosts and first-hop IP routers) needn't be directly connected by a wire (point-to-point link). They can be connected by an Ethernet LAN, wireless LAN, satellite link, whatever. The **link layer (layer 2)** takes care of moving the IP datagram from one IP hop to the next IP hop. The **network layer** deals only at the level of IP hops.

## Routers vs Switches

**What is the difference between a router and a switch?**

Generally, all network elements in a packet-switched network are **packet switches**, so IP routers are also packet switches — more specifically, **layer 3 switches**.

| Type | Layer | Routing Based On |
|------|-------|------------------|
| **IP Router (Layer 3 Switch)** | Network Layer (L3) | IP addresses |
| **Link-Layer Switch (Layer 2 Switch)** | Link Layer (L2) | MAC addresses |

> To avoid confusion, we will refer to layer 3 switches as **routers**.

## IP Addresses and Interfaces

### Who Gets an IP Address?

Every host? Well, technically, **every interface**. A host can have multiple network interfaces, each will have its own IP address.

**Exercise:** Run the Linux command `ifconfig` to see all the interfaces and IP addresses on your machine.

### Why Separate IP Per Interface?

Why should each interface have a separate IP address (instead of just one IP per host)?

Suppose a host has both a wireless interface and a wired interface. For traffic that must flow through the wireless, it will use the wireless interface's IP as the source IP (so that traffic comes back via wireless). If it used the same IP for both interfaces, the host wouldn't have control over which traffic flows on which link.

```

│   │                                                          │          │
│   │   ┌─────────────────┐     ┌─────────────────┐           │          │
│   │   │  Wired (eth0)   │     │ Wireless (wlan0)│           │          │
│   │   │  IP: 10.0.0.5   │     │ IP: 192.168.1.5 │           │          │
│   │   └────────┬────────┘     └────────┬────────┘           │          │
```

## IPv4 Addressing

### Address Format

IPv4 addresses are **32-bit (4 byte)** numbers, represented by **dotted decimal notation**.

**Example:** `192.168.1.100`

### IP Prefixes and Subnets

Groups of IP addresses are called **IP prefixes** or **subnets** (subnetworks).

**Example:** `10.0.0.0/8` denotes a set of $2^{24}$ IP addresses that have the first 8 bits in common.

| Notation | Meaning |
|----------|---------|
| `/8` | First 8 bits are the network portion |
| `/16` | First 16 bits are the network portion |
| `/24` | First 24 bits are the network portion |

This number of bits in common is called the **prefix length**, and can be represented by a **subnet mask**.

**Example:** Subnet mask of `255.0.0.0` denotes IP prefix length 8.

```
┌─────────────────────────────────────────────────────────────────────────┐
│                       IP Address Structure                               │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   Example: 10.129.5.20/16                                               │
│                                                                         │
│   Binary:  00001010.10000001.00000101.00010100                         │
│            └───────────────┘ └─────────────────┘                        │
│                Network           Host                                    │
│              (16 bits)        (16 bits)                                 │
│                                                                         │
│   Subnet Mask: 255.255.0.0                                              │
│   Binary:      11111111.11111111.00000000.00000000                     │
│                                                                         │
│   All hosts in 10.129.0.0/16 share the first 16 bits                   │
│   Range: 10.129.0.0 to 10.129.255.255 (65,536 addresses)               │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

## Subnetting

### Creating Subnets

How do you make subnets? Take the number of hosts that will be in close proximity, and allocate a subnet with enough hosts to manage them, so that they can all be served by the same LAN and by the same IP router.

### Example: Subnetting for CSE Department

Suppose CSE has the `10.129.0.0/16` prefix. We want to create 4 contiguous subnets for 4 labs that have 200, 100, 50, 50 computers respectively.

We take `10.129.0.0/23` (512 addresses) and break it up into 4 subnets:

| Lab | Required Hosts | Subnet | Addresses Available |
|-----|----------------|--------|---------------------|
| Lab 1 | 200 | `10.129.0.0/24` | 256 |
| Lab 2 | 100 | `10.129.1.0/25` | 128 |
| Lab 3 | 50 | `10.129.1.128/26` | 64 |
| Lab 4 | 50 | `10.129.1.192/26` | 64 |

```
┌─────────────────────────────────────────────────────────────────────────┐
│                      Subnet Allocation Example                           │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   Original: 10.129.0.0/23 (512 addresses)                               │
│                                                                         │
│   ┌─────────────────────────────────────────────────────────────────┐  │
│   │                       10.129.0.0/23                              │  │
│   ├─────────────────────────────────────────────────────────────────┤  │
│   │ 10.129.0.0/24 │ 10.129.1.0/25 │10.129.1.128/26│10.129.1.192/26 │  │
│   │   (256 IPs)   │   (128 IPs)   │   (64 IPs)    │   (64 IPs)     │  │
│   │    Lab 1      │     Lab 2     │     Lab 3     │     Lab 4      │  │
│   │  (200 hosts)  │  (100 hosts)  │  (50 hosts)   │   (50 hosts)   │  │
│   └─────────────────────────────────────────────────────────────────┘  │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### Special Broadcast Address

**Special broadcast IP address:** `255.255.255.255`

Packets sent to this broadcast address reach all hosts in the **"broadcast domain"**, which is typically all the hosts in a given LAN.

## Routing and Forwarding

### Two Functions of the Network Layer

The network layer has two main functions:

| Function | Also Called | Description |
|----------|-------------|-------------|
| **Routing** | Control Plane | Computing paths to destinations |
| **Forwarding** | Data Plane | Moving packets based on computed paths |

The granularity of routing and forwarding is an **IP prefix** (instead of individual IP addresses) for scalability. That is, you make the same routing and forwarding decisions for all IP addresses in a prefix.

### Forwarding Table

A forwarding table maps an **IP prefix to the next-hop IP address**. That is, for a given destination IP prefix, the forwarding table tells us:
- Which is our next-hop IP router
- Which link/interface to send the packet on

**At end hosts** with one interface typically, the forwarding table is simple, and points to the first-hop IP router and the single interface.

**Exercise:** Run the Linux command `route -n` at the command line and see your forwarding table.

**At routers**, the forwarding tables are more complex, since a router has several interfaces (links), and the forwarding table helps us determine which outgoing link/interface to send the packet on.

### Routing Table

A routing table maps an **IP prefix to a set of possible network paths** to reach that destination. Out of the various paths, the best path is chosen, and the next-hop information is populated in the forwarding table.

**How do we obtain the routing table?** You can of course manually configure routing and forwarding tables for small networks. What about large networks?

### Longest Prefix Match (LPM)

Note that all prefixes in the forwarding table need not be disjoint. That is, you can have a forwarding table entry for the "larger" `10.0.0.0/8` and "more specific" `10.0.0.0/16` prefix.

If you are looking for a particular IP address, you normally match it with the more specific entry, or a **longest prefix match**.

```
┌─────────────────────────────────────────────────────────────────────────┐
│                      Longest Prefix Match Example                        │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   Forwarding Table:                                                     │
│   ┌─────────────────────┬───────────────────┐                          │
│   │       Prefix        │     Next Hop      │                          │
│   ├─────────────────────┼───────────────────┤                          │
│   │    10.0.0.0/8       │    Router A       │                          │
│   │    10.0.0.0/16      │    Router B       │                          │
│   │    10.0.5.0/24      │    Router C       │                          │
│   └─────────────────────┴───────────────────┘                          │
│                                                                         │
│   Destination: 10.0.5.100                                               │
│                                                                         │
│   Matches:                                                              │
│   ✓ 10.0.0.0/8   (8 bits match)                                        │
│   ✓ 10.0.0.0/16  (16 bits match)                                       │
│   ✓ 10.0.5.0/24  (24 bits match) ← LONGEST MATCH, use Router C         │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

## Routing Protocols Overview

**Routing protocols** are algorithms (often distributed/decentralized) that run at various routers.

### Typical Operation

1. **Route Announcement Phase:** Each router conveys some information to other routers (e.g., "I can be used to reach so-and-so prefix")
2. **Route Computation Phase:** Information collected from other routers is digested

Together, the routing protocols result in routers discovering several paths to a given destination, and hence building their routing tables.

### Two Types of Routing Protocols

| Type | Approach |
|------|----------|
| **Link State (LS)** | Each router learns the complete network topology, then computes shortest paths |
| **Distance Vector (DV)** | Each router only knows distance to destinations via neighbors |

At the core, these are simple **shortest path computation algorithms**.

## Hierarchical Routing

Routing in the Internet is typically **hierarchical**.

### Inside an Organization (Intra-domain)

1. Hosts are grouped into **subnets** based on physical proximity
2. A subnet is connected by a layer 2 technology (e.g., Ethernet) to its first-hop IP router
3. Multiple IP routers are connected to each other by point-to-point links or Ethernet
4. All these routers in an organization run an **"intra-domain" routing protocol** (like OSPF or RIP) to compute paths among themselves
5. Every router in an organization knows how to reach other internal IP destinations

### Outside the Organization (Inter-domain)

What about IP destinations outside the organization?

1. There are special **"border" routers** at the edges of organizations that connect to other border routers
2. Internet Service Providers (ISPs) run a bunch of border routers that connect various "stub" organizations and other ISPs
3. These border routers run **"inter-domain" routing protocols** (BGP is the de facto standard today)
4. These inter-domain routing protocols determine paths between organizations

The intra-domain and inter-domain routing protocols together fill up the forwarding tables in such a way that every IP router along the path can correctly route packets.

```
┌─────────────────────────────────────────────────────────────────────────┐
│                      Hierarchical Internet Routing                       │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   ┌───────────────────────────────────────────────────────────────────┐│
│   │                         ISP Backbone (BGP)                        ││
│   │   ┌─────────┐                               ┌─────────┐          ││
│   │   │ Border  │◄─────────────────────────────►│ Border  │          ││
│   │   │ Router  │                               │ Router  │          ││
│   │   └────┬────┘                               └────┬────┘          ││
│   └────────┼─────────────────────────────────────────┼────────────────┘│
│            │                                         │                  │
│   ┌────────┼──────────────┐             ┌───────────┼─────────────┐   │
│   │  AS 1 (OSPF/RIP)      │             │   AS 2 (OSPF/RIP)       │   │
│   │        │              │             │           │             │   │
│   │   ┌────┴────┐         │             │      ┌────┴────┐        │   │
│   │   │ Internal│         │             │      │ Internal│        │   │
│   │   │ Routers │         │             │      │ Routers │        │   │
│   │   └────┬────┘         │             │      └────┬────┘        │   │
│   │        │              │             │           │             │   │
│   │   ┌────┴────┐         │             │      ┌────┴────┐        │   │
│   │   │  Hosts  │         │             │      │  Hosts  │        │   │
│   │   └─────────┘         │             │      └─────────┘        │   │
│   └───────────────────────┘             └─────────────────────────┘   │
│                                                                         │
│   Intra-domain: OSPF, RIP (shortest path)                              │
│   Inter-domain: BGP (policy-based)                                      │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### Why Separate Inter-domain and Intra-domain?

| Reason | Explanation |
|--------|-------------|
| **Scale** | Do not want to run routing protocols over millions of routers |
| **Policy** | Inter-domain routing involves more than shortest path routing (e.g., business relationships) |

More on inter-domain routing later.

## IP Address Allocation

### Getting Addresses from Your ISP

One technique is to get IP addresses from your ISP.

**Example:** Suppose your ISP has `103.21.0.0/16`. He may decide to give `103.21.0.0/24` to the customer network. The ISP will jointly announce the bigger /16 prefix. When traffic to the /24 prefix reaches the ISP, the traffic is routed to the customer organization.

### The Renumbering Problem

When you have IP addresses from your ISP, **what happens if you change ISPs?** You have to renumber.

Instead, you can apply and get your own IP address prefix from **Internet registries**. You can then announce your prefix via ISPs and the rest of the Internet can reach you.

### Classful vs Classless Addressing

IP addresses were initially allocated in units of:
- **/8** (Class A) — $2^{24}$ addresses
- **/16** (Class B) — $2^{16}$ addresses
- **/24** (Class C) — $2^8$ addresses

**Problems:**
- Class A prefix ($2^{24}$ addresses) was too big for most organizations
- Class C prefix ($2^8$ addresses) was too small
- Class B addresses were running out fast

**Solution:** Today, we have **classless allocation (CIDR)** — registries can allocate any length prefix that they wish.

## DHCP

### Dynamic Host Configuration Protocol

Once you have a prefix, how do you allocate individual IP addresses? You can allocate them **statically** or **dynamically using DHCP**.

### How DHCP Works

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         DHCP Protocol                                    │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   CLIENT                                              DHCP SERVER       │
│      │                                                    │             │
│      │                                                    │             │
│      │──── DHCP DISCOVER (broadcast) ────────────────────►│             │
│      │     "I need an IP address!"                        │             │
│      │                                                    │             │
│      │◄─── DHCP OFFER ────────────────────────────────────│             │
│      │     "How about 10.0.0.50?"                         │             │
│      │                                                    │             │
│      │──── DHCP REQUEST ─────────────────────────────────►│             │
│      │     "Yes, I'll take 10.0.0.50"                     │             │
│      │                                                    │             │
│      │◄─── DHCP ACK ──────────────────────────────────────│             │
│      │     "Confirmed. Lease for 24 hours."               │             │
│      │                                                    │             │
│   ═══╪═══════════ Client now has IP: 10.0.0.50 ═══════════╪═══════     │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

1. **DHCP Discover:** Whenever a client joins, it sends a DHCP discover message to the broadcast `255.255.255.255` IP address
2. **DHCP Offer:** Any DHCP servers that listen to this message will send out DHCP offers
3. **DHCP Request:** The client will accept one of the offers, and send a DHCP request message to the DHCP server whose request it has accepted
4. **DHCP ACK:** The server will then send a DHCP ACK

The DHCP address has a **validity period (lease)**.

## Private IP and NAT

### The Address Exhaustion Problem

Sometimes the IP prefix you get may not have enough addresses for all your hosts, especially now due to **IPv4 address exhaustion**.

**Solution:** Have some public IPs and the rest are **private IP addresses**, like in IITB.

### Private IP Address Ranges

| Range | CIDR Notation |
|-------|---------------|
| 10.0.0.0 – 10.255.255.255 | `10.0.0.0/8` |
| 192.168.0.0 – 192.168.255.255 | `192.168.0.0/16` |

In IITB, we assign addresses to all hosts from the `10.0.0.0/8` prefix. Only web servers and other hosts that receive traffic from outside get public IPs.

### The Problem with Private IP

Private IP addresses do not have routes in the external Internet, so hosts outside cannot reach you. Even if you originate the TCP connection, you must still receive SYN-ACK etc. at your IP address.

### Network Address Translation (NAT)

**Solution:** Network Address Translator (NAT). IITB has a NAT (several of them) at the edge.

**How NAT works:**
1. A NAT rewrites IP headers
2. Replaces the private IP and port with a public IP and port
3. A NAT can handle several (more than 60,000) connections using one public IP and all port numbers

```
┌─────────────────────────────────────────────────────────────────────────┐
│                       Network Address Translation                        │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   Private Network                           Public Internet             │
│   (10.0.0.0/8)                                                          │
│                                                                         │
│   ┌───────────┐                                                         │
│   │ Host A    │                                                         │
│   │10.0.0.5:80│──┐                                                      │
│   └───────────┘  │                                                      │
│                  │    ┌─────────────────┐                               │
│   ┌───────────┐  ├───►│      NAT        │                               │
│   │ Host B    │  │    │                 │     ┌─────────────┐          │
│   │10.0.0.6:80│──┤    │ Private→Public  │────►│ Web Server  │          │
│   └───────────┘  │    │10.0.0.5:80      │     │ 8.8.8.8     │          │
│                  │    │ → 203.0.113.1:  │     └─────────────┘          │
│   ┌───────────┐  │    │   12345         │                               │
│   │ Host C    │  │    │                 │                               │
│   │10.0.0.7:80│──┘    │ Maintains       │                               │
│   └───────────┘       │ translation     │                               │
│                       │ table           │                               │
│                       └─────────────────┘                               │
│                       Public IP: 203.0.113.1                            │
│                       (One public IP, 65K+ ports)                       │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### IPv6: The Long-Term Solution

A more permanent solution to IP address exhaustion is to move to **IPv6**. IPv6 has **128-bit addresses** (instead of 32-bit in IPv4), so everyone (and everything!) can have an IP address.

## Summary

| Concept | Description |
|---------|-------------|
| **Network Layer** | Transports IP datagrams from source to destination |
| **IP Address** | 32-bit address assigned per interface |
| **Subnet/Prefix** | Group of IP addresses with common prefix |
| **Forwarding Table** | Maps IP prefix to next-hop |
| **Routing Table** | Maps IP prefix to possible paths |
| **LPM** | Longest Prefix Match for lookup |
| **Intra-domain Routing** | Within organization (OSPF, RIP) |
| **Inter-domain Routing** | Between organizations (BGP) |
