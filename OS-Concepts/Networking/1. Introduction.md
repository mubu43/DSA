## What is the Internet Made Of?

The Internet is fundamentally composed of:

- **Computers** connected by **links** via **switches/routers**. Multiple links terminate at a switch/router, which enables connectivity between them.

- Many switches/routers are present in an organization like IITB to connect all the **end-hosts**. End-hosts provide and consume useful services (e.g., web, email).

- **Internet Service Providers (ISPs)** connect multiple such end-user organizations. ISP networks have several routers that provide interconnections between end organizations, and form the **"backbone"** of the Internet.

## IP Addresses and Packets

### IP Addresses

Every machine on the Internet has a unique address called the **IP address** (well, almost...).

| Property | Description |
|----------|-------------|
| **Assignment** | Can be assigned statically or dynamically (e.g., via DHCP) |
| **Visibility** | Can be public or private (e.g., through a NAT) |
| **Structure** | IP addresses have a hierarchical structure |
| **Human-readable** | Machines also have human-readable names that map to IP addresses |

### Packets

A **packet** is the unit of communication between machines. Data is broken down into packets for transmission across the network.

## Example: Opening a Web Page

What happens when you open a web page from a computer by typing in a URL?

### At the Browser Level

1. The URL gets resolved into an **IP address** of the web server that hosts this page.
2. The browser sends a special message (**GET request**) to the server.
3. The server sends back the **HTML content**.
4. The browser then displays the page to the user.

### At the End Hosts

1. Browser opens a **"TCP connection"** to the web server.
2. Messages between the browser and server are sent over this connection.
3. **TCP (Transmission Control Protocol)** is a transport mechanism that reliably sends information back and forth between two endpoints.
4. TCP modules (running in the end host operating systems, typically) make sure that messages are delivered reliably.

### How TCP Messages Travel

```
┌──────────────────────────────────────────────────────────────────────────┐
│                         Packet Journey Across the Internet               │
├──────────────────────────────────────────────────────────────────────────┤
│                                                                          │
│  ┌────────┐    ┌────────┐    ┌────────┐    ┌────────┐    ┌────────────┐ │
│  │ Your   │───►│Default │───►│ Router │───►│ Router │───►│ Web Server │ │
│  │Computer│    │Gateway │    │   #2   │    │   #N   │    │            │ │
│  └────────┘    └────────┘    └────────┘    └────────┘    └────────────┘ │
│                                                                          │
│  TCP data is routed to the server's IP address via various "routers"    │
│  running IP (Internet Protocol). Each router "talks" to others and      │
│  knows how to get to any destination IP address.                        │
│                                                                          │
└──────────────────────────────────────────────────────────────────────────┘
```

The TCP data to the server must be routed to the server's IP address via various "routers" running IP (internet protocol). Your computer sends the packet to an IP router or default gateway that sends it to another router, which sends it to another router, and so on. The IP routers "talk" amongst themselves and so they know how to get to any destination IP address. Thus, several routers along the way forward these TCP segments from one IP hop to the next based on the destination server's IP address. At the final IP hop, the IP router next to the web server hands the packet to the web server over the LAN.

Several TCP segments and ACKs go back and forth this way to transfer the complete web page.

## The Layered Architecture

The above example illustrates the concept of **layering**. There are several functions in the networking "stack", each handled by a layer.

### Key Concepts of Layering

- A layer at one host talks to its **"peer" layer** at the other host using a set of **"protocols"** or conventions that they both follow.
- Every layer provides a **"service"** or **"abstraction"** that the higher layer uses.

**Example:** The application layer at the client says GET a page and the application layer at server sends the page. This is the **HTTP protocol**. HTTP protocol uses the transport "service" provided by the TCP layer. That is, once it hands over the GET message to the TCP layer, the TCP layer takes care of actually transporting the bits in the message to the other end.

### Why Layering?

| Benefit | Explanation |
|---------|-------------|
| **Modularity** | Each layer can evolve independently |
| **Simplicity** | Easier to build large networks over differing technologies |
| **Flexibility** | Technologies can change at one layer without affecting others |

### The 5/7 Layer Models

There are 5/7 layers depending on which system you look at (OSI vs Internet). The 5 layers are the most important ones:

| Layer | Implementation Location |
|-------|------------------------|
| **Application & Transport** | End hosts - user programs, operating systems |
| **Network (IP)** | Specialized routers |
| **Link & Physical** | Network hardware (e.g., Ethernet card) and device drivers |

## The Five Layers Explained

### 1. Application Layer

The application layer is just concerned with the **application-level semantics**:
- GET a web page and display it
- Browser issues requests and displays results
- Web server holds all the pages on its disk/memory (or computes them dynamically), and serves them when a request arrives

**Common Application Layer Protocols:**
- **HTTP** - Most popular, for web browsing
- **SMTP** - For email
- **P2P protocols** - For peer-to-peer file sharing

### 2. Transport Layer

The transport layer (usually TCP, but sometimes UDP/RTP etc.) is concerned with the **transfer of the bits and bytes** that make up the application data.

**Key Responsibilities:**
- Takes the application layer "messages" and makes them into TCP "segments"
- Transmits them at a suitable pace that the network can handle
- Makes sure they are received and acknowledged by the other end host
- Retransmits them when needed

**Important Characteristics:**
- **TCP does not care about what the data is** (that's the job of the application layer)
- **TCP does not care how the data gets there** (that's the job of the lower layers)
- TCP provides a **reliable in-order data stream abstraction**
- TCP performs **congestion/flow control** to ensure that it sends data at an optimum rate

**Transport Protocol Options:**

| Protocol | Use Case |
|----------|----------|
| **TCP** | Most common, reliable delivery |
| **UDP** | When reliability is not needed |
| **RTP** | Real-time services like VoIP |

> **Note:** The application and transport layers are **end-to-end**, run at only the end hosts (in operating systems and user programs), they don't care what the network does in between.

### 3. Network Layer (IP Layer / Layer 3)

TCP segments are converted to **"IP datagrams"**. The datagram has a source and destination IP address. The job of the network layer is to **route the datagram to its destination IP address**. Each IP router along the way looks up the destination address and decides which link it should forward the packet next.

#### IP Prefixes and Forwarding

Do IP routers have separate entries for every IP address? **No.** IP addresses have hierarchical structure. An aggregate of several IP addresses is called an **IP prefix**.

Every IP router has:
- Several incoming links/ports
- Several outgoing links/ports
- A **forwarding table** that maps IP prefixes to next hop IP addresses

#### Routing vs Forwarding

| Concept | Description |
|---------|-------------|
| **Forwarding Tables** | Computed by routing protocols |
| **Routes** | Specification of the path to reach a certain IP prefix |
| **Routing Table** | Superset of the forwarding table, contains all route information |

#### Intradomain vs Interdomain Routing

| Type | Scope | Considerations |
|------|-------|----------------|
| **Intradomain** | Within an organization | Just deals with shortest paths |
| **Interdomain (Wide-area)** | Across the Internet | Must deal with policy (e.g., financial relationships) |

### 4. Link Layer (Layer 2)

Deals with delivering a link layer **"frame"** over an IP hop or "link", for example:
- Through a shared LAN
- A switch
- A point-to-point fiber link
- A wireless link

### 5. Physical Layer

Deals with transmitting the **actual bits** over a physical medium like:
- Copper wire
- Optical fiber
- Wireless radio

## The Unifying Power of IP

Note that several link layer technologies can be connected together via IP. A host connected to an Ethernet network can communicate with another host connected to a wireless network, as long as they both speak IP and are connected by a path of IP routers.

**Key Insight:** The links between any two IP hops can be very different. Thus the Internet has grown as a **network of networks** due to the unifying IP protocol.

```
┌───────────────────────────────────────────────────────────────────┐
│              IP: The Unifying Protocol                            │
├───────────────────────────────────────────────────────────────────┤
│                                                                   │
│  ┌──────────┐    ┌────────┐    ┌────────┐    ┌──────────────┐    │
│  │ Ethernet │───►│   IP   │───►│   IP   │───►│   Wireless   │    │
│  │  Host    │    │ Router │    │ Router │    │     Host     │    │
│  └──────────┘    └────────┘    └────────┘    └──────────────┘    │
│       │              │              │               │             │
│  [Ethernet]    [Fiber Link]   [WiFi Link]     [Wireless]         │
│                                                                   │
│  Different link technologies, same IP protocol!                  │
│                                                                   │
└───────────────────────────────────────────────────────────────────┘
```

## Summary

The Internet is built on a layered architecture where each layer provides specific services to the layer above it. This modularity allows different technologies to coexist and evolve independently, while IP serves as the unifying protocol that connects diverse networks into one global Internet.
