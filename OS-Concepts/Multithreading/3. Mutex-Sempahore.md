
## First: What problem are we solving?

Threads **share memory**.
If two threads touch the same data at the same time, you get:

* Data races
* Corrupted state
* Heisenbugs (appear/disappear with logging)

Synchronization mechanisms solve **two different problems**:

1. **Mutual exclusion** → “Only one thread at a time”
2. **Coordination / ordering** → “Wait until something happens”

Keep this distinction in mind—it explains *why mutex ≠ semaphore ≠ condition variable*.

---

# 1. Mutual Exclusion (Mutex)

### What is a mutex?

A **mutex** allows **only one thread** to enter a critical section at a time.

> Think of it as a **key to a room**.
> Only the thread holding the key can enter.

---

## Simple Example: Protecting a shared counter

```cpp
#include <iostream>
#include <thread>
#include <mutex>

int counter = 0;
std::mutex mtx;

void increment() {
    for (int i = 0; i < 1000; ++i) {
        std::lock_guard<std::mutex> lock(mtx);
        counter++;
    }
}

int main() {
    std::thread t1(increment);
    std::thread t2(increment);

    t1.join();
    t2.join();

    std::cout << counter << std::endl;  // Always 2000
}
```

### What’s happening?

* `counter` is shared
* `mtx` protects it
* `lock_guard`:

  * Locks mutex when created
  * Unlocks automatically when scope ends

---

## When to use a mutex

Use a mutex when:

* You have **shared data**
* That data is **read-modified-written**
* Only **one thread** should access it at a time

### Typical use cases

* Updating counters
* Modifying shared containers (maps, queues)
* Protecting session state (very common in telecom CP code)

---

## What a mutex is NOT good for

* Signaling events
* Waiting for conditions
* Limiting *N* concurrent accesses

That’s where the next tools come in.

---

# 2. Semaphores

### What is a semaphore?

A **semaphore** is a **counter + waiting mechanism**.

It allows:

* **N threads** to enter simultaneously
* Blocks when count reaches zero

> Think of it as **parking slots**.
> If no slots are free, cars wait.

---

## Simple Example: Allow only 2 threads at a time

(C++20 `std::counting_semaphore`)

```cpp
#include <iostream>
#include <thread>
#include <semaphore>

std::counting_semaphore<2> sem(2);

void worker(int id) {
    sem.acquire();  // wait if no slot

    std::cout << "Thread " << id << " entered\n";
    std::this_thread::sleep_for(std::chrono::seconds(1));
    std::cout << "Thread " << id << " leaving\n";

    sem.release();  // free slot
}

int main() {
    std::thread t1(worker, 1);
    std::thread t2(worker, 2);
    std::thread t3(worker, 3);

    t1.join();
    t2.join();
    t3.join();
}
```

### What’s happening?

* Semaphore starts with count = 2
* Only 2 threads run concurrently
* Third thread waits until someone releases

---

## When to use a semaphore

Use a semaphore when:

* You want to **limit concurrency**
* More than one thread is allowed, but not unlimited

### Typical use cases

* Thread pools
* Rate limiting
* Limiting number of active calls/media sessions
* Resource pools (buffers, channels, ports)

---

## Semaphore vs Mutex (important!)

| Aspect    | Mutex                     | Semaphore              |
| --------- | ------------------------- | ---------------------- |
| Count     | 1                         | N                      |
| Purpose   | Mutual exclusion          | Resource limiting      |
| Ownership | Same thread locks/unlocks | Any thread can release |

> A mutex is a **special case of semaphore with count = 1**, but with ownership rules.
